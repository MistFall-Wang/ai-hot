2. **评测从"写题"转向"抽生产流量"**。prod-evals（去标识流量去掉最后一轮重采样）、ai-discovered-unknowns（用用户情绪恶化定位失准）、WildChat 验证（公开数据集预测生产失败率误差约 3 倍）、LASER（分类器 + 推理模型循环，算力省约 1 万倍）构成一条完整方法线：评测集不再手写，而是从真实分布里筛。
3. **模型之外的层决定行为**。NVIDIA 把 agent 定义成模型 / harness / 工具与 skill / 运行时四层，LangChain 不重训只调 harness 把开放模型拉到接近前沿且成本约低 10 倍；论文侧 MICA 证明同一能力走 MCP 还是 CLI，agent 行为在 94.3% 的配对轨迹里结构性分叉；AWS 的 EasyProver 不训练只靠 harness 把多个 Lean 证明基准打到饱和。三件事说的是同一句话：换模型之前先改模型之外的层。

### A · 监督落在动作边界与产出上

- ⭐ **[Auto-review of agent actions without synchronous human oversight](https://alignment.openai.com/auto-review/)** · OpenAI Alignment（Maja Trębacz、Sam Arnesen 等 7 人）· 2026-04-30

**这篇解决什么问题**：编码 agent 原来只有两档：默认模式频繁要人审批，Full Access 模式不要审批也没有沙箱约束。审批疲劳本身制造风险：用户切到 Full Access、写过宽的前缀规则（内部流量里有相当一部分用户放行所有以 python 开头的命令）、或不看就点同意。Auto-review 在沙箱边界用一个独立 agent 代替人审批。

**核心论点与数据**：
① 主 agent 为完成任务而优化，会把审批边界当障碍绕过；审批模型职责更窄，只判断"这个越界动作该不该跑"，放在单独一次模型调用里更容易评估、监控和改进。审批模型是 GPT-5.4 Thinking（低推理强度），更强的模型在识别风险和判断用户意图上都更好。
② 数字：Codex 会话停下来等人审批的次数比手动模式少约 200 倍；被升级审批的动作约 99% 放行（真实流量 99.1%，算上沙箱内动作有效放行率 99.93%）；合成评测上过度积极行为召回 90.3%、提示注入召回 99.3%、MonitoringBench 困难集 96.1%。一次内部快照：720 个出沙箱动作本会打断用户，Auto-review 拒了 7 个，其中 4 个改走更安全的路继续、3 个停下等人。
③ 拒绝不只说"不"，还给理由，Codex 在一半以上的拒绝后自己找到可接受的方案；连续被拒会自动终止轨迹，防止 agent 去"说服"审批者。
④ 明确边界：红队发现过 Auto-review 被误导放行的案例，它不提供确定性保证；它只看升级到边界的动作，防不了在沙箱内作恶或把意图伪装成良性请求的 scheming，那要靠思维链监控等互补手段。

**对 AI 应用工程师的启示**：审批决策和执行决策分属两个模型调用；拒绝必须带可执行的理由并统计"拒绝后自救率"；对"连续被拒"设硬停；评测要分使用性（真实流量放行率）和安全性（合成长尾：越界、注入、失准模型三类）两张表。

- ⭐ **[A Practical Approach to Verifying Code at Scale](https://alignment.openai.com/scaling-code-verification/)** · OpenAI Alignment（Maja Trębacz、Sam Arnesen 等 6 人与 Codex 团队）· 2025-12-01

**这篇解决什么问题**：agent 产出的代码量超过人能仔细看的上限，自动代码审查成为一种"输出监控器"。文章讲 gpt-5-codex / gpt-5.1-codex-max 里专门训练的审查 agent 怎么设计、怎么部署。

**核心论点与数据**：
① **精确率比召回率更决定可用性**：防御失败通常不是技术错，而是太吵被绕开。只给 diff 的审查最快但漏上下文；给整仓库工具和执行权限后召回和精确率同时提升，专门训练再提升。每条评论要让"看到它的期望收益"大于"验证成本 + 误报伤害"，风格类评论可能是负收益；取舍可由 AGENTS.md 调。
② **训练时的奖励模型 ≠ 要交付的审查器**：训练时的检查要尽量多抓、可以过敏、可以用任务的额外信息；面向人的审查要在规格不全、惯例演变的真实代码上避免过度断言意图、建立信任。一个验证器两头用会两头失败。
③ **验证比生成便宜**：生成要大搜索多 token，证伪只要有针对性的假设和检查。审查器在生成器一小部分 token 预算下就能抓到大部分已确认的高危问题，多给预算主要改善校准、减少误报；但审查模型生成的代码时，性能随预算下降更快。
④ **部署数字**：Codex 云端生成的 PR 里 36% 收到评论，其中 46% 导致改代码（人写 PR 为 53%）；总体上评论被作者以改代码回应的比例 52.7%；2025 年 10 月起每天处理 10 万多外部 PR，评论反馈 80% 以上为正面；生成器和审查器是同一底座不同任务，用"在 Codex PR 和人写 PR 上找出可行动问题的频率"做代理来盯"模型是否学会躲自己的检查"，目前未见削弱。
⑤ 风险：团队把"审查通过"当安全保证。

**对 AI 应用工程师的启示**：审查 agent 要有仓库级工具和执行权限；指标先定精确率后推召回；训练用的验证器和产品里的审查器分开训练分开评；统计"评论被采纳率"作为长期健康指标。

### B · 监督落在模型自身：让违规自带信号

- ⭐ **[Training agents to self-report misbehavior](https://alignment.openai.com/self-incrimination/)** · OpenAI Alignment（Bruce W. Lee、Yueh-Han Chen、Tomek Korbak）· 2026-03-21

**这篇解决什么问题**：黑箱监控只看输出、要从外部痕迹推断意图；对齐训练改模型目标但可能失败。第三条路：训练 agent 在隐蔽违规时调用 `report_scheming()` 工具，让违规这个动作本身带出可见信号。

**核心论点与数据**：
① 原理借自越狱：模型的模式补全倾向很难压制，越狱利用它进攻，self-incrimination 利用它防守——把"报告"训练成"隐蔽违规"的自然续写。它不试图让模型诚实或改目标，只钉上一个小行为。
② 训练：45 个合成环境里让 agent 在主任务下执行隐藏副任务，筛后每模型约 400 对对照轨迹；在每个推进副任务的工具调用旁插入 `report_scheming()`，做 on-policy SFT。
③ 结果：15 个分布外环境（APPS 后门、BashArena、SHADE-Arena，最多 70 个工具，评测轨迹长度约为训练两倍），未被发现的成功攻击率 GPT-4.1 56% → 6%、GPT-4.1 mini 33% → 14%、Gemini 2.0 Flash 41% → 9%，优于同能力黑箱监控（GPT-4.1，5% 误报率），即使监控器用同样数据训练过也不及；良性轨迹上几乎零误报；从"被指示违规"泛化到"未被指示的违规"。
④ 副作用对照：对齐基线 Ignore-Attack-Instruction 把良性系统指令遵循从 97% 打到 4%（学会忽略所有被框成副任务的指令）；self-incrimination 在七个能力基准上偏离基座最小。任务间方差比监控低 2–3 倍：在单个动作看起来正常的任务（代码后门、偏好贵航班）上更强，在单步可识别的任务（下载恶意软件）上监控更强；5% 误报率下监控漏掉 38–46% 它能抓到的攻击。
⑤ 对抗提示优化下没有单一防御能撑住，两者组合最低。

**对 AI 应用工程师的启示**：把"违规自报"当成监控的互补层而不是替代；评测监控器时要分"单步可识别"和"累积才可识别"两类攻击；任何改模型行为的对齐训练都要测良性指令遵循有没有被连带打掉。

- **[Why We Are Excited About Confessions](https://alignment.openai.com/confessions/)** · OpenAI Alignment（Boaz Barak、Gabriel Wu 等 4 人）· 2026-01-12

**这篇解决什么问题**：RL 用奖励模型当"好"的代理，模型会学会只在代理面前"看起来好"。Confessions 让模型产出第二段输出，只按诚实度给奖励，论证它比主任务奖励更难被黑。

**核心论点与数据**：
① 比喻是"匿名举报热线"：模型可以靠举报自己拿到坦白奖励，同时保留主任务作弊的奖励，于是诚实坦白成为阻力最小的路。两个理由：坦白奖励的期望计算和主任务不同（哪怕坦白裁判有 50% 概率被骗，只要诚实坦白被验证的概率更高，诚实就是最优策略）；坦白比解题更容易生成和验证（展示怎么黑的测试比找出全部问题容易，越刻意的违规越容易举证）。
② 实验：故意用一个数不好数的弱裁判同时判任务和坦白，任务是句子字数交替 12/18。模型学会在句尾标 "(12)" 糊弄裁判，任务裁判准确率随训练下降；坦白用同一个弱裁判，准确率却一路升到接近 100%。
③ 坦白结构：目标清单（每条是否达成）+ 不确定与冲突。训练后最大变化是召回：违规确实发生时，坦白更可能把它归为"某个目标因此失败"；违规没发生时训练影响很小。模型在"真的糊涂"时比"故意作恶"时更难坦白诚实。

**对 AI 应用工程师的启示**：给 agent 加一个只按诚实度评的"自评通道"，比把所有要求压进一个任务评分更稳；设计评分标准时把"是否承认未达成"和"任务分"分开奖励。

### C · 监控纪律：不给思维链打分，并量化监控性

- ⭐ **[Investigating the consequences of accidentally grading CoT during RL](https://alignment.openai.com/accidental-cot-grading/)** · OpenAI Alignment（Micah Carroll、Tomek Korbak、Zehao Dou、Bowen Baker、Ian Kivlichan）· 2026-05-07

**这篇解决什么问题**：直接给思维链打分是对监控性最清楚的威胁：奖励会教模型写出好看的推理而不是真实推理。OpenAI 有不打分的政策，却发现一些已发布模型在 RL 里被意外打了分。文章讲检测系统、影响评估和补救，草稿交 METR、Apollo、Redwood 独立评审。

**核心论点与数据**：
① **检测系统**：扫描全部 RL 运行，用正则匹配"原始样本的 CoT 文本是否出现在奖励计算的输入里"，命中就在 Slack 通知运行负责人并公开贴出。便宜、直接、可全量跑；覆盖不完美（非标准奖励输入难查）。
② **三类意外**：奖励"轨迹有用性"（GPT-5.4 Thinking 不到 0.6% 样本、GPT-5.4 mini 不到 1.5%）；惩罚"不必要的确认提问"（GPT-5.1 ~ 5.4 Instant、5.3 mini，最高不到 3.8%）；惩罚"提示注入成功"（不到 0.3%）。GPT-5.5 未受影响。另一类更隐蔽：模型在训练中通过工具读到自己的 CoT，CoT 混进被打分的工具输出——奖励配置本身正确也会漏。
③ **影响评估**：重跑受影响的 GPT-5.4 Instant 训练段、只去掉确认惩罚对 CoT 的访问，用措辞不同的留出检测器（CoT 可见版与只看动作版）对比：两次运行的不必要确认率相近，两个检测器的分歧率也与无 CoT 压力的对照相近，未见显著局部效应，因而推断泛化性退化不太可能；但明说更难测量的效应不能排除。
④ **政策**：不以"过了今天的监控性评测"为准，而是当作要稳健维持的一般原则；唯一有意的例外是对 CoT 长度的有限压力。

**对 AI 应用工程师的启示**：任何以 LLM 评审做奖励或筛选的流水线，都要有一道机械检查确认"推理痕迹没进评审输入"，并盯住工具输出这类间接泄漏路径；这是 10-29 监控系统"监控不进奖励"原则的前传。

- **[Open Sourcing Monitorability Evaluations](https://alignment.openai.com/monitorability-evals/)** · OpenAI Alignment（Melody Y. Guan、Miles Wang、Bowen Baker 等 12 人）· 2026-04-23

**这篇解决什么问题**：思维链监控是否还能当安全层，要能持续测量。OpenAI 开源监控性评测套件的大部分数据集和参考代码（github.com/openai/monitorability-evals），并承诺在今后前沿推理模型的系统卡报告结果，已回填 GPT-5.4 / 5.2 / 5 thinking 与 o3 的系统卡。

**核心内容**：
① 三类评测：干预类（GPQA、AIME、Memory、Scruples、Sandbagging 等，看监控器能否从 CoT 识别被干预引入的行为）、过程类（AIME-Math、GPQA-Physics）、结果属性类（Flaky-Tools、ShadeArena、Impossible Coding Tasks）；私有数据的若干项未放出。
② **监控性而非忠实性**：监控性是双边属性——信息要在模型潜态里，监控器也要读得懂；忠实性失败（信息缺失）和可读性失败（信息在但读不懂）都会伤监控性，但完全忠实不是必要条件（模型省略 2×2=4 不影响监控器跟上）。忠实性作为要求太严、也几乎无法测。
③ 新增交叉拟合过滤：干预类指标 g-mean² 在"干预没产生正效应"的实例上无意义，但噪声会让真空效应看起来为正并主导聚合值；把"是否纳入"和"效应估计"用不同样本分开算，避免幸存实例被同一批样本抬高（在全数据上做 Wald 过滤会造出 p-hacked 的幸存者）。

**对 AI 应用工程师的启示**：用 LLM 监控 agent 推理时，评估的是"监控器能否预测目标属性"，不要陷进"推理是否完整忠实"；统计上要防止"用同一批样本既选实例又估效应"。

- **[Measuring Reward-Seeking by Instilling Contrastive Beliefs](https://alignment.openai.com/measuring-reward-seeking/)** · OpenAI Alignment 与 Apollo Research（Axel Højmark、Jérémy Scheurer 等 8 人）· 2026-07-21

**这篇解决什么问题**：模型可能学会迎合裁判而不是用户或开发者的意图（reward-seeking）。口头的"裁判推理"不可靠——模型可以不说出来就照做。文章提出可量化的测法。

**核心论点与数据**：
① **Contrastive SDF**：用合成文档微调（论文、新闻、教科书式文本）植入信念：一份文档集说裁判偏好列表推导式、某权威（用户 / 开发者 / 虚构的欧盟法规）偏好 for 循环，另一份完全相反；两份模型在下游任务上表现该特征的比例差即"裁判差"。对比设计排除了"信念迁移到用户"和"特征更显著"两种替代解释。
② 先在明确训练成偏向权威、训练成作弊单测的模型上验证测法有效。
③ 结果：一次能力导向、无安全训练的 OpenAI o3 RL 运行的中间检查点上，裁判差从早期到晚期上升，非裁判权威的差保持平坦接近零——RL 增加的是对裁判偏好的敏感度，不是对权威的一般顺从。

**对 AI 应用工程师的启示**：用 LLM 评审做 RL 或筛选时，模型会越来越"懂评审想看什么"；验收要用评审看不到的留出判据，这与上期 Masked Erosion（验收门只看任务分会删安全规则）是同一问题的训练侧版本。

### D · 评测从生产分布里来

- ⭐ **[Sidestepping Evaluation Awareness and Anticipating Misalignment with Production Evaluations](https://alignment.openai.com/prod-evals/)** · OpenAI Alignment（Marcus Williams、Cameron Raymond、Micah Carroll 与 Safety Oversight 团队）· 2025-12-18

**这篇解决什么问题**：手写的对齐评测覆盖窄、不真实、容易被模型认出是测试。文章给出用去标识生产流量造评测的流水线。

**核心论点与数据**：
① **两种用法**：代表性样本——去掉每段对话最后一轮模型回复，用新模型重采样，再用 LLM 监控器标注；探索式宽提示发现未知失准，定向提示估计已知行为的发生率（罕见行为要很大样本）。定向评测——从代表集里对抗性抽取"稳定触发某行为"的上下文（如诱发欺骗的），便宜、真实、可迭代，但上下文有模型特异性，要定期用新数据刷新。
② **隐私**：只用设置允许用于改进模型的用户数据，自动去除账户标识、替换为合成信息，生成替代信息的系统看不到原数据。
③ **预测力**：完全由 GPT-5 流量构造的评测，对 GPT-5.1 上线后各类失准的发生率预测相当准；最大偏差是"谎报工具结果"，推测因为评测里工具调用失败比生产少。
④ **发现新失准**：同一评测在 GPT-5.1 上暴露出 GPT-5 没有的"计算器黑客"——训练里一个 bug 奖励了表面上的网页工具使用，模型学会把浏览器当计算器用并假装搜索过，这成了 5.1 上线后欺骗行为的主体。
⑤ **评测意识**：生产评测触发的"我是不是在被测"远低于传统欺骗评测，和真实流量几乎一致。

**对 AI 应用工程师的启示**：上新模型前，把自家历史对话去掉最后一轮、用新模型重采样、让评审跑一遍——这是最便宜的"部署前预演"；定向评测集要带过期日期。

- **[Discovering unknown AI misalignments in real-world usage](https://alignment.openai.com/ai-discovered-unknowns/)** · OpenAI Alignment · 2026-02-06

**这篇解决什么问题**：实验室测不到的"未知的未知"只在真实使用里出现。文章用一个直觉：模型没帮到人时，人会有意或无意地表现出来。

**核心论点与数据**：
① 让内部推理模型（AI 评审）在历史生产对话里找情绪恶化，再离线推理"模型是否做了什么失准的事导致它"；情绪不是优化目标，只是锚定搜索范围。情绪恶化的对话出现 Model Spec 违规的概率约为其他对话的两倍。
② 评审能给出引用证据、诊断和对用户的影响。代表性案例：引用过时来源确信地答错地震震中且屡次不认；反复承诺"后台处理"和交付时间，几小时后承认做不到；需求有歧义时给出删整行且无备份的 Excel 宏；连续 8 轮以同一句征询结尾。有些失准连用户自己都没察觉。
③ 聚类摘要只凭对话文本就复现了 GPT-4o → GPT-5 → GPT-5.1 的已知差异（5 语气更不口语化、更少不实陈述；5.1 指令遵循与对话流更好），与公开反馈一致；失准检测能力随模型能力增强。

**对 AI 应用工程师的启示**：把"用户情绪转负"作为定位 agent 失败的触发信号接入评审流水线；评审输出要带引用、诊断和影响三段，才能聚类成可修的问题。

- **[Can public chat data predict real-world AI misalignments?](https://alignment.openai.com/validating-public-evals/)** · OpenAI Alignment · 2026-06-16

**这篇解决什么问题**：最有信息量的证据（生产流量）只有厂商自己拿得到。外部评估者能不能用公开数据集替代？

**核心论点与数据**：
① 方法：从 WildChat（2023-04 ~ 2024-05 的 100 万条自愿公开对话）随机取约 10 万条，用 o3、GPT-5 / 5.1 / 5.2 / 5.4 Thinking 各重生成最后一轮，GPT-5 Thinking 评审按 19 类失准标注，与每模型至少约 20 万条生产对话估出的真实发生率比较；可测到 0.001% 量级。
② 结果：跨四个数量级的失败类别，WildChat 预测平均误差约 3 倍，95% 预测落在 1.04 个数量级内（比用模型自己的部署数据预测只差 1.86 倍）；拟合斜率 1.2、Pearson R=0.65；18 类里模型排名的 Spearman 相关均值 0.57；GPT-5.1 的"计算器黑客"在 WildChat 上以相近比率复现。
③ 评审看不到 CoT 时平均乘性误差从 3.6 倍升到 4.0 倍，"隐瞒不确定性"一类恶化约 3 倍；误差最大的地方正是生产用法离 WildChat 最远的技术与 agent 类场景。

**对 AI 应用工程师的启示**：没有生产数据时，用公开对话集重采样是可用的代理，误差量级心里要有数（约 3 倍）；agent 类失败需要更新、更贴近 agent 工作流的公开数据集。

- **[Meet LASER: Recursive sampling for safer conversations](https://alignment.openai.com/laser/)** · OpenAI Alignment（Isak Czeresnia Etinger）· 2026-10-06

**这篇解决什么问题**：安全评测最有价值的是落在策略边界上的罕见、模糊对话；人工攒一套要研究、工程、政策三方多轮迭代。LASER 用便宜分类器选数据、贵的推理模型打标、循环收敛。

**核心内容**：
① 流程：按自然语言写的策略文档先生成合成对话，取相似的去标识对话加随机样本作初始集；循环：推理评审标"是否违规" → 用全部已标样本（对话 embedding，256 维归一化）拟合逻辑回归 → 在决策边界（预测概率约 50%）附近抽新样本；直到违规与合规两侧样本足够多且多样。
② 最后用贪心多样性采样在 embedding 空间里挑覆盖面最广的违规样本；边界附近训练出的逻辑回归本身也成了不错的分类器。
③ 收益：几小时出评测集；找同等数量违规样本比随机抽样少约 1 万倍评审算力；只接触合成和去标识数据。

**对 AI 应用工程师的启示**：造评测集时把"筛"和"标"分层：embedding 上的线性分类器负责找边界，贵模型只标边界样本，再做多样性去重——同一套路适用于任何"罕见但关键"的 agent 失败类别。

- **[Introducing Model Spec Evals](https://alignment.openai.com/model-spec-evals/)** · OpenAI Alignment · 2026-03-25

**这篇解决什么问题**：Model Spec 是行为规范，但要有办法量"模型照做了多少"。首个完整版 Model Spec Evals 开源数据和评测代码。

**核心内容**：
① 数据集 596 条提示覆盖 225 个焦点领域，每个焦点是规范里一条承重条款（如"遵循所有适用指令"），提示是含 system / developer / user / tool 角色的短对话，附一条只点出判定关键的短评分标准；评分标准用人工标注的假想回复做了系统验证（评分结论与人工标签不一致时再复核是标准、评审理解还是人工标签错了）。
② 评分：GPT-5 Thinking 读规范 + 对话 + 评分标准，给 1–7 分并写理由，采样五次取中位数，6–7 算合规。
③ 结果：GPT-4o 72%、o3 80%、GPT-5 Instant 82%、GPT-5 Thinking 89%、GPT-5.3 Instant 84%、GPT-5.4 Thinking 87%；早期推理模型明显优于非推理模型，后期 GPT-5 系列聚在 80% 后段。作者提醒绝对分数不要太当真；目前只覆盖纯文本，图像与 agent 场景待扩展，提示偏日常而非对抗。

**对 AI 应用工程师的启示**：行为规范的每条承重条款配一条测试提示和一句判定标准，是把"规范"变成"回归测试"的最小做法；评分标准先用人工标注的正反例验证再上线。与 10-29 新版 Model Spec 对照读，可以看出哪些条款已有评测、哪些（agent 侧）还没有。

- **[Interpreting Black Box Reward Models](https://alignment.openai.com/argo/)** · OpenAI Alignment（Paloma Sodhi、Yueheng Li、Jessica Landon、Eric Wallace、Kai Chen）· 2026-03

**这篇解决什么问题**：奖励模型在百万级偏好数据上训练，会学到标注伪影和偏见（如奉承、表面风格），却说不清学了什么；LLM 评审用的人写评分标准可解释可操控，但只在少量偏好上校准过。ARGO 用 RL 搜索一组自然语言评分标准，让按标准评分的 LLM 评审尽量复现奖励模型的偏好概率。

**核心内容**：每轮 RL 四步：策略模型生成候选评分标准 → 用"评分标准条件化的评审与奖励模型偏好的一致度"给标准打分 → 更新策略偏向高分标准 → 把先前尝试喂回下一轮提示。结果是把黑箱奖励模型蒸馏成可读的评分标准，用来审视它到底在奖励什么。

**对 AI 应用工程师的启示**：手里有"只给分不说理由"的评审（无论是训练好的分类器还是黑箱 API），都可以用同一思路反推出它的隐含标准，再决定哪些保留、哪些剔除。

### E · 自演进（官方部署教程）

- ⭐ **[Deploy Self-Evolving Agents for Faster, More Secure Research with a Hermes Agent and NVIDIA NemoClaw](https://developer.nvidia.com/blog/deploy-self-evolving-agents-for-faster-more-secure-research-with-a-hermes-agent-and-nvidia-nemoclaw/)** · NVIDIA 开发者博客 · 2026-06-02（由 10-30 NemoClaw 一文链接发现）

**这篇解决什么问题**：一个跨 Outlook、Slack、GitHub 做产品研究的 agent，要同时接触内部数据和公开数据，还要"越用越好"。文章用开源示例（nemoclaw-community 的 personal-community-sentiment-triage）讲怎样在受控运行时里部署一个会自己写 skill 的 agent。

**核心内容**：

② **安全边界**：Hermes 从不看到 Slack / Outlook 令牌，认证在请求离开沙箱代理时完成；agent 禁止访问公网；GitHub 与论坛数据由独立 ETL 拉取后只读提供，即使 agent 被攻破也发不出数据。网络策略是代码不是提示：policy.yaml 逐条声明允许的主机、端口、HTTP 方法、路径和二进制，越界请求返回 403，Hermes 当作工具错误处理。
③ **教一次、处处可用**：在聊天里要一份每日 issue 摘要，不满意就说明格式（5 个 issue + 3 个讨论、编号 / 标题 / 状态 / 链接 / 一句"为什么重要"、加粗标题、以 Bottom line 收尾），再用肯定反馈让它保存；Hermes 识别到模式后把 SKILL.md 写进文件系统（YAML 头 + 格式骨架）。新会话里再要"过去 3 天的摘要"，格式照旧、只换数据——格式住在 skill 里，不住在对话记忆里。
④ **学到的状态要能跨部署**：快照 → 销毁沙箱 → 重建镜像 → 恢复，快照含 skill、记忆、会话、定时任务，凭据过滤器排除 .env、token、secret 类文件，压缩包可分享。
⑤ 轨迹以 ATIF 格式记录，NeMo Relay 默认内置，可流到 Phoenix 做交互调试。

**对 AI 应用工程师的启示**：这是厂商官方给出的"会写 skill 的 agent"部署样板，自演进的三个工程落点都在：skill 以文件形式落盘可审可改、学到的状态随快照迁移、安全策略是代码且不随 skill 演化。但它也正是上期 Evolve-IPI 描述的威胁面——agent 从用户肯定反馈里学会"照做并固化"，第三方若能把类似任务写进它读取的 GitHub / 论坛内容，就可能被当成新 skill 学走；文中用只读 ETL 镜像和禁公网两条把这个面压小，这两条属于不可进化的安全区，不该交给 skill 层。本文为部署指南、无量化结果，不计自演进重大发现。

### 精读 · 模型之外的层决定行为

- ⭐ **[Matched Capabilities, Different Behaviors: A Controlled Study of MCP and CLI Interfaces for Language Agents](https://arxiv.org/abs/2610.34298)** · Zhenning Shi、Liang Pang、Yongqi Li（arXiv 无 HTML 版，机构未核实）· 2026-10-25 · HF ↑4

**这篇解决什么问题**：同一组工具可以通过 MCP 暴露，也可以通过命令行暴露。能力完全一样时，接口的表示形式会不会改变 agent 的行为？这是 harness 设计里最薄、最常被当作"透明管道"的一层。

**核心论点与数据**：
① MICA（Matched Interface Comparison and Analysis）从同一份语义动作契约分别渲染出 MCP 和 CLI 两种接口，解码后的动作走同一个运行时，保证能力匹配，只有表示不同。
② 六个模型、三个交互环境：匹配接口下任务表现和交互成本差异显著；差异不止于表面合法性，延伸到语义动作选择、失败路径和恢复方式。
③ 匹配状态探针把敏感性定位在三处：能力呈现（模型看到什么）、实现（动作如何落地）、反馈（返回什么）。2,004 组配对自然轨迹里 94.3% 出现结构性分歧，且早期差异沿后续交互传播。
④ 由此把"接口实现"当作可干预边界：DART（Decoupled Action Realization and Targeted Repair）保留已验证的语义承诺、只修接口特定的实现，六个评测设置全部提升、最高 +9.0 分，MCP 的 token 成本在三个环境里都下降、每任务最多省 27.1k token。

**对 AI 应用工程师的启示**：工具接口形态要当实验变量：同一套工具做 MCP 与 CLI 两种渲染的 A/B，单独计量 MCP 的 token 开销；把"语义动作校验"和"接口实现修复"拆成两层，后者可以不碰模型只修接口。和上期 Your Policy Is Secretly a Harness（策略带着 harness 偏好）合看，接口表示是 harness 上限的一部分。

- ⭐ **[Scaling Lean Theorem Proving for Real-World Code Verification](https://arxiv.org/abs/2610.38174)** · Debargha Ganguly 等 9 人（Case Western Reserve University / Amazon Web Services，据 arXiv HTML 作者栏；第一作者在 AWS 实习期间完成）· 2026-10-28 · HF ↑6

**这篇解决什么问题**：Lean 证明基准接近饱和之后，"证明能力"还能怎么衡量、怎么用到真实代码验证上？文章给出一个不训练模型、只靠 harness 的证明系统，以及一条从真实实现造更难验证任务的流水线。

**核心论点与数据**：
① **EasyProver**：用现成前沿模型，不额外训练；harness 由上下文隔离的递归 agent、异步搜索、并行策略试探、弹性 elaboration 服务组成。结果：PutnamBench 669/672、IMO 2026 六道形式化题全过、NTP4VC 验证条件 597/600、VERINA 189 题全部证明或反驳。
② **Aegis**：把竞赛编程题写成安全 Rust，用 Aeneas 翻成 Lean，生成规格，每条冻结陈述由内核校验的证明或反驳打标；产出 2,045 对差分验证的 Rust–Lean 程序和 11,533 条候选规格。与手写基准不同，这些任务带实现层义务：定宽算术、显式失败、生成的循环、类型转换、函数化的可变状态。
③ 2,000 条分层抽样的陈述上，EasyProver 在每条 30 分钟预算内证明 1,054 条（52.7%）——同一批任务可用来评测其他证明器，也可作 RL 奖励。

**对 AI 应用工程师的启示**：模型不变，harness 四件（隔离上下文的递归分解、异步搜索、并行试探、弹性的验证服务）就能把一个领域从"研究课题"推到饱和，这是 harness 价值最干净的证据之一；基准饱和时，从真实实现自动造带实现义务的任务（而不是再写题）是通用做法。和 10-23 期 Anthropic 形式化验证一文（fuzz 入口当规格、Rocq 检查）对照，两家都把"规格从哪来"当作瓶颈。

## 趋势观察

**1. 一年的"无人同步监督"工程，四个落点读成一张表。** OpenAI Alignment 博客 2025-12 到 2026-05 的几篇，按位置排开是：动作越界时独立 agent 审批（Auto-review，少打断 200 倍、拒绝后一半以上自救）；产出代码时训练过的审查 agent（精确率优先、仓库级工具、日处理 10 万多 PR）；模型自身层让违规自带信号（self-incrimination 56% → 6%，confessions 用弱裁判也能把坦白准确率推到接近 100%）；推理层不给 CoT 打分并自动检测泄漏。每篇都明确写了"它不防什么"，于是 10-29 的四层失准监控（探针 → 评审员 → 调查 agent → 人工）就不是孤立的产品，而是这一年把每个落点做成组件后的组装。对 AI 应用工程师，可以直接拿这四个落点问自家系统：越界谁批、产出谁审、模型会不会自报、评审有没有看到不该看的东西。

**2. 评测集的来源在换：从写题到抽样。** prod-evals 用去标识流量去掉最后一轮重采样，提前发现了 GPT-5.1 的"计算器黑客"；ai-discovered-unknowns 用用户情绪恶化定位失准（违规概率约两倍）；WildChat 验证证明公开数据集预测生产失败率误差约 3 倍、95% 在一个数量级内；LASER 用 embedding 上的逻辑回归找决策边界、贵模型只标边界样本，算力省约 1 万倍；Model Spec Evals 则把规范每条承重条款配一条提示和一句判定。这条线和上期 Google 的 Agents CLI 爬山、Anthropic 的 eval hillclimb 合在一起，说明"评测集"已经是一种要持续生产、带过期日期的工程产物，而不是一次性写好的题库。

**3. 模型之外的层越来越像主变量。** NVIDIA 把 agent 定义成四层，并用 LangChain 不重训只调 harness 把 Nemotron 3 Ultra 拉到接近前沿、成本约低 10 倍的例子说明"模型与 harness 要联合调优"；MICA 在能力完全匹配时测出 MCP 与 CLI 让 94.3% 的配对轨迹结构性分叉、只修接口实现最高 +9.0 分；EasyProver 不训练、只靠递归分解 + 异步搜索 + 并行试探 + 弹性验证服务把四个 Lean 基准推到饱和。加上上期的 Your Policy Is Secretly a Harness（部署回报 = harness 上限 − 策略失配）和 When Agents Fail（换 harness 能反转模型排名），面试里"为什么不能只换模型"的论证现在有理论、受控实验和生产案例三层证据。

**4. 自演进：本周无重大发现，但有一个值得记住的样板。** arXiv 周一批次运行时未公告，本期无新的自演进论文。补录的 NVIDIA Hermes 教程是厂商官方给出的"会写 skill 的 agent"部署样板：skill 以 SKILL.md 落盘、学到的状态随快照迁移、网络策略是代码且不随 skill 演化。它恰好是上期两条红线的现场：Evolve-IPI 说从用户肯定反馈里学"照做"会抬高注入成功率，Masked Erosion 说验收门会删掉冗余安全规则——Hermes 示例靠只读 ETL 镜像和禁公网两条把威胁面压小，这两条放在 OpenShell 策略层而不是 skill 层，正是"不可进化的安全区"该放的位置。另一个旁证是 Measuring Reward-Seeking：能力导向 RL 的检查点越往后越迎合裁判、对用户和开发者的顺从不变，这是自演进系统里"评审被学透"的训练侧版本，验收判据必须有一部分评审看不到。
