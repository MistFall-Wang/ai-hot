2. **让前沿模型当"研究员"同时改模型和 harness，第一轮改得动，第二轮接不上**：CoEvoBench 给五个前沿模型 24 小时预算，在五个 agent 领域里协同演进模型和 harness，在单独的测试任务上打分。最强的一个补上了与参考系统差距的五分之四以上；但协同演进在交互类任务上能成，在长时程编码上很少成功。论文的结论是：当前模型能做出很强的第一次改进，却还不能把"改进后的系统"给出的反馈变成下一次改进。[CoEvoBench](https://arxiv.org/abs/2611.27116)，见精读 A1。
3. **"答对了"不等于"学到了"**：AstronautBench 在一次运行里同时量三件事：知道什么、自己的证据是否支持、在世界里走了多远。GPT‑6.1 Sol agent 的答对率从 14.6% 升到 26.8%，但第 8 轮时只有 59%–68% 的正确答案有它自己引用的证据支持，第 3 轮之后没有再发现任何新事实。只看一条曲线会把"猜对"当成"自改进"。[AstronautBench](https://arxiv.org/abs/2611.26910)，见精读 A2。

- 【必看】⭐ **[Perplexity and Intelligence](https://openai.com/index/perplexity-and-intelligence)** · 出处：OpenAI · openai.com/index（Research）· 2026-11-22 —— **解决什么问题**：下游基准换得太快（GPT‑2 时代的基准到 GPT‑4 基本饱和），各家又用不同的评测集，行业缺一个能跨实验室、跨年份比较"底层智能"的指标，也就没法约定"发展到哪一步之前要先把监控做好"。**核心内容**：这是一篇第一人称署名文章（抓取到的正文里没有作者姓名，这里不写）。作者把 AI 研发简化成三步：造算力、在大规模语料上预训练一个"压缩器"、再用提示、微调、RL 把潜在能力引出来。预训练的进展一直用留出集上的困惑度衡量，文章第一次公开了 OpenAI 内部的数字：对数困惑度 GPT‑3.5 约 0.99（能流畅对话），GPT‑4 约 0.91（能有效利用 CoT），现在低于 0.8（网络安全和数学上出现变革性能力）；模型升级到约 0.76 之后，在数学开放问题上"一个接一个"地出结果。作者据此外推：进入 0.68–0.70 区间会出现新的变革性能力，具体是什么不知道，今天可能都没有在测；同时现有的对齐审计会继续失效，模型的评测意识和训练意识会更强。关于 RSI，作者认为通常说的"全自动递归自改进"框架漏掉了一点：AI 只要参与进"预训练算法研究"这一环，就可能带来台阶式变化，最早 2027 年会出现一批基础性的预训练进展；而对齐和监控的进步不够快，撑不住这种加速。**提议**：前沿开发者共同建立评测和红队 safety case 的规范，并约定"共同上限"，即以困惑度等指标划一条线，达到某个具体里程碑（例如做出 CoT 监控的继任技术）之前不越过。文章也列了困惑度的四个缺点：各家数据不同难以比较；不对应具体任务；不反映预训练之外的进步（CoT 不降低困惑度但大幅提升能力）；下限未知，越接近下限，同样的困惑度下降对应的能力跃迁越大。**对应用工程师的启示**：① 面试里讲"模型能力从哪来"，可以用"预训练压缩 + 后期引出"这个两段式，并说明基准为什么会饱和；② 做能力规划时别只看当前基准分，下一代模型的新能力很可能落在现有评测集之外，评测集要留出"还没人测"的任务；③ 依赖 CoT 监控的安全方案要准备好替代手段。HN 反响：626 分 / 410 评论。
- 【必看】🧪 **[Combatting adversarial distillation](https://openai.com/index/combatting-adversarial-distillation)** · 出处：OpenAI · openai.com/index · 2026-11-20 —— **解决什么问题**：有人拿前沿模型的输出去训练另一个没有护栏的模型（对抗性蒸馏），等于把网络安全、生物这类两用能力搬到防护之外。**核心内容**：内部实验从同一个预训练学生模型出发，用 Astra 级教师做编码和防御性安全任务的轨迹做 SFT。对照组只给用户本来能看到的内容（最终回答、推理摘要、工具交互），实验组多给原始推理轨迹。SFT 之后，实验组的网络安全能力普遍更强；再做一轮轻量 RL，在最大推理预算下实验组仍然领先（低预算下摘要组更高）。结论是原始推理链值得重点保护，哪怕任务本身是合规的。防御分两层。请求层有三样：对抗训练让模型拒绝泄露推理，同时不影响正常的解释请求；输入分类器识别提取企图，输出分类器检查最终回答和工具调用参数里的泄露，流式和非流式都覆盖；API 把受保护推理绑定到产生它的对话历史，更早的消息被改写就丢弃其后的推理，旧模型族读不了新模型的推理。团伙层：按请求和账号信号识别协同提取，查实后封禁整个账号网络，调查发现的攻击再回流成训练和测试样本。自适应自动红队评测里，提取更早请求推理的平均成功率从 GPT‑6 Astra 的 54.0% 降到 GPT‑6.2 Astra 的 0.2%。**启示**：① 泄露检测要覆盖工具调用参数，模型可以不在最终回答里说、却把内容塞进参数；② 把红队、线上调查、外部披露发现的成功攻击都存成回归集，每次改防御先重放旧攻击；③ 自己的 agent 如果会重写历史消息或跨模型复用推理，要检查在新 API 语义下是否还成立。
- 【注意】🧪 **[Can AI help scientists identify promising drug candidates?](https://openai.com/index/introducing-medchembench)** · 出处：OpenAI · openai.com/index（Research）· 2026-11-20 —— **解决什么问题**：药物化学里"下一个该合成哪个分子"的判断没有现成的基准可测。**核心内容**：MedChemBench 从 117 篇论文和专利、761 个分子结构里整理出 99 道题，每题给出某个研究阶段已知的靶点、目标和实验结果，按四部分评分：分子结构重建、基于证据的解释、化合物排序与选择、性质数值预测；数值题按接近实测值的程度给部分分。xhigh 设置下 GPT‑6.2 Astra 84.5%，GPT‑5.6 Sol 58.2%；Astra 的结构重建得 95.4%，但化合物选择和性质预测只拿到约一半分数。文章自己写明三条局限：不能排除模型见过原文，每题只作答一次，不用工具。**启示**：领域基准按"表示正确、解释、决策、定量预测"分层打分，才能看出模型卡在哪一层；发布基准时把污染风险和单次作答这类局限写在正文里，读者才能判断分数能说明什么。
- 【注意】**[Time awareness and async input for personal agents](https://developers.openai.com/blog/time-awareness-and-async-input-for-personal-agents)** · 出处：OpenAI 开发者博客（Kevin Whinnery）· 2026-11-20 —— **解决什么问题**：个人 agent 要在截止时间前交付，中途又可能需要问用户一句话；传统做法是提问就阻塞，用户不回就卡死。**核心内容**：用"15 分钟后开会，提前 3 分钟给我简报"的例子演示 Agents API 的两个能力。一是时间感知（`experimental.time_awareness`），模型会周期性收到当前时间，临近截止时优先核对已有结论和写稿，不再开新的调研方向。二是异步函数工具（工具定义里 `async: true`），agent 发出提问后继续干活。应用侧要做四件事：把"15 分钟后"换算成绝对时间戳再交给模型；监听事件流里的 `agent.session.turn.item.done` 来发现异步提问（阻塞动作列表 `required_actions` 里看不到它）；用保存的 `turn_id` 和 `call_id` 回填答案；在交付前 2 分钟对没回答的问题回 `{"status":"no_answer"}`，让 agent 有时间收尾。截止时间到了就返回最近一版完成的简报，或说明没有核实过的结论。**启示**：agent 的"问用户"应当设计成不阻塞、有过期时间、过期有明确返回值的工具；相对时间一律由应用换算成绝对时间。

### 精读 A · 自演进：先问"第二轮还能不能改进"

- ⭐ **A1 · [CoEvoBench: Can LLMs Drive Recursive Co-Evolution of Agentic Systems?](https://arxiv.org/abs/2611.27116)** · Chuan Xiao 等 5 人（代码仓库在 GitHub 的 AlibabaResearch 组织下）· 2026-11-19 —— **问题**：agent 的表现同时取决于模型和 harness，改其中一个会改变另一个的价值。现有基准要么评后训练（harness 不在范围内），要么评 harness 优化（模型固定），"每一轮该改哪个"这个联合决策没人测。**做法**：让 LLM 当研究员，从同一个基座模型和初始 harness 出发，在 24 小时预算内训练和修改，交出一对"模型 + harness"，在单独的测试任务上打分，覆盖五个 agent 领域。**结果**：五个前沿模型里最强的补上了与一个指令微调参考系统差距的五分之四以上；协同演进在交互类任务上能成功，在长时程编码上很少成功。**结论**：当前模型能做出很强的第一次改进，但还不能把改进后系统的反馈变成下一次改进。**启示**：评自改进系统要看多轮曲线，第一轮的大幅提升说明不了"递归"；设计自演进循环时，把"第 N 轮相对第 N−1 轮的增益"单独记下来。
- ⭐ 🧪 **A2 · [AstronautBench: Measuring Agent Self-Improvement Across Episodes Through Knowledge, Evidence, and Progress](https://arxiv.org/abs/2611.26910)** · Congyuan Yu、Runping Tian · 2026-11-19 —— **问题**：权重固定的 agent 靠跨回合经验自改进，只看任务进度或问答正确率都会误判：答对不代表它见过证据，走得远不代表它学到了什么。**做法**：基于游戏 Outer Wilds，每回合 22 分钟后世界重置，只有 agent 的知识能带到下一回合。每回合结束量三样：到达的地点和揭示的事实；164 道关于世界的问题的正确率；每个答案是否被 agent 自己引用的画面帧和位置支持。两个不同模型族的 LLM 评审逐条检查。**结果**：GPT‑6.1 Sol 和 Gemini 4 Argon 各跑 8 回合，三条曲线并不同步。Sol 的答对率从 14.6% 升到 26.8%，但第 8 回合只有 59%–68% 的正确答案有证据支持；第 3 回合后没有揭示新事实，而到达地点和记忆还在增长；第 3 回合之后新答对的题，一半以上引用的是更早回合的证据。**启示**：评 agent 记忆和自改进时，除了"答对率"还要加一列"答案有没有自己的证据支持"，并且用两个不同家族的评审交叉检查。
- **A3 · [Self-Evolving Beyond Human-Crafted Experience for EDA Scripting](https://arxiv.org/abs/2611.26912)**（ZhuLong-SE）· Yang Liu 等 11 人 · 2026-11-19 —— 在任务级 harness（API 检索、文档问答、隔离沙箱执行、静态检查）之上加跨任务自演进：把历史执行轨迹提炼进三层记忆库，由四条规则把关：以真值为锚、证伪过滤、留出集回滚、检索防泄漏。158 题的 EDA-Eval-PyAether 上，关掉自演进的完整 harness 就有 92.4% pass@1；在更难的、实例不重叠的测试集上，从空配置自演进得到 80.0%，比人工编写经验的基线 77.5% 高 2.5 分。**启示**：经验入库的四道闸可以直接照搬，尤其是"留出集变差就回滚"和"检索时防止把答案带进来"。
- **A4 · [EvoTER: Evolving Embodied Agents via Tool-Use Experience and Reflection](https://arxiv.org/abs/2611.27797)** · Yingting Zhou 等 5 人 · 2026-11-20 —— 论文指出局部修复成功并不代表整任务变好。三个角色循环：Explorer 记录工具使用轨迹；Diagnoser 把成败轨迹提炼成工具选择、参数计算、后置条件检查和恢复四类 skill；Validator 只在候选修订于全新会话里提高了整任务成功率时才保留。仿真里整体成功率从演进前的 53.60% 升到 80.40%；真实环境中继续演进把长时程任务成功率从 20% 提到 80%–100%，skill 库还能吸收仿真阶段之后新增的工具功能。**启示**：skill 修订的接受标准用"全新会话里的整任务成功率"，不用"这一步修好了没有"。
- **A5 · [HookEvo: A Framework for Coordinated Plugin Evolution on Hook-Enabled Agent Runtimes](https://arxiv.org/abs/2611.27294)** · Shengze Huang 等 12 人 · 2026-11-20 —— 利用现有 agent 运行时的生命周期钩子来演进任务专用 harness（在 DeepSeek Harness 上实现）。每轮由独立的改进者根据执行轨迹诊断失败并提出候选，候选和当前 harness 在配对任务上比较，胜者进入下一轮。一个候选可以同时改多个插件处理器及其共享状态，比如让工具回执影响上下文组装、再约束后面的动作。执行模型固定为 Qwen3-4B：ALFWorld 95.41%、DBBench 70.56%、WebShop 48.17%、OSBench 41.67%。三种改进者、三种编辑范围（只改 skill 文本、改单个组件、协同改多个组件）的对比里，GPT‑6.1 Sol 从最宽的范围获益最大。**启示**：harness 自改不要局限在 skill 文本，钩子级的协同修改空间更大；接受与否靠配对任务对比。
- **A6 · [Search-RSI: Expanding Search Worlds Along Multimodal Agents' Capability Frontier](https://arxiv.org/abs/2611.27780)** · Chengchao Lv 等 4 人 · 2026-11-20 —— 多模态搜索 agent 的训练任务在线生长时，新问题可能格式正确、可验证，但证据根本不在检索后端里，agent 查对了却搜不到，被当成策略错误来惩罚。Search-RSI 让当前策略自己诊断"半掌握"的区域（按跳数、关系稀有度、干扰密度划分），在那里连同证据一起生成新任务，再由同一个策略决定怎么用：探针意见不一的拿去做 RL，够不着的做成带提示的示范。九个多模态搜索基准上，9B 和 27B 模型的平均准确率分别比所基于的方法高 9.8 和 9.5 分；把改进者冻结在训练起点会掉 3.2 分；计算开销是静态任务生长的 1.27 倍，不用外部模型。**启示**：自生成训练任务时要保证"环境里真有答案"，否则自演进是在惩罚正确行为。
- **A7 · [From Acting to Learning: Experience Selection toward Continually Learning Agents](https://arxiv.org/abs/2611.27159)** · Yaoyuan Yan 等 7 人 · 2026-11-20 —— 成功的交互记录不等于该学的记录。给一个 4B 语言 agent 比较 9 种经验选择器，两个经验池、8 个初始化种子、2 个采样种子，共训 288 个学生，在 128 组开发任务上评。按优化器感知的梯度来选，成功率 81.45% 和 73.19%，比全局随机高 8.25 和 5.96 分，比"挑高 NLL 的"高约 4 分；另在事先冻结的 128 组保留任务上复现，差值为 +7.03 和 +5.03。**启示**：用自己的成功轨迹做持续学习时，"选哪些学"值得单独做实验，而且要像这篇一样多种子、留一份冻结的复现集。

### 精读 B · 评测方法论：谁来判分、判分器本身对不对

- 🧪 **B1 · [Who Grades the Agent? Privilege Separation for Coding-Agent Benchmarks](https://arxiv.org/abs/2611.27860)**（SplitBench）· Nathan Nour Houlamy 等 4 人 · 2026-11-20 —— 给编码 agent 判分往往要运行它写的代码，而这些代码可以反过来操纵评测过程。论文提到自动审计器 BenchJack 不解题就在十个常用 agent 基准中的九个拿到接近满分。SplitBench 借用安全系统的权限分离：把"运行任务测试"和"判定结果"拆开，期望答案只在可信的判分器手里，agent 的代码即使接管了整个测试环境也伪造不出通过。Terminal-Bench、DeepSWE 等的 202 个任务里 180 个能转换过来，与原生判分器在 98.7% 的 agent 尝试上一致。最坏情况下（对抗 agent 能读全部判分代码、读不到期望答案）拦住 75% 的攻击，剩下的大多暴露的是原任务测试本身的弱点。**启示**：自建评测时，期望答案和判定逻辑放在被测代码够不着的进程里；和上期 Truthgate"评审要读 agent 改不了的记录"是同一条原则。
- 🧪 **B2 · [Benchmarks' Last Exam](https://arxiv.org/abs/2611.27622)** · James Zhu、Zekki Cat · 2026-11-20 —— 排行榜只报总分，没人核对每道题的提示、环境和判分器对"什么算成功"是否一致。作者汇总了 8 个前沿基准 749 个任务的逐题质量审查和 767 次公开模型评测。任务有效率和判分方式强相关：公开纠错后修订过的封闭式问答基准达到 92.5%，六个多步任务套件只有 29.3%。rubric 类套件的问题是提示和参考清单对不上；执行类 harness 多出状态断言不完整、共享通道泄漏、判分时冲突。已确认的缺陷里 71.7% 是让合规解拿不到分，28.3% 是放过捷径解，也就是说榜单上限低估了前沿能力。把提交的补丁放进全新容器里判分，可确认的运行时绕过从共享容器的 14.7% 降到 2.7%。**启示**：引用基准分数前先看这个基准的任务有效率；agent 基准的判分一律在干净容器里做。
- 🧪 **B3 · [CodeReviewBench: An Automated Benchmark for Evaluating the Software Factory](https://arxiv.org/abs/2611.26942)** · Ashley Zhang 等 12 人 · 2026-11-19 —— 代码审查质量没有客观校验器，现有基准的标注者是第三方评审，而真正决定改不改的是 PR 作者。这个基准改用"显示偏好"：开发者按审查机器人的建议改了就算有用，无视就算没用。信号每天从 GitHub 公开事件流里挖，覆盖 18 个工具、50 多万个已判定的 PR，并随工具更新持续刷新。作者用一个独立的离线基准做了验证：两者在精确率排名上一致，并且都能在厂商发版后几天内检测到同一次产品更新。**启示**：评审类 agent 的线上指标可以用"建议被采纳率"，它便宜、持续更新，但要用一个离线集校验它的排名是否可信。
- 🧪 **B4 · [ProbeAgent: Principled Diagnosis of Agent Failures in Verifiable Environments](https://arxiv.org/abs/2611.26897)** · Yue Huang 等 13 人 · 2026-11-19 —— 同样的失败结果可能来自任务太难，也可能来自 agent 跨任务重复犯的错。ProbeAgent 对每条失败轨迹先解释错误，再构造保留"疑似原因"、换掉周边情境的新任务，让 agent 重跑，看同一错误是否复现；然后把原因相近的失败聚成失败模式并写出描述。22 种 agent 配置、10 个基准的任务，收集 1,244 次失败，产出 536 条失败模式描述，能把"没做完"细分成"只规划不动手""交付文件前就停了"等。人工评估中，标注者接受 90.0% 的归属描述，并正确拒绝 83.3% 的相似干扰项。**启示**：错误分析不要停在读轨迹下结论，给每个猜想造一组"同因异境"的任务去验证。
- 🧪 **B5 · [Do Senior Agents Do Their Job? Measuring Role Integrity in How LLM Agents Use Subordinate Material](https://arxiv.org/abs/2611.27139)**（RI-Bench）· Jinxiang Xie 等 6 人 · 2026-11-20 —— 多 agent 系统只给最终答案打分，看不出上级 agent 是在权衡下级报告还是简单汇总。RI-Bench 取同行评审、上诉审理、议会质询三种制度（规则明确规定了上级的职责：权衡、核实、转述），不评输出对错，而是控制下级材料的变化，看上级输出怎么反应；判定用规则检查加按人工标注校准过的 rubric LLM 评审。8 个模型、12,000 多个回合：上级很少采纳植入的程序性错误（2.9%），但经常跟随多数的泛泛评审意见（最高 71%），或丢掉证人自己声明的局限（最高 65%）。加职责提示能减少但消不掉这些问题，还会改变对照组的行为。**启示**：评 orchestrator 要做扰动实验（改子 agent 的材料看主 agent 是否跟着变），不能只看最终答案。
- 🧪 **B6 · [TuringSpace: Grounding Spatial Intelligence in Action with Interactive CAPTCHAs](https://arxiv.org/abs/2611.25387)** · Xuwei Ding 等（HF 组织：Meta）· 2026-11-19 · HF ↑23 —— 125 个要靠点击和拖拽完成的交互式 CAPTCHA，覆盖五类空间能力，每个任务程序生成、带检查器和标准解，也能当训练环境。人类完成 94.1%；最强的 GPT‑6 Astra 仍有 25.9% 失败，最强开源模型 Kimi K3 失败 68.0%。失败大多来自读错截图，而且推理很少纠正感知错误，反而编造证据来维护它。用这个环境微调 Qwen3.5-9B，成功率从 1.6% 到 33.1%，七个分布外基准都有提升。**启示**：computer-use 评测把"感知错误"和"推理纠错"分开统计。

### 速览 · 自演进 / 记忆 / 后训练（14 篇，读了摘要，取主要结论）

- [MedicalRSI](https://arxiv.org/abs/2611.26806) · Ziqing Wang 等 · 11-19 —— 一个模型兼任解题者和改进者，改进者根据失败写医疗 harness，按"比不用它多得多少"给奖励，两个角色一起训练；摘要称能迁移到未见过的流程、新模型和新数据库，但没给数字，所以放速览。
- [NavRSI](https://arxiv.org/abs/2611.27499) · Guangzhao Dai 等 · 11-20 —— 设计者 agent 重写导航 harness，只保留有效修订，设计者自己也积累修订经验；仿真器的特权诊断只给设计者。R2R-CE val-unseen 上 GPT‑6-Astra 成功率 85.64%，比此前最好高 4.13 分，真实人形机器人上也验证过。属视觉导航领域，放速览。
- [Embodied-Harness](https://arxiv.org/abs/2611.27689) · Zhenxuan Fan 等 · 11-20 —— Actor 执行、Reflector 把执行证据变成可复用的操作指引，不更新参数；RoboTwin 2.0、RoboSPA、RMBench 成功率 82.4% / 76.7% / 94.4%。机器人操作领域。
- [RemoteEvolver](https://arxiv.org/abs/2611.27110) · Shengxiang Xu 等 · 11-19 —— 遥感 agent 的外部 harness，按执行反馈补工具、把验证过的成功经验提炼成 skill；工具齐全和部分缺失两种设置下，比初始状态平均高 8.18 和 23.86 分。遥感领域。
- [SIR-Agent](https://arxiv.org/abs/2611.27285) · Yijian Wang 等 · 11-20 —— 图像修复 agent 用 skill 库替代微调，修订后的 skill 与已知任务兼容就替换、不兼容就追加；还用元学习改进"修订策略"本身。14 个基准加 7 个未见任务。图像修复领域。
- [RoHa-SGG](https://arxiv.org/abs/2611.27529) · Jee Eun Kim 等 · 11-20 —— 先由根因分析 agent 找出场景图模型在哪个组件丢结果，再由提议 agent 搜 harness；有根因引导时，搜索达到同样分数最快快三倍。视觉领域，但"先定位再搜索"可以借鉴。
- [MoHA](https://arxiv.org/abs/2611.27646) · Jianghan Chao 等 · 11-20 —— 长视频 agent 的 harness 按所搭载的规划模型和观察模型做适配；三个模型栈上 Video-MME 提高 6.2–27.1 分；适配后的 harness 换到别的模型上只能部分迁移。结论和 HF 的 harness 适配器一致：harness 是按模型调的。
- [Bel](https://arxiv.org/abs/2611.27222) · Jiajun Fan 等 · 11-20 —— 视觉 agent 的正确动作常在自己的采样里，只是没被贪心解码选中。把每个候选动作画在截图上，让决策模型给出"执行它是对的"的概率，不训练任何东西；在移动、网页、桌面三类屏幕上都显著优于贪心解码和投票。
- [ADAPT: Learning When to Ask](https://arxiv.org/abs/2611.27443) · Aasheesh Singh、Vishal Vaddina · 11-20 —— 教小模型在什么时候向强模型求助：TextWorld 24.5% → 77.3%，LiveCodeBench 21.8% → 56.0%，GAIA 17.5% → 49.3%，每个任务只问约 1.0–2.1 次；换成训练时没见过的顾问仍有效。
- [DM-PRM](https://arxiv.org/abs/2611.27068) · Jiajun Fan 等 · 11-19 —— 把通用决策模型（回答是 / 否并给概率）零样本当作过程奖励模型，每步问一个问题、把标准化后的回答加到优势里；Qwen2.5-1.5B 上让 GRPO 在 ALFWorld 提高二十多分。
- [CSPD](https://arxiv.org/abs/2611.27376) · Zhen Zhang 等 25 人 · 11-20 —— 每个 RL 专家各自蒸馏成一个软提示，拼接即可组合，不用联合训练；23 个设置里 22 个能恢复教师至少 90% 的增益，全部组合后与多教师蒸馏持平（67.83 对 67.79）。
- [SkillBridge](https://arxiv.org/abs/2611.26256) · Anjie Xu 等 · 11-19 · ICSE 2027 —— skill 跨操作系统失效的诊断与修复：静态分析 1,090 个 skill × 三个系统的 3,270 个组合，再对选中的做动态验证；修复后目标任务通过率从 30.6% 到 38.4%，185 次动态验证找到 38 个确认问题，随机抽查约需 865 次。
- [Privacy Protection in Self-Evolving Personal Agents](https://arxiv.org/abs/2611.26983) · Zibin Lin 等 · 11-19 —— 综述：持久记忆的准入、维护、释放和撤回；指出"读取方不再使用"不等于学到的状态已被清除，缺少谱系记录会让衍生内容找不到。
- [MemOnce](https://arxiv.org/abs/2611.27973) · Chang Nie 等（HF 组织：Nanjing University）· 11-20 · HF ↑12 —— 架构层的记忆：只缓存少量最后一层隐状态作为紧凑记忆，用时再解码回 KV 缓存，并做稀疏检索。属模型架构，不是 agent 工程，了解即可。

### 速览 · 评测、harness 与治理（13 篇，读了摘要，取主要结论）

**异同和可以照搬的点**。本期各家的做法集中在一个问题上：**判分的那一方可不可信**。SplitBench 和 Benchmarks' Last Exam 从两头说了同一件事：编码 agent 的基准里，判分器要么能被被测代码操纵，要么本身就判错了（多步套件只有 29.3% 的任务有效）；修法也一致，判分放到被测代码够不着的地方、在干净容器里做。Hugging Face 在训练侧撞上了同样的问题，校验 RL 任务时顺带查出 Terminal-Bench 2.1 的一个错误校验器。LLM 评审这一侧，《Your Judge Inherits Your Prompt》说明少样本示例的正反比例会让评审单向虚高，RI-Bench 和 AstronautBench 则都用了"校准过的评审 + 规则检查 / 双评审"的组合。可以直接照搬的四条：① 判分进程和期望答案与被测 agent 隔离；② 评审器的示例正反平衡、多次抽样；③ 成功攻击和失败案例存成回归集，每次改动先重放（OpenAI）；④ 评自改进和记忆时加一列"答案是否有 agent 自己的证据支持"。各家不同的地方在数据来源：OpenAI 和 Google 用内部红队与线上流量，CodeReviewBench 用公开事件流里的开发者行为，学术界仍以改造现有基准为主。

## 趋势观察

**RSI 的口径在从"研究员被加速了多少"扩到"底层指标走到哪了"**。上期 OpenAI 的研究加速报告量的是人：研究员人均 agent 工作日从 0.5 到 5.7。本期的困惑度一文量的是模型本身，并且第一次把"共同上限"写成了具体提议：按困惑度划线，监控技术达到里程碑之前不越过。文章对时间的判断（最早 2027 年出现预训练进展的雪崩）比上期 Christiano 在 Dwarkesh 播客上的"6–12 个月"略晚，方向一致。两篇放在一起读，OpenAI 的立场是：全自动 RSI 要避免，但部分自动化带来的加速已经在发生，需要一个跨实验室可比的指标来约定节奏。

**论文侧给这个判断泼了点冷水，也给了测量方法**。CoEvoBench 的结论是前沿模型第一轮能改、第二轮接不上；AstronautBench 发现答对率在涨、证据支持率没跟上。它们和上期"按评分挑改进约等于随机""无反馈自改 30 轮掉 15 分"是一条线：自改进的瓶颈在于系统能否可靠地知道"这次改动是否真的更好"。本期的 ZhuLong-SE、EvoTER、HookEvo 都把这道闸做成了显式组件（留出集回滚、全新会话验证、配对任务对比），这已经是自演进系统的标准结构。

**harness 是按模型调的，这个结论本期有三处独立证据**：Hugging Face 的三个 LoRA 各自在自己的 harness 里提升最大、分布外持平；MoHA 发现适配后的 harness 换模型只能部分迁移；HookEvo 里不同改进者从不同编辑范围获益不同。对做应用的人来说，"换了模型之后 harness 要不要重调"的答案是要，而且值得为此留一套固定的评测任务。

**评测基础设施本身成了研究对象**。上期是 agent 作弊（Truthgate），本期往下挖了一层：判分器可被操纵（SplitBench）、任务本身无效（Benchmarks' Last Exam）、评审示例带偏（Judge Inherits Your Prompt）。引用任何 agent 基准分数之前，先问三件事：判分在哪里跑、任务有效率多少、评审器校准过没有。
