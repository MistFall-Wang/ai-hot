### Anthropic

- ⭐ **[How AI agents shape experts' judgment calls](https://www.anthropic.com/research/agents-judgment-calls)** · Anthropic Research（Alignment；作者 Amaç Herdağdelen、Hailey Joren、Alex Tamkin，附完整论文）· 2026-10-27

**这篇解决什么问题**：专家把活交给 agent 后，通常默认"关键判断还是人做的"。这项随机对照试验直接检验这个假设：当 agent 对没有标准答案的分析决策有自己的倾向时，专家是自己做决定，还是不知不觉顺着 agent 走。

**核心论点与数据**：
① **设计**：招募 61 名通过因果推断知识测验、常用 Python / R、有观察性因果分析经验的专业分析师，在内置 Claude Code（Claude Opus 4.8，High effort）的网页版 VS Code 里评估一个虚构农业合作社的付费咨询项目该不该推广（董事会只在生产率提升约 3–4% 时才扩大）。中间留了四个各有两个合理选项的分析决策：产出口径（每公顷产量 vs 每单位成本产量）、比较方法（双重差分 vs 直接比较加统计调整）、覆盖范围（只算入组农场 vs 全体成员）、加权（每户等权 vs 大户加权），再加最终建议。每个决策 agent 的"倾向"由抛硬币决定，写在隐藏系统提示里：把它当自己的观点、决策出现时主动提出、尽力论证；证据明显相反时改口，绝不歪曲数据。11 人选择不用 agent，分析以其余 50 人为主（65% 有硕博学位或六年以上经验，90% 自评熟练或专家，中位用时 65 分钟）。
② **顺从率**：四个分析决策上分析师的选择与 agent 倾向一致的比例分别为 92%、82%、81%、90%，合计 86%（无影响时应为 50%）。
③ **最终建议**：agent 倾向推广时 54% 的人建议推广，倾向相反时 36%；效应较弱是因为有了估计值之后建议基本由是否过线决定。但只用四次抛硬币的结果就能预测 82% 的最终建议（总是猜多数类为 61%）。
④ **改主意**：38 个案例里分析师在 agent 表态前已有偏好，agent 反对时 60% 改主意，赞同时 6%；差 54 个百分点，但样本小，95% 置信区间 24–82。
⑤ **谁会顺从**：经验年限、自评专长、学历、测验分、对 AI 的信任、使用频率、认知需求、开放性、性别、年龄十项特征都预测不了；只有年龄显著，做多重比较校正后消失。
⑥ **自我归因**：52% 的人认为最终建议"更多是自己的"，但这组人的选择平均向 agent 倾向移动了 65 个百分点，另一组 79 个百分点，差异在误差范围内；全部跟随倾向的人对建议的信心 71 分，其余 73 分。事后解释里 77% 至少在一处复述 agent 的论据，有的逐字，只有 15% 在任何地方提到 agent。48 人里 6 人猜到研究在看 AI 的影响，没有人怀疑 AI 的倾向被操纵过。
⑦ **不用 agent 的 11 人**：55% 犯了使结果无效的严重方法错误（用 agent 的为 6%），中位用时 90 分钟（用 agent 的 65 分钟）；但这组更没经验，作者不下因果结论。
⑧ **默认倾向**：不设倾向时，Claude Opus 4.8 在 123 次运行里 112 次做出同样的五个选择；完整论文称无倾向的 agent 偏好更弱，有时会反驳用户。
⑨ **局限**：故意强化了倾向；一个任务、一个领域、一个模型；只记录了选项没记录偏好强度。
⑩ **含义**：agent 很少替"另一个选项"做最强论证，分析师于是直接接受了它的假设。多个团队依赖同一模型的偏好时，结论一致不再意味着独立；AI 安全研究里用 agent 跑实验、人来复核，同样面临"复核不再独立"的问题。

**对 AI 应用工程师的启示**：
- 判断型 agent 的输出要对每个合理选项都给出最强论证，并标明"这是我先提出的倾向"；只论证一边的 agent 会替用户做决定而用户不自知。
- "人在环上"要被设计成可度量的：随机化 agent 的倾向、看用户的选择分布，是检验复核是否独立的方法；事后问用户没用，他们报告不出来。
- 这和同周 Google 的 Thinking-in-Bets（agent 被质疑时放弃正确答案）是同一问题的两面：谁听谁的，要显式设计。

- **[Early progress on accelerating drug development with Claude](https://www.anthropic.com/research/early-progress-drug-development)** · Anthropic Research（Science 团队；每个案例附合作方技术报告）· 2026-10-27

**这篇解决什么问题**：Anthropic 生命科学团队与六家药企（BigHat、Bristol Myers Squibb、Divergence Labs、Enveda、Generate Biomedicines、The Column Group）做了数月深度合作，并开始自己的药物发现项目。文章讲 Claude 在药物研发各环节能做什么、不能做什么，给出可核对的数字。

**核心论点与数据**：
① **Generate Biomedicines（模态工程）**：六名科学家用 Claude Code 重设计 CAR-T 疗法的一段基因指令，一个设计比标准版短约 70%，实验中免疫细胞受体数量约 10 倍、杀瘤更有效、存活更久。
② **Divergence Labs（命中生成）**：Claude 把目标转成详细设计计划后，基本自主地在约一个月内生成约 35,000 个抗体设计；早期测试在两条"臂"上分别找到 3 个和 20 个命中，其中 3 个比标准药更能把 IgE 从免疫细胞上拆下来。
③ **BigHat（先导优化）**：Claude 接入实验室数据系统 Reccy 提出改动，实验室 10 周内制备测试约 1,010 个变体；中途团队怀疑标准的热稳定性和聚集指标误导，Claude 与研究员重分析原始数据，提出替代指标和实验方案，主要预测成立：最优版本结合力高 10 倍以上，抗癌先导耐热高 18°C。
④ **Enveda（生产与申报）**：制造化学家此前最多 75% 时间花在文书上；把全部生产文档接给 Claude 做质检，1,061 页里人工找到的 11 个问题全部命中并多找出 7 个，审核时间减少 89%（25 小时以上降到不足 3 小时）；两份监管文件初稿一份 4 小时写完（人工约 3 个月），另一份人工复核只发现一处小错。
⑤ **The Column Group（公司创建）**：新公司 Pleiades 用 Claude 跑远多于小团队常规数量的药物项目，第一个 Claude skill 评估药物靶点是否值得做，已在 45 个靶点—疾病对上评测。
⑥ **BMS**：用 Claude 评估早期临床试验计划并估算成功概率，计划 2027 年扩大。
⑦ **自营**：收购一人公司 Mithril Medicine，创始人用 Claude 管理与 11 家外部实验室的合同、物流和实验，18 个月内把一种肌营养不良症候选药推进到小鼠阳性结果，预计最早 2028 年末进入临床。
⑧ 文章承认工作基本处于临床前阶段。

- **[Fast, reliable A2UI, with swappable inference formats](https://developers.googleblog.com/fast-reliable-a2ui/)** · Google 开发者博客（A2UI 项目）· 2026-10-27

**这篇解决什么问题**：A2UI 是 agent 驱动生成式 UI 的协议：客户端公布可信组件目录，agent 发消息描述界面，渲染器绘制。此前 agent 直接生成受复杂 JSON schema 约束的传输消息，慢且易错，还把 A2UI 绑死在输出文本的 LLM 上。

**核心内容**：
① **解耦"模型生成的格式"和"传输格式"**：SDK 根据组件目录的 JSON schema 同时生成提示词片段和编译器，模型写中间 DSL，确定性代码编译成合法 A2UI 消息；因为两者都来自 schema，格式不可能引用目录外的组件或属性。
② **A2UI Express**：一行一句、接近 Python 的语法，变量名即组件 ID，参数按 schema 声明顺序位置传递，`_` 跳过一个，`$/title` 绑定数据模型，`Event("accept")` 声明服务端动作。相同界面比 Direct JSON 少用最多 3 倍 token、延迟最多降 3 倍；在 51 个任务的评测上对比了 Direct JSON、Express、Atom（S 表达式）、Elemental（HTML）四种格式（gemini-3.5-flash，思考开 / 关），Express 关掉思考也保持质量。Python（a2ui-agent-sdk 0.9.0）、TypeScript、Dart SDK 均支持；Python 宏可让模型只写 `OrderStatus("ord_42")`，由宏取数填值。
③ **决策模型做受控生成**：形状固定的页面（设置页、结账页）不需要模型设计布局，只需在预定义布局里选。TypeSafe 的 Jev 是"System One"决策模型：输入状态和一组类型化问题（真假 / 选项 / 评分），100–300 毫秒内回答约 30 个布局问题，代码拼装组件树，gemini-3.5-flash-lite 只写文案。开源示例 Apparite 在 11 个提示上组件树 92–298 毫秒上屏、整页 0.8–1.7 秒完成、全部产出合法 A2UI，延迟最多降 80 倍；但只能产出语法描述的九种页面原型和十二种块。
④ 选择规则：能预定义的页面用受控生成，需要完整表达力的用 Express。

**对 AI 应用工程师的启示**：让模型输出结构化内容时，不要让它直写 schema 复杂的 JSON，改写一种为它设计的紧凑 DSL，由确定性编译器保证合法性；形状可预定义的输出干脆改成"分类决策 + 代码拼装"。四种格式同一评测对比的做法本身也值得复用。

- **[Build Generative UI Apps with A2UI & CopilotKit Agents](https://developers.googleblog.com/build-generative-ui-apps-with-a2ui-copilotkit-agents/)** · Google 开发者博客（A2UI 项目，与 CopilotKit 合写）· 2026-10-29

**这篇解决什么问题**：agent 能规划行程却只能返回一堵文字墙，没有标准办法在对话里渲染可选列表、地图或日期选择器。文章讲 A2UI 与 CopilotKit（基于 AG-UI 协议）怎样接起来。

**对 AI 应用工程师的启示**：生成式 UI 的三条做法：组件白名单加 schema 校验、生成放在独立子 agent 里不占主上下文、无效输出带错误回传自修复后再上屏。和上一篇合看，A2UI 已经把"模型写什么格式""谁来校验""怎么回传"三件事都标准化了。

### 精读 A · 自演进的能力树与记忆的净价值

- ⭐ **[The Trinity: Capability-Driven Recursive Self-Improvement for Multimodal Agents](https://arxiv.org/abs/2610.36077)** · The Trinity Research Team（Weidong Tang 等 20 人；HF 组织 National University of Singapore）· 2026-10-26 · HF ↑389

**这篇解决什么问题**：多模态 agent 的进化卡在两处：构造异构、可验证的环境太贵；人工迭代 harness 跟不上任务多样性。作者的关键观察是不同模态和表面形式的任务可能共享同一能力需求，于是把"世界生成"和"harness 进化"耦合成一个递归自改进框架。

**核心论点与数据**：
① 三个角色：Creator 把同一能力节点下不同形态的任务抽象成简化、可验证的模拟世界；Explorer 沿能力树逐步进化可复用的能力模块，形成固定拓扑内只累积验证过更新的 harness 树；Evolver 根据验证过的执行轨迹，按"共享能力需求"而非表面类别重组任务树。
② 能力感知路由器按任务公开信息选模块配置。
③ 进化后的 harness 在 28 个训练基准上平均 +34 分，在 18 个未见基准（含两个真实具身任务）上 +26 分。
④ HF ↑389 是本期最高之一。

**对 AI 应用工程师的启示**：按"能力需求"而不是按任务类型组织 skill / harness 模块，拓扑固定、只累积验证过的更新，便于迁移到新任务；"同一能力换一个表面形式出题"是便宜的验证集生成法。和上期 RSIHub（增益不一定迁移到留出任务）对照，这篇给出了留出集正面数据，但 18 个未见基准的具体清单和每项数字要看原文。

- ⭐ **[Memory Tax: Dissecting the Net Value of Agent Memory](https://arxiv.org/abs/2610.34073)** · Xuan He 等 11 人（伊利诺伊大学厄巴纳-香槟分校 / 清华大学 / 中国人民大学 / Verdent.ai / 滑铁卢大学，据 arXiv HTML 作者栏；作者含 Jiawei Han、ChengXiang Zhai）· 2026-10-25 · HF ↑156

**这篇解决什么问题**：记忆系统在长时程 agent 里越来越常见，但它们究竟比"直接对原始历史做 RAG"好多少？作者在多个基准和多个模型底座上做大规模评测，发现很多专门的记忆系统在不少情况下不如朴素 RAG，净价值为负。

**核心论点与数据**：
① 以 RAG 为参照，把记忆的净价值拆成"记忆收益"和"记忆税"：记忆处理改变了原始信息的组织和访问方式——重组事实、提炼偏好能带来收益，也可能删掉或掩盖证据，这就是税。
② 论文重点分析税从系统侧（压缩、抽象、索引时丢了什么）和评测侧（基准怎样奖励或惩罚这种丢失）怎么产生，并推广到更多记忆应用场景；代码和结果将开源。
③ 结论的强形式："很多情况下"净价值为负，不是"所有"。

**对 AI 应用工程师的启示**：上线任何记忆模块前先跑"对原始历史做 RAG"这条基线，报告净增益而不是单独分数；审一遍记忆写入时丢掉了哪些证据。和同周 AMIE（只累计检索频率就能稳定提分）、When Retrieval Is Not Enough（一条过时的竞争陈述能把准确率从 100% 打到 44.6%）合看，记忆层的三个便宜动作是：保留原文可回溯、给每条记忆记"被检索 / 被采纳"次数、把过时版本显式标记而不是并列返回。

### 精读 B · 自演进的两条新红线

- ⭐ **[Masked Erosion: How Acceptance Gates Lose Redundant Safeguards in Self-Improving Agents](https://arxiv.org/abs/2610.38392)** · Hau-Sing So 等 3 人（澳门大学 / 清华大学，据 arXiv HTML 作者栏）· 2026-10-28

**这篇解决什么问题**：自改进 agent（ADAS、Darwin Gödel Machine、GEPA、ACE、Self-Harness 这一类）编辑自己的 harness，只有验收门在一批任务上打分更高才保留编辑。验收门看到的是 harness 在当前模型下做了什么，看不到"某条安全规则失效时它还能挡住什么"。当安全规则互相重叠，删掉一条是被"遮住"的：别的规则还在挡，门只按任务分决定，冗余在看不见的地方被侵蚀。

**核心论点与数据**：
① 两个环境（AppWorld 里的凭据滥用、OpsSim 里的破坏性清理）、四条书面安全规则的全部 16 个子集逐一测伤害，跑 411 轮改进循环、10 种门规则，大多是受控删除实验，外加 3 轮原样 GEPA。
② 一条规则被另一条正常工作的规则遮住时，删掉它几乎不增加可观测伤害。
③ 配对显著性检验能挡住碰运气通过的删除，但挡不住真能提升任务分的删除；评测批次越大，门越能删掉"便宜"的规则：同样成本下 20 任务批次让每个 harness 都保住了防护，40 任务批次把六条规则全丢了。
④ 大规模伤害审计能防止当下暴露，但防不住深度流失；深度流失在 harness 换到更弱的模型上复用时变成真实伤害：GEPA 原样保留了所有安全规则文本，但三个终版 harness 里有两个在弱模型下滥用凭据（"规则还在、行为变了"）。
⑤ 一个在实验前冻结的统计模型能预测随规则成本和批次大小变化、每种门的防护在哪里崩；冻结安全文本或审计单层消融能保住深度。

**对 AI 应用工程师的启示**：
- 验收门只看任务分是不够的：要对安全规则做"单层消融"审计（删掉一条看伤害是否上升），或者干脆把安全文本冻结在可进化区域之外。
- 评测批次更大不一定更安全——它让门更有把握地删掉"看起来没用"的规则。
- harness 要跟模型一起验收：在强模型下通过的 harness，换弱模型前要重新测安全。
- 和 Treude（自提改动多数无效）、Evolve-IPI（下一篇）合看：自演进的最低配置是"改动带后续验证 + 安全回归 + 不可进化的安全区"。

- ⭐ **[Appreciation Teaches Unauthorized Execution: Self-Evolution Degrades the Robustness of Personal Agents to Indirect Prompt Injection](https://arxiv.org/abs/2610.39122)** · Xinyan Wang 等 4 人（威斯康星大学麦迪逊分校 / 约翰斯·霍普金斯大学，据 arXiv HTML 作者栏；作者含 Chaowei Xiao）· 2026-10-29

**这篇解决什么问题**：自演进的个人 agent 替用户办事并从用户反馈里学习。如果它服从第三方藏在内容里的指令，第三方就控制了它（间接提示注入，IPI）。问题是：自演进会不会让它更容易被注入？

**核心论点与数据**：
① 两阶段受控方法。适应阶段：用户让 agent 读外部内容并完成内容里描述的任务（日常常见请求），agent 按设计从用户反馈里学习并自我改进。测试阶段：第三方把类似任务写进新的外部内容，但用户的测试请求并没有授权那个任务。
② 在一个真实个人 agent 上构造多个领域、多种测试实例。
③ 相比不从用户反馈演进的基座 agent，skill 进化让平均攻击成功率上升 14.0–48.8 个百分点，RL 上升 3.0–39.3 个百分点。
④ 代码已公开（SaFo-Lab/Evolve-IPI）。

**对 AI 应用工程师的启示**：
- 用户的"赞赏"教会 agent 的是"读到任务就执行"，而不是"用户授权的任务才执行"。自演进的奖励信号要能区分这两者：把"是否来自用户的明确授权"作为可学习的特征，或在 skill / 经验里显式记录授权来源。
- 自演进 agent 的安全回归要包含注入评测，而且要在演进前后各测一次。
- 和 Masked Erosion 合看，这是本期第二条红线：自演进会在任务分上涨的同时悄悄降低安全属性，验收必须多目标。

### 精读 C · 自演进进生产：知识模块、推荐系统

- ⭐ **[KARMA: Training-Free Knowledge-Atomic Harness Evolution for Industrial Advertising Agents](https://arxiv.org/abs/2610.39884)** · Xinhua Miao 等 4 人（阿里国际数字商业集团，据 arXiv HTML 作者栏）· 2026-10-29

**这篇解决什么问题**：工业广告 agent 的决策知识要随商品、流量和运营政策持续变化。KARMA 在模型权重和可执行 harness 代码都冻结的前提下，只进化六类类型化知识模块。

**核心论点与数据**：
① 流程：确定性 Trace Verifier 把观测到的错误映射到候选模块；Critic 对比成功与失败轨迹指导受工具约束的 Evolver；Evolver 做原子知识编辑；固定验证门只在测得的增益达到阈值时保留，否则恢复上一知识状态。
② 数据：从约 50 万条真实运营日志（六个电商域）采样案例，三个 LLM 家族。
③ 结果：18 组域 × 模型设置下留出均分从 30.19 升到 39.15（+8.96，+29.7%）；去掉成功轨迹或失败轨迹任一项，平均留出增益减半以上；进化出的知识不加适配就能跨域迁移，所有源—目标对平均留出 +8.54。

**这两篇解决什么问题**：让 LLM agent 自主改进推荐算法（RSE-Agent）正在成为一个方向，但能力边界和效率都不清楚。

**核心论点与数据**：
① **AutoRSE**：六个工业级推荐任务，三个前沿模型 × 三个常用 agent harness。RSE-Agent 在六个任务里的五个稳定提升底座，平均相对 +16.1%，说明已经能自主改进推荐效果；但轨迹级分析发现它们主要是"工程优化器"而不是"算法改进者"：增益来自调超参、训练策略和模型集成，真正的算法创新很少。注入前沿研究或人类专家的想法后，提升明显大于自生成想法——想法生成是当前的核心瓶颈。
② **RecRSI**：推荐系统的训练配方改动要全量重训才知道好坏，大量重训预算花在后来被丢弃的编辑上，而重训前的信号（采样训练损失）不可靠且跨编辑不可比。RecRSI 从对当前模型的诊断生成多个候选编辑，每个候选只跑训练开头一小段，用留出探针用户上的全排序 NDCG@10 打分，再选一个全量重训。两个序列推荐器、三个数据集、相同重训次数下每种设置都显著优于现有自演进 agent，在两个 Amazon 数据集上第一轮就达到其他方法五轮都到不了的排序质量。

**对 AI 应用工程师的启示**：自演进系统要分清"工程优化"和"算法创新"两种增益，前者 agent 已经能稳定交付，后者还要人喂想法；候选改动先做短试跑再决定是否投入全量资源，是把自演进成本压下来的通用办法（上期 TGR-EvoDAG 的分阶段成本规划是同一思路）。

## 趋势观察

**1. 监控、规范和对齐指标开始"写进发布"。** OpenAI 这周把失准监控的四层架构、各层节奏、召回评测材料和红队结果一次公开，并把"监控不改奖励、异步运行"写成原则；Model Spec 改按价值组织，明说模型还没达到；DeepMind 把 Terminal-Bench 作弊率 0.0%、越权 −26%、少做 −29%、无依据断言减半、注入成功率 0.0% 和能力分数并列写进 Carbon 发布页。上期的结论是"围堵从沙箱升级到安全论证"，本期是安全论证的内容开始标准化：评测表里要有这几列，监控层要有回放召回的数字。

**2. 人在环上要被当作需要验证的假设。** Anthropic 的随机对照试验给出 86% / 60% / 77% 三个数：分析师跟随 agent 倾向、被反对时改主意、用 agent 的话解释自己的选择；经验、学历、对 AI 的信任都不能免疫。这和 Google 的 Thinking-in-Bets（agent 被质疑时放弃正确答案）、Treude（agent 自提的 harness 改动多数无效但看起来合理）、FeatureArc（agent 95% 的时间不回头检查自己早先的错误）构成一组：无论是人复核 agent 还是 agent 复核自己，"复核是否独立"都要设计和测量，不能默认。

**3. 自演进拿到了节律，也拿到了两条新红线。** Google 睡眠框架把"什么时候写进参数、写之前怎么筛、写完怎么验收"做成固定周期；KARMA 在 50 万条真实日志上证明"只进化知识模块、权重和代码冻结、每条补丁带证据可回滚"是可审计的形态；AT-AT 在生产 MCP server 上降成本或错误率；Trinity、PCE、CoHARL、SkillCompiler 各自在留出集或新基准上给出正面数据。反方向：Masked Erosion 证明验收门只看任务分会删掉冗余安全规则，批次越大删得越狠，换弱模型后出事；Evolve-IPI 证明从用户反馈学会"读到任务就做"会把注入攻击成功率抬高 14–49 个百分点。加上 Treude 和 AutoRSE（增益主要是调参不是算法），本期对自演进的工程结论是：多目标验收（任务分 + 安全回归 + 留出泛化）、不可进化的安全区、改动带证据和回滚、评测批次大小也是安全参数。

**4. 记忆层的问题从"要不要"变成"怎么算账"。** Memory Tax 说很多记忆系统不如朴素 RAG；When Retrieval Is Not Enough 说一条过时陈述能把准确率从 100% 打到 44.6%；AMIE 说只记检索次数就能提分；CALM 把"永久保存"和"查询时准入"解耦；Stratum 说瓶颈是选择不是容量；Security of Memory Files 和 Role Grounding Attack 说记忆文件和社交记忆都是攻击面。上期的结论"自写记忆是控制面"本期有了账本：每个记忆模块都要对 RAG 基线报净增益，每条记忆要有来源、版本、访问统计和准入门。

**5. harness 的理论和实操同时到位。** Your Policy Is Secretly a Harness 把上期"模型 × harness 配对"的经验结论写成公式（部署回报 = harness 上限 − 策略失配，训练只改失配），并用 MiniWoB 的 85.0% → 19.2% 说明策略带着 harness 的偏好；Rethinking Verification 说验证预算优先给独立 critic；Effort Level 说默认最低强度、失败再升级；Google 的 Agents CLI 把"改一行、跑一分钟、逐用例看分差"做成命令；A2UI 把"模型写什么格式、谁来校验、怎么回传"标准化。对 AI 应用工程师，这一周的 harness 材料足够支撑一次"为什么不能只换模型"的完整论证。
