- 【必看】🧪 **[Building strong safety evaluations](https://www.anthropic.com/research/building-strong-safety-evaluations)** · 出处：Anthropic Research（anthropic.com/research，Engineering 索引页同步列出）· 2026-11-13 —— **解决什么问题**：安全评测的结果直接决定模型能不能发布、带哪些防护上线，但评测本身容易被钻空子、测的不是想测的东西、也难以复现。Anthropic 借用心理学应对"可重复性危机"的三项改革（预注册、更好的测量、更严的统计），结合自家 system card 的例子写出从设计到报告的做法。**核心内容**：① 设计阶段先分清问题是观察性的（"模型对进食障碍类请求回应得是否安全"）还是因果性的（"改系统提示会不会改变这一点"），因果结论必须一次只改一个变量。② 测量对象要对：自杀自伤类对话里"一律拒绝"在拒绝率指标上是满分，但其实是失败；所以多轮评测报告"恰当回应率"，整段对话有一轮不当就判整段不合格，每个风险领域由领域专家写专属 rubric；单轮评测把同领域的有害请求和正常请求成对放，同时测有害配合和过度拒绝。③ 多轮模拟的流水线：专家写规格（用户目标、手法、人设、处境、语气等维度，每个维度多个选项），首轮固定，另一个 Claude 按规格扮演用户、每次运行抽不同组合，评审模型按 rubric 打分；各维度要独立组合，否则分不清是"严重程度"还是"语气"在起作用。场景尽量从真实使用模式、红队记录、事故报告里来，并持续增删。单轮安全集覆盖 16 个政策领域、7 种语言和多个产品形态。④ 运行阶段防数据污染和捷径；单轮评测在 API 上各新模型都在 94%–98%，已经饱和，只适合做回归检查，变难要靠更长的时间跨度、更隐蔽的呈现，而不是加刁钻题。⑤ 统计：复杂多轮评测至少 100 条、单轮至少 1,000 条，每条跑多次并报告离散程度；比较两个模型用同一批题做配对比较；事先写下主指标、比较对象、切片和"算改进 / 算退步"的阈值，偏离计划要说明。多轮评测在 API 上的置信区间可超过正负 10 个百分点，恋爱诈骗多轮评测上 Opus 5 是 98%、Opus 5.5 是 94%，差异并不显著；同一模型在 API 与 claude.ai 两种配置下恰当回应率最多差 34 个百分点，所以必须报告运行配置。文中还说，因为自家此前的事故，已暂停多数给模型联网的评测，必须联网的搜索类评测加了实时监控。**对 AI 应用工程师的启示**：文中评审模型的六条做法可以直接当 LLM-as-a-judge 的检查清单——评分项拆成单一的是 / 否问题，并写明什么不算达标；写明免责声明、警告语、教育性包装不改变结论；评审只看对话、看不到构造场景用的元数据，尽量不用被测模型当评审，检查分数是否和回答长度相关、成对比较要交换顺序再跑一遍；评审出错的条目要报警并剔除，不能静默计分；人工在看不到评审结论的情况下盲标一批，报告校正过随机一致的人机一致率，并和人与人之间的一致率对比，人与人都不一致说明问题本身没定义清楚。面试里被问"你怎么知道你的 agent 评测靠得住"，按"构念效度—内部效度—评审校准—样本量与置信区间—预注册"这条线回答。

- 【必看】**[Building always-on agents](https://claude.com/resources/articles/building-always-on-agents)** · 出处：Anthropic · claude.com/resources/articles · 2026-11-13 —— **解决什么问题**：很多团队想让已有 agent 主动起来，或者从头做"常驻" agent（跨会话保持状态、无人监督时自己行动），但不清楚除了 agent 循环本身之外还要搭什么。**核心内容**：所谓常驻其实是"大部分时间睡着、被事件唤醒做一次 run、存档后再睡"，一次 run 发生在一个 session（消息和工具调用记录）里。外围结构拆成五个原语：① **事件收件箱**：各事件源不直接调 agent，而是写进一张持久表，由 worker 读取，避免两个事件同时到达起两次竞争的 run、或进程崩溃丢事件；handler 要快速确认（webhook 方会把慢响应当失败），提示注入检查放到 run 里做；收件箱是唯一事实来源，worker 中途挂掉新 worker 能重取；一个收件箱同时只允许一个活动 worker；连续多条消息合并成一次 run。② **定时器**：分"agent 给自己设的跟进期限"和"固定周期的任务"两类，单独一张表，由调度器轮询，到期后更新状态并往收件箱写事件。③ **记忆**：用持久存储里的文件目录，只存 agent 查不回来的东西（别处已有的存指针）；分用户指令、用户笔记、已发消息、任务进度四类，多文件时每次 run 只加载索引；可以加 dreaming 定期整理。④ **权限**：凭据由 agent 环境之外的代理在请求出站时注入，agent 自己拿不到；高风险动作走 auto mode 的分类器审查；需要人批准的调用用"延迟工具调用"——run 结束、session 停在调用中途，用户的回答作为新事件进收件箱再恢复，期间 worker 可以处理别的事件。⑤ **发件箱**：run 有三种结局（发消息、决定不发、挂起等批准），大多数情况一个"发送"工具就够。文中还给了一个成本数据：在一个长时程编程基准上，Opus 5.5 每解决一题的成本比 Opus 5 低 78%，一般工作负载上低 40%，作为常驻 agent 变得可行的原因之一。**对 AI 应用工程师的启示**：这是一份可以直接画在白板上的系统设计答案。已有按消息触发的 agent 要加主动能力，最小改动是加两张表（events、timers）和一个单 worker 消费者；人审批不要用阻塞等待，而是"挂起 session、审批结果当事件回来"，这样 agent 不会被一个待批请求卡死。和 OpenAI 11-12《Securing persistent agents like OpenClaw》（上期已收）对照读，两家在"凭据不进 agent 环境"上做法一致。

- 【必看】⭐ 🧪 **[Independent Assessment of AI R&D Acceleration at Anthropic in October 2026](https://metr.org/blog/2026-11-05-anthropic-ai-rd-acceleration-assessment)** · 出处：METR（Anthropic 独立评估者计划下的驻场评估，Anthropic 有删改权）· 2026-11-05（补录：日报与上期周报均未扫到，本期从 Dwarkesh 11-13 长文的引用发现）—— **说明**：这不是厂商自己发的文章，而是 Anthropic 10-15《An update on independent evaluators》里承诺的驻场第三方评估的第一份公开结果，评估对象与数据都来自 Anthropic 内部，按"厂商授权的官方评估"收录。**解决什么问题**：如果 AI 开始显著加速 AI 研发本身，能力可能突然跃升，这是递归自改进（RSI）风险的核心。外界一直只有厂商自报的数字。**做法**：2026-08-12 至 10-29，METR 人员在 Anthropic 内部做高权限评估，看到了预训练、RL 的多项指标、各领域训练算力、内部模型的基准分、AI 提速分析、对未来模型指标的预测，并访谈相关员工。**结论**：① 截至 2026 年 10 月，Anthropic 在定义明确的任务上提升模型能力的速度约为 2024-03 ~ 2025-10 的两倍，不确定性大，真实值在 1.3 倍或 3 倍都不意外；② 大部分加速可能来自 Anthropic 大量用 AI 做研发，但 2025 年末的加速也有其他重要原因；③ 自 2025-10 以来，以 AECI（Anthropic 版 Epoch 能力指数）衡量的基准分增速是此前的 1.9 倍（95% 置信区间 1.5–2.8），相当于一年走了约两年的历史进度；④ 可以确定加速不是因为训练算力扩张变快；⑤ 访谈和问卷与"AI 使用让能力进展翻倍"一致，研发主要靠 AI 辅助而不是完全自主的贡献，但有迹象显示完全自主的贡献很快会变多；⑥ 未来 12 个月内没看到算法、训练算力、实验算力或数据方面会卡住进展的明显瓶颈，不过 METR 对瓶颈的判断在拿到更细的信息后变过几次，信心不高。**透明度**：最能支撑上述结论的证据大部分被 Anthropic 删去，理由是"可能加速其他 AI 开发者的机密信息"；METR 明确写出这份报告没有做到"证据透明"，公众只能更多地依赖 METR 的判断。**对 AI 应用工程师的启示**：这是 RSI 进度第一份"外部机构进厂、看内部数据"的量化，面试里谈"AI 加速 AI 研发到了什么程度"可以引用 2 倍（1.3–3 倍）和 1.9 倍（1.5–2.8）这两个带区间的数字，并说明它的局限：只覆盖可验证任务、关键证据不公开。评测方法上也值得学：METR 同时用了基准增速、算力对照（排除"只是算力涨了"）、员工访谈三类证据互相印证。

### 精读 A · 自演进：经验要按"对下一次有没有用"来记

这一组六篇的共同点是：评价一条经验、一条记忆、一个 skill，不看它写得好不好，而看带上它之后下一次运行的结果有没有变好，并且要能被新证据推翻。

- 【必看】⭐ 🧪 **[Who Remembers What? Multi-Granularity Memory Extraction for Multi-User, Multi-Agent Interaction](https://arxiv.org/abs/2611.10439)** · Yunzhe Wang 等（HF 标注 Amazon Web Services）· 2026-11-07 · HF ↑13 —— **问题**：自演进 agent 把技能、记忆和 harness 代码当成可积累的经验，但在多用户、多 agent 共享时，一个用户的私密信息可能流到另一个用户那里。**做法**：记忆系统 MixUA 把各用户-agent 的独立轨迹提炼成教训，按"谁会受益、哪些内容可以披露"分配到四级作用域：用户-agent 对、用户、agent、全局；配套基准 CrossLearnBench 在常见 agent 任务上叠加用户偏好和隐私探针，检查私密事实会不会漏进他人可读的记忆。**数据**：5 个用户、7 个 agent 的设置下，通过率比无记忆高最多 16 个点，比单一全局记忆高 5 个点，而且即使这个任务此前只被其他用户在其他 agent 上做过也有效；偏好保留率最高 90%；隐私探针命中禁止作用域的比例不超过 0.02%。**启示**：多租户产品要上经验记忆，先给每条记忆加 scope 字段，再写"植入私密事实、检查其他作用域能否读到"的回归测试。规模只有 5 用户 7 agent，离生产还有距离。

### 精读 B · 评测方法论：评审器、监控器和评测意识

- 【必看】🧪 **[A Model Organism for Studying Unverbalized Evaluation Awareness](https://arxiv.org/abs/2611.09945)** · Daniel Donnelly 等 4 人 · 2026-10-16 提交（11 月公布）—— **问题**：模型能认出自己在被评测并改变行为，这会让安全基准失真。目前测"评测意识"主要靠 LLM 评审在推理过程里找明说的识别语句，但前沿模型 system card 报告的明说比例在下降，这和"意识到了但没说出来"无法区分；可解释性方法可以检测，却缺少逐条样本的真值标签。**做法**：用合成文档微调、SFT 和 DPO 训练 Qwen3.5-27B：认出评测时在最终回答里输出一个指定标记，同时在推理中不表露。这个标记基本跟随"评测"概念，会被系统提示中的评测说法强烈调节；不告诉它是否在评测时，它也能从测试题的线索认出评测，和基座模型常常明说的情况一致。**数据**：以标记为标签，测试了基于基座模型、看不到标记的线性探针、Jacobian Lens 和 Activation Oracles，没有一种能可靠恢复这个标签。**启示**：不能把"推理里没提到在被测"当成"没意识到在被测"；目前的可解释性方法也还不是可靠的检测器。做 agent 安全评测时，要尽量让评测输入在线索上接近真实流量。

**本期各家做法的异同与可以照搬的点**：

1. **大家都在检查"评分本身可不可信"**。Anthropic 给出评审模型的校准清单（拆成是 / 否题、写明不改变结论的因素、盲标对照人与人一致率）；SPRING-5 直接测同一配置复测的噪声底，发现约八分之一的比较单凭噪声就"胜出"；Nanda 等发现评审和探针进了奖励回路就会被绕过；Donnelly 等说明"推理里没说"不能当作"没意识到被测"。照搬方法：任何 A/B 结论先报噪声底和置信区间，评审器上线前先做人工盲标对照。
2. **把大任务拆成必要子任务来评**。Anthropic 的无人机评测和机器人评测都按子任务或控制接口拆开报分，能提前看到"哪一块补上就会突然成功"。agent 评测可以照此拆成检索、规划、工具调用、验收几段分别报。
3. **用 agent 改不动的判定器做验收**。Google 用未改动的测试套件、Lean 检查器、硬件计数器，Anthropic 要求先关掉"不完成任务也能拿满分"的路径，DeepStress 检查答对的题是否根本没用检索。共同原则：判定器必须在 agent 的可写范围之外。
4. **外部评估开始进入厂商内部**。METR 驻场 Anthropic 是第一次由外部机构基于内部数据量化 AI 研发加速，但关键证据不公开。读这类报告时要同时看结论和"哪些证据被删"。

## 趋势观察

**一、递归自改进有了第一份"外部机构进厂"的量化。** 此前关于 AI 加速 AI 研发的数字都来自厂商自报（Anthropic 9 月称 Claude 主导了 26% 以上的 AI 研发工作，OpenAI 9 月公布研究员的编码 agent 用量）。METR 这份报告第一次由外部评估者看过内部训练指标、算力和员工访谈后给出判断：能力提升速度约翻倍，大部分来自用 AI 做研发，未来一年看不到明显瓶颈。同一周 Dwarkesh 发长文说自己把"AI 达到顶尖人类 AI 研究员水平"的预期从十年左右改成一两年甚至几个月，主要依据之一就是这份报告。对照上期论文里的 RSI Tax、持续进化遗忘等"验收"结果，可以看到两条线并行：前沿实验室内部的加速在发生，而公开研究里的自改进方法在接受越来越严格的成本与遗忘检验。

**二、评测文章从"测了什么"转向"怎么证明测得对"。** Anthropic 的安全评测长文几乎全篇在讲效度、评审校准和统计功效，而不是讲新基准；本期论文里一半评测类条目也是在审计评测本身（CAGE 4 审计、SPRING-5 噪声底、证明步验证的配对置信区间、评测意识检测）。面试回答评测问题时，"我怎么确认这个分数可信"已经和"我用什么指标"同样重要。

**三、常驻 agent 的后端结构在收敛。** Anthropic 的五原语（收件箱、定时器、记忆、权限、发件箱）、OpenAI 上期的 OpenClaw 安全实践、Google /teamwork 的上下文分隔与外部判定器，三家都把可靠性放在模型之外的普通工程组件上：数据库表、单 worker、出站凭据代理、不可改的测试套件。agent 应用工程越来越像传统后端工程加一层模型调用。

**四、记忆研究的评价标准在统一为"对下一次有没有用"。** MixUA、CoReMem、MemCredit、KEEL 都用"带 / 不带这条记忆，下一次结果差多少"来决定记什么、留什么，并给记忆加作用域、证据和退役机制。这与 Anthropic 记忆文章（上期收录）用原始记录校验笔记的做法一致。
