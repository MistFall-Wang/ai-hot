## 本周新文章（2026-08-19 ~ 08-26）

### OpenAI

- **[Codex as a platform: build on the open agent harness](https://developers.openai.com/blog/codex-as-a-platform)** · 8 月 19 日
  本周最重要的一篇。论点：可复用的不是模型而是 **agent loop（harness）**——理解任务、维护上下文、调工具、处理失败、请求审批的那套执行系统。硬数据：ARC-AGI-3 上仅靠"保留推理 + 上下文压缩"两个 harness 设置，GPT-5.6 Sol 从 13.3% 升到 38.3%，输出 token 降 6 倍。文章教你用开源 Codex harness + app-server 协议（创建线程、启动轮次、接收事件、处理审批）把 agent 嵌进自己的产品，并给出三档集成方式：`codex exec`（脚本/CI）、Codex SDK（应用代码）、app-server（agent 是产品本体）。启示：面试里聊 agent 架构，harness 分层是 2026 年的标准词汇。

- **[Automating repetitive work at OpenAI with Codex](https://developers.openai.com/blog/automating-repetitive-work-at-openai-with-codex)** · 8 月 25 日
  OpenAI 内部实践：用 Runme + WebMCP 把重复出现的工程任务（发布流程、例行排查）固化成**可评审、可复用**的工作流，而不是每次让 agent 从零发挥。核心思想是"把一次成功的 agent 运行沉淀为资产"。

- **[Scaling cyber defenders with Daybreak](https://developers.openai.com/blog/scaling-cyber-defenders-with-daybreak)** · 8 月 21 日
  安全运营场景的完整 agent 工作流：用 ChatGPT / Codex Security / 开源工具做威胁调查 → 漏洞验证 → 从发现推进到经过评审的修复。配合 Daybreak Blue/Red 分级访问体系读。

### Google

- **[Agent Plugins package your skills, tools, and more](https://developers.googleblog.com/en/agent-plugins-package-your-skills-tools-and-more/)** · 8 月 6 日（DeepMind）
  行业标准信号：Agent Plugins 1.0.0 是把 Agent Skills + MCP 服务器打包成统一目录规范的**厂商中立标准**，核心维护者含 Amazon、Cursor、Microsoft、OpenAI、Vercel，Google 刚加入。设计哲学值得学："一个插件就是一个目录"，manifest 只有两行，组件独立失败互不拖累。解决的痛点：同一套 skill + MCP 要适配每个客户端就得 fork 一份包装，最后各自漂移。

1. **[How we contain Claude across products](https://www.anthropic.com/engineering/how-we-contain-claude)** · 5 月底 · 当前置顶

## 趋势观察

2024 年的《Building Effective Agents》讲**怎么搭**；2026 年这批文章讲**怎么在生产环境里管住它**。三条主线：① harness 成为竞争单元——三家都在证明同一模型下 harness 好坏能差出 3 倍分数，OpenAI 干脆把 harness 开放当平台；② 围堵取代监督——93% 批准率宣判了逐条弹窗的死刑，方向全面转向沙箱 + 确定性边界；③ 评测工程独立成学科，连"模型意识到被评测"这种失效模式都有专文。另有 Agent Plugins 规范落地——skills + MCP 的打包层被全行业标准化，interop 之争进入下半场。
