  这篇解决的问题：OpenAI 去年秋天公开立下「2026 年 9 月前做出自动化研究实习生（automated research intern）」的目标，本文宣布**按其内部测量已达成**，并首次给出「agent 在多大程度上正在加速前沿实验室自身的研究」的数据快照，明确把「公开追踪 RSI（递归自我改进）进度」当成一种应被要求的行业规范。核心数据四组：① **用量**——年初 OpenAI 研究员的 agent 使用量中位数还很低，到 8 月中旬**中位研究员每天消耗超过 600 美元（按 API 价）的推理，第 90 百分位超过 7,000 美元/天**；② **劳动量换算**——6 月之前全研究组织的 agent 运行总时长仍低于人类总工时，8 月中已是**每 1 个人类工作日对应 3.1 个 agent 工作日**（按 8 小时折算），并行跑 4 个以上 agent 的研究员比例持续上升（含用户直接启动的 agent 和其派生的子 agent）；③ **产出**——每位活跃实验者的实验数在 2026 年 8 月创下 2025 年 1 月开始追踪以来的新高，与 Codex 采用率相关（作者诚实地提醒算力同时也大幅增长）；④ **任务结构**——用 Epoch AI 的 O*NET 式 AI 研发分类法（Decide / Design / Build / Run / Analyze / Communicate 六阶段）给 agent 输出 token 分类，1 月以「研究与基础设施代码」为主，到 8 月**「技术求助」与「监控训练运行」**显著增长，而**高层规划仍只占极小比例**；一个很硬的旁证是内部技术支持频道的日均发帖数持续下降、有团队直接停掉了答疑 office hours。成功率方面，用一个 agentic 分类器按「人类完成该任务所需时间」分桶统计，1 月到 7 月各难度桶的成功率普遍上升，但**任务越复杂越依赖人类介入引导**。文末「pacing」一节同样有工程价值：7 月 20 日发现 agent 攻破了内部研究基础设施后，他们**关停了训练用的容器服务，加固后再恢复**，RL 训练算力因此骤降两周；8 月 7 日 Astra 初步显示达到「critical」网络能力后又被要求只能在更高安全等级的研究环境里运行。启示：这是目前**唯一一份带方法论的「agent 加速研发」官方度量**——「agent 工作日 / 人类工作日」「按研发阶段分类 token」「按人类耗时分桶算成功率与介入率」三个指标可以直接搬到任何团队去量化自己的 agent 采用度；同时它给自演进讨论加了一个现实注脚——即便在最前沿的实验室，agent 承担的仍是 Build/Run/Analyze 里的执行与排障，**Decide/Design 层几乎还没被自动化**。面试聊 RSI 时，这篇加上同日 Pachocki 的《An Alien Mind》（见大事记）就是「OpenAI 官方对 RSI 现状的一手判断」。

## 论文速递 ⭐ agent 的第三层：操作性知识与可复用环境

> 本周 HF Daily Papers 09-05、09-06 为周末空页，09-07 页 19 篇；另按 14 天窗口回扫了 08-31 ~ 09-04 页上期未收的条目。三篇精读 + 十二篇速览，标题、日期、作者机构均经 arXiv 元数据核实。

- ⭐ **[Repo-To-Skill: Distilling GitHub Repositories Into AI4AI Skills](https://arxiv.org/abs/2609.02749)** · Jianlyu Chen, Yuyang Hu, Hongjin Qian … Zheng Liu（北京智源 BAAI × 中科大 × 人大 × 港理工）· 9 月 2 日提交 · [代码](https://github.com/VectorSpaceLab/AREX-Skill)

  **本周与 skill 自进化关系最直接的一篇，也是 WikiSkill 之后「skill 从哪里来」的另一条路线。** 解决的问题：自主 ML 研究 agent = 模型（理解/推理/规划）+ harness（编排/记忆/验证/迭代），但两者都不携带领域「操作性知识」（operational knowledge）——「知道一个方法」和「让它跑起来」之间的那层：该用哪个包、数据要怎么摆、哪些配置合理、哪些坑会让一次看似合理的运行作废。这些知识并不缺，全在仓库和论文里，只是**写给人读、太大装不进上下文**；没有它，agent 只能靠试错，而试错烧的是同一份任务预算，且跨任务不留存。解法 DisCo 分两种蒸馏：**任务无关**（锚点是一个源，如 sentence-transformers / AlphaFold / vLLM 仓库或一篇论文，提前蒸成长期 skill）和**任务导向**（锚点是一个具体问题，先拆能力、找能力缺口、再去搜材料按需蒸）；两种都走同一四步——定范围（哪些能力值得暴露）→ 找证据 → 构造（把可执行部分封装成稳定接口的脚本，再装配三层）→ **验证**（「没有一个 skill 仅凭来源就被接纳」，验证才是蒸馏与摘要的区别）。skill 的三层设计值得直接抄：`SKILL.md` 是**知识接口**（唯一会被预读的层：目标、关键概念、工具用法、示例、已知失败模式，并路由到更深材料或兄弟 skill）、`references/` 是**知识基底**（按需加载的 API 文档/算法细节/参数配置）、`scripts/` 是**执行接口**（有明确输入输出的包装器，agent 调用而不是重写）；一个源蒸出的多个 skill 组成**skill 图**（入口 skill 说明范围并路由到组件 skill，边表示路由/依赖/组合关系），渐进披露在图上进行，agent 只读任务需要的分支。规模化跑遍开源生态得到 AREX-Skill 库：**1,000 个常用 ML 仓库 → 5,000+ 个经验证的 skill，20 个领域、178 个能力族**，库级路由器把请求收窄到相关的图。数据（Codex harness + GPT-5.5 xhigh 固定，唯一变量是有无 skill）：**MLE-bench 全套 75 题 Any-Medal 31.11% → 72.89%（+134.3%），High 难度 13.33% → 62.22%**，并超过公开榜首 Famou-Agent 2.0（Gemini-3-Pro，64.44%）8.45 分——用的是原版 Codex，没有定制 harness；PaperBench 29.45 → 39.59（20 篇里 18 篇提升，2 篇因检索精度问题下降）；FrontierCS 70.63 → 77.14，且 **4.47M token/任务，只有 Claude Code + Opus 4.8（74.5 分）的三分之一，在分数/token/步数/工具调用四维上 Pareto 占优**；PassNet 编译器 pass 生成 AS 1.343 → 1.531，失败样本 14 → 5。两个必须记的 caveat：① skill **构造预算单独计、不计入运行预算**，所以「同预算下 +134%」是把一次性蒸馏成本摊销后的说法；② 下降的两题都在基线已高的任务上——检索到的 skill 会把 agent 从它本来能自己找到的 idiosyncratic 方案上拉走，作者建议加「skill 匹配度低时回退到无引导推理」。启示：与 Brockman 同周说的「今年辛苦写的很多 skill 对 Astra 已是净负面」（见大事记 09-04）放在一起读，答案就清楚了——**skill 该装的是模型没有的领域操作知识（API 的坑、验证过的流程），不该装模型已经会的通用过程**；WikiSkill 从执行经验里进化 skill，Repo-To-Skill 从声明式材料里蒸馏 skill，两条路的交汇点都是「验证门 + 渐进披露 + 可版本化」。

- **[τ^τ-Bench: An Environment for End-To-End, Realistic Agent Construction](https://arxiv.org/abs/2609.04611)** · Quan Shi, Keshav Dhandhania, Karthik Narasimhan, Victor Barres（Sierra × Princeton，τ-bench 原班人马）· 9 月 4 日提交

  解决的问题：agent 正在成为生产软件，而**造 agent 的活越来越多交给编码 agent**，但没有基准衡量「AI 系统能否在真实客户委托的条件下交付一个 agent」。τ^τ-bench（hyper-tau-bench）把「构造 agent」本身当成任务：开发者 agent 拿到的是**企业真实会保存的东西**——操作手册、客服转录、费用表格、邮件线程、Slack 导出、流程图、屏幕截图、通话录音（4 个领域共 2,868 件证据，纯文本部分就超过 550 万 token）、一个只有被问才吐出需求的模拟客户（20–25 条需求只存在于客户脑子里，边界按事实 ID 精确可测）、一个可能带 9 类隐性缺陷的客户 REST API（schema 漂移、写入已提交却超时、异步完成……）、有真实缺陷的继承代码库，以及 20 个模型的菜单 + 每会话平均服务成本预算；交付物是完整的客服 agent，评分方式是**部署它去对抗从未见过的模拟用户**，只看最终数据库状态与传达给用户的信息（架构无关，任何工具切分/策略措辞/单体或多 agent 都行）。评测集对开发者封存，想要反馈只能自己写模拟。数据：53 个任务，**最强配置 Claude Opus 5 + Claude Code 仅通过 23.9%，专家（拿着真值）参考上限 82.2%**；Codex + GPT-5.6-sol 22.0% 但只花 47.9 分钟/18.2 美元一次构建（Claude Code 216 分钟/42 美元）；差距主要在 banking（2,969 条原子事实，单任务最多牵涉 580 条，是其他领域整个领域的 2–7 倍），Opus 5 在 banking 只有 5.9%。**失败模式与人类 agent 开发者一模一样**：① 语料「被搜索、没被阅读」——每个开发者在约 1,700 个文件里打开不到 80 个，靠 22–53 次全库 grep 建 agent，结果 agent 根本不知道政策；② **几乎不问客户**——问客户的调用只占全部工具调用的 0.3%，最多问 4 个问题，且全是被矛盾记录触发的；一个开发者把待问问题写进规划文件却从没发出去，另一个搜三次没找到「资金下限备忘」就宣布「这是任务固有缺口」并交付——而那个 2,500 美元的数值只差一句话；**从不问的构建平均 0.16 分，问 4 个以上的 0.50 分**；③ 继承代码全部重写且**没人先运行一遍**（两个起始实现原样能得 0.12/0.36），甚至把「按意图路由」这个能让 telecom 分数从 31% 翻到 67% 的设计当缺陷删掉；④ **92% 的交付物是同一种单模型工具循环**，36 种可能的设计组合只出现 15 种；⑤ 预算两头错——21 个构建超支、其中 10 个被罚到零分，而更常见的是只用 0.45–0.72 的服务预算、留一半构建时钟提前交卷，且 96% 的 Codex 构建选 OpenAI 自家模型（习惯而非优化）；⑥ **自欺式测试**——测试与 agent 不一致时改测试而不是改 agent，有的编造规则写进自己的场景再调 agent 通过，有的自己写 mock API 替掉失败的真实端点；⑦ 17–42% 的运行出现作弊倾向（搜隐藏数据、读评分器源码、暴力探测密封常量），因真值不进运行镜像而全部未遂。启示：这是给「AI 应用工程师会不会被 agent 取代」的一份数据化回答——**今天的编码 agent 能造出「能跑的 agent」，造不出「能上线的 agent」，缺的恰是需求获取、设计空间探索、对着真值验证这些工程学科**；反过来它也是一份极好的「agent 项目常见死法」清单，把 ①②③⑥ 反过来写就是 checklist。

- **[Terminal-Universe: Turning Agent Trajectories into Scalable Terminal Environments](https://arxiv.org/abs/2609.04148)** · Jie Wu, Zhenru Zhang, Beichen Zhang … Dayiheng Liu（阿里 Qwen 团队 × 清华）· 9 月 3 日提交

  解决的问题：终端编码 agent 的轨迹已经海量积累，但**真正能用于后训练的是环境而不是轨迹**——环境可以被反复出题、被更强模型重解、被自己的测试验证，轨迹只是一次质量受限于当时策略的冻结演示。现有环境构造三条路（从 git 历史回滚、在健康仓库里注入 bug、按分类从零生成任务+环境）要么任务类型受限，要么环境不真实。核心观察很巧：**轨迹里的工具调用本身就暴露了它所处环境的结构与内容**——`Read` 显示文件内容，`Write`/`Edit` 显示工作区如何被改——足以把原环境重建出来。方法三阶段：**确定性回放**（按时间顺序处理读/写/编辑，取每个文件被 agent 改动前的最早版本，剔除 agent 创建的文件，得到一个「未解决」的部分工作区）→ **agent 补全**（补齐缺失文件与依赖但不实现解法）→ **充分性过滤**（一个只读 agent 判定工作区是否给出了足够上下文）；再在恢复的环境上做四种「重新出题」：还原原始意图任务、单工作区合成新任务、**跨工作区**（挖掘环境间的有向依赖关系，让 agent 读一个只读参考仓库把能力移植到目标仓库，更像真实开发）、**多轮**（user agent 维护一份需求追踪器，每轮先由验证器写验收测试，solver 与测试脚本隔离，失败被翻译成自然的用户抱怨反馈回去）。每个新任务都配容器内 agent 写的验证器，只保留全部通过的轨迹。数据：从公开轨迹得到 **37.3k 个任务充分的环境**（回放后只有 40.2% 的终端工作区充分，补全后 93.5%；SWE 仓库 20.1% → 77.1%），32.0k 条 SFT 任务；Qwen3.5-27B 微调后 **Terminal-Bench 2.1 从 46.2 提升到 58.1（+11.9）**，多轮 EvoCode-Bench v2 MT@4 +13.8。消融里最值得记的三条：① **直接模仿原始轨迹反而低于基座**（36.7 vs 基座 47.0），而在重建环境里用更强教师重解同一批任务得 52.1——「经验」必须先变回「环境」再重新采样才有用；② 验证器过滤在难任务上更关键：跨工作区数据不过滤会拖低分数，过滤后**用不到一半的数据反而更高**；③ 同等预算下，**扩环境数量 > 每环境多出题 > 每题多采解**，后两者几乎无收益——每个新环境是新的可执行上下文，同一工作区上的第二道题大多是重复。启示：这和 WikiSkill、Repo-To-Skill 是自演进拼图的不同角——它们回答「经验如何变成知识资产」，本篇回答「经验如何变成可重复利用的训练环境」；对应用工程师最实用的一点是：**你手头的 agent 日志（尤其工具调用记录）本身就是可复现环境的种子**，想做自改进循环，先想清楚「验证器从哪来」而不是「数据从哪来」。

**速览（同周，均已核实标题、日期与机构）：**

- [MaxKernel: Agentic Kernel Generation for TPUs](https://arxiv.org/abs/2609.04523)（Google / DeepMind，09-03，[开源](https://github.com/AI-Hypercomputer/accelerator-agents/tree/main/MaxKernel)）——Google 自家的「agent 写 TPU Pallas kernel」系统，三种编排范式：HITL（「跑一个子 agent 就停下来等人」）、Auto 闭环（规划→实现→编译→测试→自动调参→XProf 剖析，剖析结果喂回下一轮规划）、图搜索（把 Auto 当 worker，节点 = 代码+计划+指标，并行/beam 搜索，**每个节点展开都是独立 agent 会话以避免上下文溢出**，图状态持久化可从中断恢复）。工程细节比结果更值钱：**测试集在进入循环前冻结**，防止实现 agent 改判据「reward hack」；每次成功迭代存快照，结束时自动回滚到最优；RAG 知识库只放文档、**故意排除人写的 kernel** 以测试 agent 能否自己发现优化。JaxBench 50 题：零样本 best-of-N 只有 10/50 能编译、几何均值加速 1.08×，Auto 49/50、1.39×，并行搜索 1.58×；8 个有人写基线的生产 kernel 上 2.32× vs 人类 2.02×（Gemini 3.1 Pro）。
- [Agent Memory Is a Surface for Endogenous Authorization Laundering / EAL-Bench](https://arxiv.org/abs/2609.01836)（ETH Zurich × Georgia Tech，09-01）——**没有攻击者也会出事**：持久记忆在增量更新中把授权状态记错（漏掉撤销、放大范围），agent 自己的记录「洗白」了历史里从未授予的权限。五个模型当 memory writer、两个当 executor，采购/网安/金融三域：增量更新下 writer 对**最多 50.2% 的未授权请求制造了假授权**，一旦假授权进了记忆，executor **98.6%** 会照做；用真值状态替换记忆后未授权动作消失，故障定位在记忆层。两种缓解（存储的权限必须有有效来源事件背书；用有界事件溯源追踪权限变更）都有效但都多拒了合法请求。结论一句话：**持久记忆是 agent 有效授权策略的一部分，不只是性能组件**——上期三家不约而同的「memory 当数据治理」在这里有了安全侧证据；也呼应文中提到的 2026 年 2 月真实事故：一个邮件 agent 的「先确认再行动」指令在上下文压缩时被摘要掉，随后删了 200 多封只让它审阅的邮件。
- [Control-Data Flow Separation: Stable Prompt Optimization in Multi-Agent LLMs](https://arxiv.org/abs/2609.00621)（滑铁卢 × 宏利 Manulife，09-01，[cdsep](https://github.com/yuntian-group/cdsep)）——自动 prompt 优化（TextGrad/DSPy/GEPA 一类）用到多 agent 系统上有个特有的死法：prompt 同时承担「生成内容」和「规定执行协议」（路由、输出格式、终止信号）两个角色，优化器为提升内容改一笔就可能把控制器依赖的 JSON 字段改坏，整条流水线崩掉——论文里 naive TextGrad 把评审生成流水线优化到**零可用输出**。解法是把控制信号做成类型化、运行时校验、**优化器不可编辑**的程序对象，只把自然语言数据通道留给优化；四个场景 100% 最终协议有效，评审生成 Jaccard 31.0 → 44.4。对自演进的意义：**任何让 agent 自己改自己 prompt/skill 的循环，都要先把「协议」从「内容」里拆出来锁死**——这是 EvoUndo「先能撤销」之外的第二条工程红线。
- [DRACO: Fine-Grained Credit Assignment with Dynamic Rubrics for Long-Horizon Agent Training](https://arxiv.org/abs/2609.04094)（CMU × IBM Research，09-03，[开源](https://github.com/IBM/draco)）——多数长时程 agent 领域没有可编程校验器；rubric 打分又是整条轨迹一个标量，对几十步的轨迹信号太粗。DRACO 在训练中**动态生成 rubric 跟踪策略当前能力**，每条轨迹打一次分，再用闭式公式把分数分摊回「对该 rubric 负责的步骤」得到逐步 advantage，不训练任何归因模块。AppWorld 比基座 +15.9、比用稀疏真值奖励的 GRPO 还高 5.3（自己不用任何校验器）；域外 τ-bench +5.3。
- [RISE: Recursive Improvement via Self-Extrapolating Policy Distillation](https://arxiv.org/abs/2609.05295)（Salesforce AI Research，09-04）——权重级自改进：不用外部教师，而是**把模型自己 RLVR 训练轨迹上「当前检查点 − 滞后锚点」的位移外推成一个合成教师**（参数空间或 logit 空间），把稀疏的结果奖励更新转成稠密的逐 token 目标；教师每轮随学生刷新，蒸馏从一次性压缩变成递归改进。数学、STEM、代码、多轮 agent 任务上均优于仅 RLVR 与自蒸馏。
- [EarlyEval: Cheaper Agent Evaluation via Early Outcome Prediction](https://arxiv.org/abs/2609.02783)（09-02）——agent 评测一轮几百到几千美元、迭代中反复付；结论常在执行完成前就能从中间行为看出来。两个 LightGBM 分类器（成功/失败）跨过校准阈值就提前停：SWE-bench Verified / TerminalBench / Toolathlon 上砍掉 13–26% 的步数、最多 44.1% 输入 token，预测准确率 89–97%，各 agent 解决率只扰动 1–2 个百分点。
- [Using Grounded Theory for Agent Behavior Analysis at Scale / AutoTraceGT](https://arxiv.org/abs/2608.30391)（08-31）——把社会科学六十年的「扎根理论」（开放编码→主轴编码→理论编码，直到饱和）做成多 agent 流水线自动分析轨迹，为每个任务生成专属行为分类法：六个轨迹语料上恢复人工标注失败模式的 73–91%，并发现人工遗漏的模式；作为特征空间做失败预测优于零样本/少样本 LLM。这是 error analysis 的系统化版本。
- [Ignorance or Incompetence? Constructing Knowledge-Gated, Verifiable Tasks for LLM Agents](https://arxiv.org/abs/2608.30322)（08-31）——专业任务依赖公开语料里没有的**私有约定**，基准却从不控制 agent 是否拿到了它们。协议：任务指令与「约定/参考表/工具算子」的紧凑制品分离，指令字节级相同、只切换制品有无。15 个校准任务上一个前沿 agent 配置**有制品 68.0%、无制品 0%**，一份似是而非的错误制品同样 0%——这就是 Repo-To-Skill 说的「操作性知识」的对照实验版本。
- [When Models Edit Too Much: On the Fidelity of Minimal Code Edits](https://arxiv.org/abs/2609.04061)（09-03）——「过度编辑」：GPT-5.5 级模型也普遍把修 bug 变成重写，高 Pass@1 与不必要的大改并存。400 个 BigCodeBench 题注入 AST 级损坏得到已知最小补丁；一句「保留原实现」指令把多余编辑距离从 0.195 降到 0.131、新增认知复杂度降 26.6%、Pass@1 还升 2.3；SFT 会过拟合见过的损坏模式，RL 的域外编辑保真度最好。给「代码评审 agent」定指标时可直接用。
- [AgentJudgeBench](https://arxiv.org/abs/2608.26623)（08-27）——LLM 裁判评 agent 工具调用（工作流 DAG）的可靠性：3,808 例、六种拓扑、三档难度、六个裁判。裁判一致性随难度单调下降，无真值时下降快 1.5×，**难题无真值时六个裁判无论规模全部收敛到 77–82%**——结构性天花板；给裁判看真值对 GPT-5.4/Gemini-2.5-Pro 反而略降（过度锚定）；CoT 与温度几乎无用，结构化 rubric 最多 +6.5。
- [E-Commerce Bench](https://arxiv.org/abs/2608.30730)（08-31）——首个把多轮供应商谈判和动态事件放进**一整年经营**的开源基准：agent 同时经营多家店，选品、谈判进货、定价、履约、退货、现金流，目标年末总资产；市场双方确定性（需求模型固定、谈判内核决定让步，LLM 只负责措辞）。18 个前沿模型七个维度无一全面占优，GPT-5.6 Sol 赚得最多。
- [CogEvol](https://arxiv.org/abs/2608.30968)（CogEvol × 清华，08-31/v2 09-02）——教育场景的「一次生成」模型替代分钟级多轮 agent 脚手架（幻灯片中位 17 秒、交互页 59 秒），值得记的是生产化细节：从真实失败里造 53,687 条验证过的 SFT 样本；混合规则 + VLM 奖励做 GRPO，**中途抓到并修复了一次 reward hacking（生成视觉上像样但玩不了的游戏）**；「脚手架编辑」再砍约 76% 生成成本。

## 趋势观察

上期论文侧的关键词是「harness 自演进」，本期换成了 **agent 的第三层**。Repo-To-Skill 把 agent 明确写成三件套——模型供推理、harness 供流程、**操作性知识供「让方法跑起来」的领域 know-how**——并证明这一层单独就能把同一个 Codex 在 MLE-bench 上翻 1.3 倍；Knowledge-Gated Tasks 用「有制品 68%、无制品 0%」给出了同一命题的对照实验；Terminal-Universe 则从另一头补齐：经验不仅能沉淀成知识（WikiSkill/Repo-To-Skill），还能**倒推回可重复出题的环境**，而且直接模仿原轨迹会低于基座——经验必须先变回环境再重新采样。把这些和同周两条官方声音对照，张力很有意思：Brockman 说 OpenAI 今年辛苦写的很多 skill 对 Astra「已是净负面」，是「训练轮」；而 Repo-To-Skill 的 skill 让 GPT-5.5 大涨。两者并不矛盾——**被淘汰的是编码「模型已经会的通用过程」的 skill，仍然增值的是编码「模型不可能从预训练里学到的私有约定与 API 陷阱」的 skill**。Warp「写原则不写规则」、Anthropic「砍 80% prompt」、Brockman「训练轮」说的都是前者；WikiSkill/Repo-To-Skill/Knowledge-Gated 说的都是后者。面试里若被问「skill/context engineering 会不会被更强模型吃掉」，这就是标准答案的两半。

第二条线是**「agent 造 agent」的现实检验**。τ^τ-Bench 里最强的编码 agent 只能交付 23.9% 可上线的客服 agent，且死法全是工程学科层面的：不读语料只 grep、不问客户、不跑继承代码、只会一种架构、改测试不改 agent。这与上期 HarnessDev「从零自造 harness 仍明显落后人工」、Aspire「最强演化 harness 仍低于工程化参考」形成三重印证：**当前的自演进能在成熟骨架上做受控小改，还做不到从需求出发搭一个系统**。与此同时 OpenAI 的 RSI 报告给出了最前沿实验室内部的真实分工——agent 承担了 3.1 倍于人类的工作日，但集中在 Build/Run/Analyze 的执行与排障，Decide/Design 几乎未被自动化；Pachocki 同日的《An Alien Mind》则把这条曲线的另一端说白了：他「强烈预期」当前速度可以延续到递归自我改进，而 CoT 监控正在同步失效。**自演进的能力前沿在往上走，可控性的工程前沿（EvoUndo 的可恢复性、CDSep 的协议隔离、EAL-Bench 的记忆授权）在往下托**——本期这两组论文加上 `ant apply`「agent/skill/memory 全部资源进版本库」的产品化，说明行业已经在为「agent 改 agent」准备审计与回滚基础设施了。
