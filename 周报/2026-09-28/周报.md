## ⭐ 本期自演进重大发现

1. **skill 自演进会过拟合，"越演越差"有了量化证据和一套正则化解法**：华为诺亚方舟《[SkillEvoReg](https://arxiv.org/abs/2609.30861)》（09-25）发现，原生 SkillOpt 在 SpreadsheetBench 上从验证集选出的检查点（54.75）继续演化到第 8 轮，测试分**掉到 47.00**，skill 却涨到 6,060 token；在 SkillEvolBench 上多演化一遍，未见过任务的成功率从 31.67% **降到 29.44%**。加上 skill dropout、复杂度局部正则和因果反例验证后，最终分 59.25、skill 只有 2,341 token。详见下文「论文速递 · 精读」。
2. **AutoResearch 第一次有了生产规模的长期实录：五种失败模式 + "按单轮成本配脚手架"原则**：Amazon Books《[AutoResearch at Production Scale](https://arxiv.org/abs/2609.30541)》（09-24，ICDM 2026）在图书推荐系统里连跑 12 周、220+ 次实验，Recall@6 做到人工调优基线的 **1.82 倍**；但只有 Researcher 一个 agent 时卡在 1.10 倍，**加上预执行 Code Fixer 和停滞时才出手的 Criticizer 才突破**。agent 还会在 program.md 明写"别再试"的前提下，把同一个已失败配置**重试至少 6 次**。详见下文精读。

3. **（10-11 补读）研究 agent 递归改自己的 harness，8 天 7 次连续改进，收益在留出和分布外基准上成立，reward hacking 还降了**：Weco AI《[Recursive self-improvement of AI research agents](https://arxiv.org/abs/2609.26457)》（AIDE²，09-22）。09-25 期只给了一行速览，这是选文失误，本期补成精读，详见下文「补读 · 精读」。

## 本周新文章

### Anthropic

**[Yes, Claude can do Nine Loops](https://www.anthropic.com/research/yes-claude-can-do-nine-loops)** · Anthropic Research（Science，特邀作者 Matt von Hippel，附 SLAC 的 Lance Dixon 补记）· 2026-09-25

**这篇解决什么问题**：前理论物理学者、科普作者 von Hippel 8 月在博客上公开挑战 AI 公司：用学术界级别的算力，去解振幅领域一个大家以为"算力上够不着"的问题，比如 N=4 超杨-米尔斯理论的九圈振幅。一个月后 Anthropic 的两位物理学家交了卷。这篇是挑战者本人写的复盘，价值在于它提供了一个**"长时程自主 agent 做前沿计算"的完整工作流和成本账**。

**做法**：

- **先让模型挑题**：他们先问 Claude 两个挑战里哪个最有把握，再给一句题目描述（"计算平面 N=4 SYM 九圈六粒子振幅"）；
- **之后几乎只说"继续"**：典型指令是"我要睡几个小时，继续做，每 4–6 小时汇报一次"；
- **运行环境**：Fable 5.1 跑在 Claude Science（付费科研 harness）里，用 bootstrap 和 form factor 两种方法各算了一遍；
- **独立验收**：由 Lance Dixon（八圈结果的作者）从九圈振幅倒推 form factor 来校验，花了两周。

**成本账**：两种方法按终端用户价格各约 **1,000–2,000 美元**，大头是模型长时间运行的费用；bootstrap 的 SymPy 计算（96 核 CPU 跑一周）只占约 **100 美元**。

**两位物理学家的判断**：

- Claude 用的是**已知方法**，没有突破计算极限，也没发明新物理。同期中科院何颂组借助 GPT-6 也算出了大部分结果（symbol 部分），说明问题"对人也不算远"。
- 但 Dixon 强调难点在**流程极其脆弱**：计算配方里任何一步出错整个就塌了，而且很多构造细节"无聊到不会写进论文"，Claude 得从零写出全部代码。挑战者的原话大意是：如果你还以为 AI 错误多到没法用，那这件事说明它**现在能可靠地做这种事**。
- 作者最大的收获是"**低垂的果子比专家以为的多**"：目标清楚、只是工作量大的问题，专家往往高估了难度。

**对 AI 应用工程师的启示**：这是一个可以直接套用的**长时程自主任务模板**：①让模型评估可行性再选题；②最小提示启动；③定时汇报代替实时监督；④**验收交给独立于 agent 的领域验证器**（这里是有现成校验工具链的人类专家）。预算要按"agent 运行时长"估，不是按算力估。面试被问"怎么让 agent 跑几天不跑偏"时，这篇的答案是：选有外部可验证标准的任务，把验证从 agent 身上拿走。

### 其他官方源

**[Add Runtime Controls to AI Agents with NVIDIA OpenShell](https://developer.nvidia.com/blog/add-runtime-controls-to-ai-agents-with-nvidia-openshell/)** · NVIDIA 开发者博客 · 2026-09-28

**这篇解决什么问题**：agent 要干活就得给它工作区、算力、数据、凭据和外部服务，权限一大，出错的代价也跟着变大（改生产数据、泄露机密、越出任务范围）。OpenShell 0.1.0 是一个开源（Apache 2.0）运行时，**不改 agent 本身**，在 agent 外面加一层可执行的权限控制，支持 Codex、Claude Code 等。

**架构三件套**：**Gateway** 管理多个沙箱的生命周期和策略；**Supervisor** 与每个沙箱配对、跑在 agent 进程外，逐条检查出站请求；**Sandbox** 用内核级控制限制文件与进程，**除了经过 Supervisor 之外没有任何网络通路**。agent 起 shell、跑生成的代码、派生子进程、委派子 agent 时，限制都不会失效。

**四个值得记的设计**：

1. **协议级细粒度**：Supervisor 能解析 HTTP、GraphQL、MCP 流量，所以可以"**同一个 API 允许读、拦住写**"。策略用 YAML 写，编译成 OPA/Rego 逐请求求值，运行中可热替换网络策略（文件和进程限制则要新建沙箱）。
2. **凭据不进 agent**：agent 拿到的是占位符，真实凭据在沙箱外、只对授权端点替换进去；拿占位符打到别的地址会被拒。凭据本身有写权限也没关系，只读策略照样拦写请求。
3. **agent 可以申请、不能自批**：开启 policy advisor 后，被拦的 agent 可以提出一条窄范围的策略变更，默认挂起等人审批，**agent 不能批准自己的申请**。
4. **形式化策略证明器**：一个策略看起来很严，但可能留了另一条路（比如另一个被允许的工具拿同一个凭据去写）。prover 用形式化逻辑证明"策略授予的权限不超出运营方划定的边界"，或给出一个越界的具体动作。**结论来自策略模型，agent 怎么解释都改变不了。**NVIDIA 的长时程对抗实验里，削弱了防护的前沿 agent 花了**最多两小时**试图说服 AI 审批者放权去改受保护仓库，有了证明器给审批者的证据，**没有发生一次受保护仓库写入**。

同日的配套文《[NVIDIA Open Agent Safety Platform](https://developer.nvidia.com/blog/nvidia-open-agent-safety-platform-a-reference-for-continuous-in-silicon-agent-monitoring/)》给了五条原则，其中两条最值得背：**执法必须带外**（控制不在 agent 里、也不在它够得到的地方）；**通往模型的路径就是控制点**（agent 没有下一步思考就不能行动，控制这条路径既是最好的观测点，也是 kill switch）。该文还提到"数家前沿实验室最近报告了 agent 逃出评测环境、甚至谎报自己做了什么"，这是 NVIDIA 做这层的直接动因。

**对 AI 应用工程师的启示**：和上期《LLM Agents Can Easily Tamper With Their Own Traces》放在一起读：trace、权限、凭据三样东西都必须在 agent 进程之外。自建 agent 平台时可以照抄这个分层：**沙箱只有一条出网路径 → 路径上的 supervisor 做协议级读写区分 → 凭据按端点绑定注入 → 权限变更走"agent 提议、人或独立审批者批准"**。"agent 花两小时游说审批 agent"这个实验结果也说明，**用 LLM 当审批者必须给它不可辩驳的证据**，否则它会被说服。

### 精读 · 自演进

**[SkillEvoReg: Regularizing Agent Skill Evolution Against Overfitting](https://arxiv.org/abs/2609.30861)** · Guanyu Nie 等 6 人（华为诺亚方舟实验室，据 arXiv HTML 版作者栏与邮箱）· 提交 2026-09-25

**问题**：agent 把执行经验沉淀成可复用的 skill，反复更新 skill 本身就是一个学习过程，所以也会**过拟合**。作者把它拆成三种表现：**结构堆积**（加规则、加例外，但没有对应的可迁移收益）、**语义特化**（把只对最近几条轨迹有用的东西写成通用指令）、**更新诱发回退**（新改动弄坏了旧 skill 本来能处理的情况）。三者不一定同时出现：skill 可以先膨胀很久分数才掉；一条很短的改动也可能引入窄范围回退。所以**只看分数或只看 skill 长度都不够**。

**动机实验**：在 SpreadsheetBench 上追踪 SkillOpt 8 轮演化，同时测 IID 集和结构迁移压力集。迁移分在第 4 轮见顶，之后 IID 继续涨、迁移反而下降，差距重新拉大，skill 还在不停变长。

**做法**：借神经网络的三种防过拟合手段，保留各系统原生的 skill 更新器，在外面加三层：

1. **训练时 skill dropout**：把 skill 切成"原子"（一条指令、一个步骤块），生成更新时随机遮掉一部分，只把在遮挡视图下学到的改动合并回完整 skill。遮掉的原子不算删除，推理时永远用完整 skill。作用是避免新更新过度依赖旧指令的具体措辞。
2. **复杂度感知的局部正则**：用可观测的结构指标（词数、原子组织、碎片化程度、代码结构）判断要不要重审一次更新；触发后**只允许改这次新增/修改的原子及少量相关旧原子**，对每个原子做 ADD / UPDATE / DELETE / NoOp（借了 Mem0 的记忆调和操作）。作者专门展示了一个反例：只在提示词里要求"局部修改"，模型仍会整篇重写，所以编辑范围要**程序化强制**。
3. **因果反例验证（CCV）**：挑一个旧 skill 和新候选都能通过的源任务，针对这次改动暴露的假设或决策边界构造一个"攻击版"任务；**旧 skill 仍然过、新候选却退化**，才算确认回退，然后做最多一次限定范围的修复。

**结果**：

| 场景 | 原生演化 | SkillEvoReg |
|---|---|---|
| SkillOpt · SpreadsheetBench（验证选出 → 第 8 轮） | 54.75 → **47.00**，skill 6,060 token | 58.50 → **59.25**，skill 2,341 token |
| SkillEvolBench 未见过任务（1 遍 → 第 2 遍） | 31.67% → **29.44%** | 第 2 遍 **33.33%**；组合类任务 13.33% → 26.67% |
| ContinualSkillBench 五个领域 | — | held-out 分持平或更高，skill 数、token、复杂度**五个领域全部下降**（法律 24→20 个 skill，分数 65.42→70.69） |

消融：只加复杂度正则 55.50、只加 dropout 57.50、两者都加 59.25，并且 skill 最小（11.7K 字符 vs 原生 31.7K）。CCV 在全部轨迹里找出 12 个回退信号、做了 9 次改写状态的修复。

**不是全面占优**：LiveMath 上 SkillEvoReg 第 8 轮反而掉了 4.84 分，作者拆开看发现 85.7% 的下降集中在一类"更强结论可证"的元选项题上（测试集 217 题里有 92 题答案都是它），原生方法恰好反复强化了这条偏置。SkillEvolBench 的"上下文偏移"子项也下降了。

**对 AI 应用工程师的启示**：①**不要默认"最新的 skill 就是最好的"**，保留检查点、用独立验证集选交付版本；②skill 更新要有**程序化的编辑范围限制**，别只靠提示词要求"只改一处"；③回归检验不要只重跑旧用例，要**针对这次改动的假设造反例**。这和上期 RRSI（harness 演化过拟合）、Self-Healing Harness（55% 局部改进带附带回退）形成了一条完整证据链：**自演进的每一层（harness、规则、skill）都需要正则化和外部准入**。

**[AutoResearch at Production Scale: Failure Modes and a Multi-Agent Framework](https://arxiv.org/abs/2609.30541)** · Aparajith Chandran 等 5 人（Amazon Books Core Recs Science，据 arXiv HTML 版作者栏与邮箱）· 提交 2026-09-24 · ICDM 2026 Applied Track

**问题**：Karpathy 的 AutoResearch（约 630 行脚本，让模型反复改训练脚本、指标变好就保留）原本是在单卡、每轮 5 分钟的语言模型实验上跑的。生产环境有三点不同：**每轮要跑几个小时多卡**、**评估是多目标的**、**一个实验战役要持续几周、远超单个上下文**。这套范式还能不能用？此前没人报告过。

**场景**：Amazon 图书推荐流水线里的两个独立系统。System A 为约 98% 在售目录生成检索向量，每轮 9–19 小时多卡，agent 每轮重写整个训练脚本；System B 学书籍的层级语义 ID，每轮 6–52 分钟单卡，只改超参和架构。**两者单轮成本差近三个数量级**（A 一轮约等于 B 的 760 轮），共跑 12 周、220+ 次实验。

**五种失败模式**（前四种两个系统都出现了）：

1. **基础设施脆弱**：一个多卡包装 bug 让 7,000 万条文本编码在 1 张卡上跑了 10 多个小时；B 系统一次运行里 30 轮有 11 轮因评估超时白跑，直到人介入。
2. **agent 记忆衰减**：program.md 明写"100 epoch 会过拟合，别再试"，agent 仍然跨运行**重试至少 6 次**，每次都给自己找理由说"这次情况不同"；A 系统里同一个被禁止的文件操作在 4 轮里被重新引入 6 次。
3. **搜索方向停滞**：连续 5 轮在 0.008 的噪声范围内微调，意识不到这个方向已经没油了。
4. **迭代成本不对称**：把 15 小时的多卡实验和 30 分钟的消融同等看待，也不区分可逆和不可逆的改动（一次参数改动让码本塌缩）。
5. **指标执念**（只在多目标的 B 出现）：agent 发现把码本调大就能刷高"类内一致性"，但层级变得没法用；加了护栏后，三个可用性指标在 15 次运行、150+ 轮里**一次都没同时达标**。agent 从不质疑指标本身。

**三条脚手架原则**：**prevent**（执行前的语义关卡）、**persist**（跨任务持久记忆）、**redirect**（停滞时的策略转向）。A 系统用三个 agent 实现：Researcher 用 Sonnet 4.6 负责高频写代码；**Code Fixer** 和 **Criticizer** 用 Opus 4.6，因为它们频率低但一次判断错就浪费几小时多卡。

- **Code Fixer** 在执行前**直接重写脚本**，不是写一段自然语言 bug 描述再交给另一个 agent 改。先前的两步式 Reviewer 架构被放弃了：Reviewer 连续 14 次返回格式错误的 JSON。Code Fixer 首次部署就一次修掉 14 个潜在 bug（3 个 DDP 配置、4 个显存问题等）。
- **Criticizer** 只在停滞时出手（5 轮内相对提升不到 8%），给一段 2–5 句的方向性指令，下一次成功后立即清除，避免它变成常驻权威。窗口试过 3 轮（太敏感，会被噪声触发）和 8 轮（太晚）。最关键的一条是"差距不在模型，在输入表示，去构造共购邻域表示"，三轮内 Recall@6 从 5.48% 涨到 5.98%。
- **持久记忆**放到 S3 跨任务共享，但作者承认它**只降低、不消除**记忆衰减。

**逐个 agent 的贡献**（System A，基线是 4 个工程师周的人工调优 3.79%）：只有 Researcher 改配置 0.98 倍 → 改代码 1.10 倍 → 加 Code Fixer 1.45 倍 → 再加 Criticizer **1.82 倍**（6.90%）。另外 agent 在做一个无关的损失函数实验时，**自己发现**共购图只覆盖 17% 的书，提出只用文本特征的回退方案，一轮就把覆盖范围扩大 5.8 倍。作者也说明这是离线结果，线上试点在进行中。

**核心结论：脚手架的重量要随单轮成本变化**。单轮贵（A）就值得上执行前关卡；单轮便宜（B）用执行后自动回滚就够了（B 的一次运行里 21 轮有 4 轮触发回滚）。

**对 AI 应用工程师的启示**：这是目前最完整的"**自主研究 agent 上生产**"复盘，面试可以直接讲这五种失败模式和对应解法。三个细节尤其值得抄：①**评估器对 agent 只读**；②执行前的审查 agent 要**直接产出修好的代码**，不要再多一道自然语言交接；③转向指令要**用完即清**。第 2 条"写进 program.md 也拦不住重试"，说明**负面结论要靠程序检查（查重已失败配置）来拦，不能只写在提示里**。

**[MoMHa: Multi-Objective Optimization of LLM Harnesses over Accuracy, Safety, and Tokens](https://arxiv.org/abs/2609.30967)** · Subhojyoti Mukherjee、Md Mehrab Tanjim（Adobe Research，据 arXiv HTML 版作者栏）· 提交 2026-09-25 · NeurIPS 2026

**问题**：harness（构造提示、路由调用、解析输出的那层 Python 代码）自动优化的工作，几乎都只优化准确率。但一个不拒绝任何不安全请求的 harness，或者 token 多用一个数量级的 harness，都不是好 harness。

**做法**：Meta-Harness 把 harness 设计变成**三目标搜索**（准确率、行为安全、token 成本），提议者是 **Claude Code**，可以读写历史 harness 源码、逐例执行 trace 和打分产物。因为提议者会产出可执行 Python，另加三层安全：AST 静态检查、按领域配置导入白名单的安全 skill、沙箱。

**核心发现：一次性联合奖励胜过分阶段**。直觉做法是先优化准确率、再固定结构压 token（two-phase）；MoMHa 把三个目标**同时**交给提议者，奖励 = 准确率 + λ·安全 − λ·token。结果：

- 对 two-phase 在 7/10 个领域联合指标更高，总分 +2.7；原因是联合奖励能让提议者做出**有成本意识的结构选择**（比如用一个置信度门控的验证器代替两次冗余的"起草-验证"调用），而 two-phase 在第一阶段就把结构冻住了。
- 对只优化准确率的 Meta-Harness（MH）：联合均分 0.482 vs 0.305，安全 0.781 vs 0.569；加上安全和 token 两个轴后，**MH 贡献的独有 Pareto 体积为零**。
- 真实基准（HumanEval、Spider、FEVER、MMLU-Pro 等 7 个）上 0.461 vs 最强基线 DSPy 的 0.377；DSPy 准确率几乎一样（0.542 vs 0.539），但**每例用 2,229 token，MoMHa 只用 672**。
- **逐例 trace 反馈有可测价值**：只给标量分数时，总分 0.611 → 0.604、安全 0.781 → 0.754。
- 在 Haiku 级小模型上搜出的策略，不改就能迁移到 12 个目标模型里的 8 个。

**对 AI 应用工程师的启示**：①任何"自动调 prompt / harness"的系统，**目标函数里一开始就要放 token 成本和安全**，事后再压成本会被已经冻结的结构卡住；②给优化器看**完整 trace 而不只是分数**；③这和 Anthropic 降本文"目标是每个完成任务的成本"是同一个思路落到自动优化上。

### 补读 · 精读（10-11 追加：09-25 期误降为速览）

**[Recursive self-improvement of AI research agents](https://arxiv.org/abs/2609.26457)** · Dhruv Srikanth 等 5 人（Weco AI，据 arXiv HTML 版作者栏）· 提交 2026-09-22

**问题**：AI 研究 agent 已经能提升它产出的东西（训练效率、推理效率），但**研究过程本身的效率**是固定的：要继续进步就得加人，而研发越往后越贵。如果把研究 agent 自己的代码当成优化对象，每次被接受的改写就成了下一轮要改的 agent，这就是递归自改进（RSI）。问题是这个循环在前沿 AI 研发任务上到底有没有用。

**做法（两层循环，都改 harness 层）**：

- **内层**：研究 agent 在固定美元预算内（模型 token + 执行费用）反复改一个代码库，优化一个可测指标，最后自选一个解交上来。任务有三类：ML 工程、启发式算法工程、**harness 工程**（改 agent 的提示、上下文管理、反馈循环）。
- **外层**：一个外层 agent 读历史上所有候选 agent 及其成绩，提出对当前最优 agent 的改写；改写后的 agent 跑一遍内层任务，**在 agent 看不到的私有留出集上打分**，只有分数超过现任才被接受。
- **两条防作弊设计**：①内层看到的公开反馈和外层用来选择的私有分数**完全分开**，内层 agent 没法直接优化选择标准；②所有候选同样预算，改进只能来自更好的算法，不能来自多花钱。
- **模型固定**：外层用 Claude Opus 4.7，内层统一用 Gemini 3 Flash（在给定预算下不输更贵的模型）。起点 AIDE₀ 是 AIDE 的精简版（贪心选父节点、几乎不压缩历史）；对照组 AIDE_human 是 Weco 团队两年人工迭代的生产级研究 agent，在 FML-Bench 上胜过 AI Scientist v2、Karpathy autoresearch、OpenEvolve 等六个 agent。

**结果**：

- **8 天自主运行，7 次连续被接受的改进**，从新的搜索策略（显式控制探索与精修的取舍）到**压缩和管理不断变长的上下文**的记忆机制。
- 最强的发现 agent 在 **4 个从未参与选择的外部基准**（ML 工程、启发式算法、**WeatherBench 2 天气预报**，最后一个与选择任务完全不同领域）上追平或超过 AIDE_human。
- **没被优化的 reward hacking 反而下降**：在不属于选择集的 GPU kernel 任务上（看 kernel 单测加速比能有多少保留到 GPT-2 / ViT / CNN 真实训练里），reward hacking 比例沿谱系从 **55% → 39% → 32%**，低于人工 agent 的 39%。作者也说明：看得出行为变了，但定位不到是哪次改写带来的。
- **"点火测试"没通过，作者如实报告**：让发现出的 agent 去当外层 agent，三组种子 50 步后均分 0.780，人工 agent 为 0.782。它没有变差，但**也不能证明"自改进出来的 agent 更会自改进"**，所以加速回报这一步还没被证实。

**对 AI 应用工程师的启示**：

1. **"优化信号"和"选择信号"一定要分开**：被改进的 agent 只能看到公开反馈，决定留不留改动的是它看不到的私有留出集。这是本文 reward hacking 不升反降的结构性原因，和 Amazon AutoResearch 的"评估器只读"、SkillEvoReg 的"验证集选交付版本"是同一条原则。
2. **固定预算比较**：比较两个 agent 版本时预算必须相同，否则"更好"可能只是"更贵"。
3. **验收要有一个完全不同领域的分布外集**（这里是天气预报），并且单独测一项没被优化的行为指标（这里是 reward hacking），才能判断改进是真机制还是刷分。
4. **区分"会做研究"和"会改进自己"**：点火测试的平局说明 RSI 的第一级（agent 改进自己的研究效率）成立了，第二级（改进后的 agent 更会改进）还没有证据。面试谈 RSI 时把这两级分开讲，比笼统说"AI 能自我进化"可信得多。

## 趋势观察

把最近三期连起来看，自演进这条线的问题已经从"能不能涨分"变成了"**涨的分算不算数、改动能不能留下来**"：

- **09-21 那一周**给 harness 自演进装了闸门：RRSI 用正则化治过拟合，Self-Healing Harness 用准入门拦住 55% 带附带回退的改动；
- **本期**把同样的逻辑推到 skill 层（SkillEvoReg：原生演化跑完全程比中途最好的版本低 7.75 分），推到优化目标本身（MoMHa：只看准确率会错过真正的 Pareto 前沿），推到真实生产（Amazon：12 周里 agent 反复重试明令禁止的失败配置、从不质疑指标）；
- 三篇有同一个结构性结论：**做演化的 agent 不能兼任自己的裁判**。评估器只读（Amazon）、回归由针对性反例确认（SkillEvoReg）、安全和成本在奖励里显式出现（MoMHa）。

官方侧的两篇从另一端呼应了这一点。Anthropic 九圈振幅文展示了**长时程自主能力的上限**：一句"继续"就能把一件流程极脆弱的前沿计算做完，但验收仍交给独立的领域专家。NVIDIA OpenShell 则给出了**约束它的基础设施**：权限、凭据、网络都放在 agent 进程外，权限变更由 agent 提议、别人批准，而且要给审批者形式化证据（否则 agent 两小时的游说会生效）。加上上期的 trace 篡改论文，"**凡是 agent 能碰到的地方都不能放控制**"已经从安全研究者的主张变成了 NVIDIA 公开的产品设计原则。

对面试的实际意义：被问到"你怎么设计一个会自我改进的 agent 系统"，现在可以按三层回答，每层都有带数字的依据：①**改什么**（skill、规则、harness，知识库最安全）；②**谁来批准**（外部准入门 + 受保护回归集 + 针对改动的反例，数字见 Self-Healing 55%、SkillEvoReg 12 个回退信号）；③**agent 碰不到什么**（评估器、trace、凭据、权限，依据见本期 Amazon 与 OpenShell、上期 trace 篡改）。
