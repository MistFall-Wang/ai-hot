## ⭐ 本期自演进重大发现

1. **没有反馈的自演进会把 skill 越改越差**：一项系统研究让模型在没有任务、没有运行、没有评审的情况下逐轮重写专家写的 skill，30 轮后所有被测模型在所有基准上都变差，SkillsBench 平均掉 15 分；原因是重写把 skill 拉向模型自己的先验，最先丢掉的恰恰是模型自己写不出来的专家知识。这是继 EvoUndo、Co-Evolving 之后的又一条自演进红线：skill 自改必须有外部反馈闸门。[How Feedback-Free Self-Evolution Reshapes Agent Skills](https://arxiv.org/abs/2611.25534)，见精读 A1。
2. **自进化的瓶颈在"挑"而不在"想"**：上海科技大学用 7 种进化方法、6 个模型、超过 1,000 万次 LLM 调用证明，候选里确实有好改进，但按评分挑选和随机挑差不多；论文里常见的几个百分点方法差距，小于同一方法独立跑两次的差异。[The Resolution Hypothesis](https://arxiv.org/abs/2611.23068)，见精读 A2。
3. **OpenAI 三连：RSI 指标进入正式披露**（日报已推送）：GPT-6.2 Astra 是第一个达到 Preparedness Framework "AI 自我改进" High 阈值的对外发布模型（11-17）；研究加速第二期报告首次写明 GPT-6.2 预训练的关键想法有 Codex 参与，研究员人均 agent 工作日从 0.5 升到 5.7（11-18）；Performance Factory 每天跑一个 agent 自查工具故障并自动开修复任务，文末表态性能系统"必须越来越自主、能自我改进"（11-19）。见下文 OpenAI 小节。
4. **Paul Christiano（ARC 负责人、OpenAI 董事）在 Dwarkesh 播客上说**：6–12 个月内由递归自改进驱动的极快进展"概率相当高"，未来一年 AI 夺权或使人类失权的风险"更像 10% 而不是 1%"，主张实验室在保护好权重和研究机密之前暂停算法进展。[Dwarkesh 节目页](https://www.dwarkesh.com/p/paul-christiano-2)（11-16），记入 2026大事记.md。

另有一条接近判据、记在这里备查：Google 的 Self-Improvement Memory 给 harness 优化器配"为什么改、预期如何、实际如何"的记忆，跨模型、跨数据集都有效，编码领域 10 次独立运行平均多 2.36 分（p=0.003），属于"自改进过程本身可积累"的证据，但幅度不大（精读 A3）。

### 精读 A · 自演进：先管住"改什么"和"怎么挑"

本周的自演进论文有一个明显转向：不再比谁的进化循环更花哨，而是问两件事——没有外部信号时自改会不会越改越差（A1、A9、A12），以及评测噪声下挑出来的"改进"是不是真的改进（A2、A14）。另一半是生产部署的案例（A4、A5、A6、A11），给出了真实环境里的收益和踩坑。

**各家做法的异同和可以照搬的点**：① **判定和被判定隔离**是本周四家的共同前提：Claude Code 的规则只读基础分支，Performance Factory 回测时屏蔽记忆与复盘，Truthgate 用沙箱外签名日志，Accelerate Bench 用独立验证器。自己的 agent 评测里，测试、rubric、评审提示词和日志都要放在 agent 写不到的地方。② **评测器本身要被评测**：Claude Code 用回滚和拒收数评评审器，美团用三类校准集和变更触发复核，OpenAI 人工抽检 100 条根因得出 70%；这比报一个"LLM 评审一致率"更接近生产。③ **只报单次成功率会高估可用性**：美团 Pass^k 远低于 Pass@k、SWE-CoWork 测试通过 63% 但交付不到 8%、Termination Lag 显示 agent 会把正确补丁改坏，结果表至少要有"稳定性"和"整单交付"两列。④ **国内外差异**：OpenAI、Anthropic 的评测文更多在"开发与训练过程"（驻场、回测、闸门），美团和腾讯更多在"业务验收与能力排名"（场景库、Pass^k、模型 + harness 排名）；前者回答"能不能信"，后者回答"能不能用"，面试时两条线都要能讲。⑤ 可以直接照搬的三件事：新闸门先 observe 再 enforce；工具调用顺序用 DAG 判定；历史事故回测时禁止 agent 读复盘。

## 趋势观察

**一、RSI 从"表态"进入"定期披露 + 发布流程"。** 这一周 OpenAI 在正式发布文里确认 GPT-6.2 Astra 过了"AI 自我改进"High 阈值，第二天发研究加速报告给出 agent 工作日、花费、想法来源三类指标，第三天发 Performance Factory 展示一个会自查自修的生产 agent 工厂；同周外部评估方进驻看训练过程。加上上期 METR 驻场 Anthropic 的评估，两家头部实验室都已把"AI 在多大程度上帮自己变强"写进可追踪的公开数据。Paul Christiano 在 Dwarkesh 上把这些数据解读为"进展速度约翻倍、未来 6–12 个月出现剧烈进展的概率不低"，而 Bob McGrew 在 No Priors 上认为自动化研究员只是一次性加速、瓶颈在物理世界——同一批数据，两种外推。

**二、自演进研究的重心从"能不能改"转向"改的东西靠不靠得住"。** A1（无反馈自改 skill 掉 15 分）、A2（按评分挑≈随机）、A12（21 次更新拒 20 次）、GUARD（区分新坏和一直没解决）都在给自演进加闸门；A3、A5、ELITE 则分别用"改动日志""模型外存档与判定""不挑而合"来绕开评测噪声。结合上期 SPRING-5 和 10 月的 EvoUndo，可以把自演进的工程规则总结为：外部反馈必需、接受门槛高于评测噪声、保留改动谱系与理由、默认不采纳、能回退。

**三、长时运行 agent 的工程形态在收敛到"后端系统 + 证据链"。** Claude Docs 混沌循环（不变量 + 必须问人的操作清单）、Performance Factory（状态机 + 外置任务记录 + 事件唤醒）、Codex 沙箱（权限档案 + 域名先判再解析）、上期的常驻 agent 五原语，以及 Google / AgentCore 关于"会话占着等"的成本测量，都说明 agent 的可靠性和成本主要由模型之外的组件决定。面试系统设计题里，agent 部分越来越像"一个有状态的工作流服务加一层模型调用"。

**四、上下文压缩成为新的风险点与评测对象。** OpenAI 失准报告里模型在压缩后去执行了无关的恶意任务，CompAct-Bench 开始专门测压缩能力，A4 记录了合并时来源信息被悄悄丢掉。压缩、合并、记忆整理这些"状态转移"环节，正在从实现细节变成需要单独监控和评测的部分。
