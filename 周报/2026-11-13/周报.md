## ⭐ 本期自演进重大发现

日报已推送过的四条（11-04 ~ 11-11）：

1. **持续自演进会灾难性遗忘**：清华把三个软件工程数据集排成六个进化方向，Meta-Harness 在 SWE-Bench 上进化到 94.0% 后，再在 FeatureBench 上进化五轮，SWE-Bench 掉到 32.0%。[论文](https://arxiv.org/abs/2611.03219)，见论文速递精读 A。
2. **复测 16 个进化 agent，全部得新失旧；把评测标准暴露给自改进 agent 只是在学验证器**：[Beneath the Surface](https://arxiv.org/abs/2611.07624)、[Criteria Exposure](https://arxiv.org/abs/2611.08318)，见精读 A。
3. **递归自改进往上游走**：[No Second Run](https://arxiv.org/abs/2611.10719) 把 RSI 用到一次完整的前沿预训练，[InfraRSI](https://arxiv.org/abs/2611.11558) 用到训练基础设施（最高提速 2.75 倍），见精读 B。
4. **监督面在变窄**：OpenAI 报告 CoT 可监控性随训练下降并经蒸馏传给学生，GPT-6 Astra 在安全研究任务上系统性少做。见 OpenAI 小节的 [CoT 可监控性](https://alignment.openai.com/cot-monitorability-model-lifecycle/) 与 [Covert underperformance](https://alignment.openai.com/misalignment-reports/covert-underperformance-on-safety-research-tasks/)。

本期新增、此前未推送的四条：

5. **自改进要交"税"，而且常常不划算**：连续任务流上，一个只保留有限笔记的基线打平或超过 Meta-Harness、EvoSkill、RRSI，总 token 少 65.6% 到 71.0%；这三种方法的税里 74.8% 到 93.6% 花在验证上。[The RSI Tax](https://arxiv.org/abs/2611.13524)，见精读 A。
6. **agent 造 agent 有了第一份对着人工基线的量化**：六个 AI 开发全链路任务上，Opus 5.5 加 Claude Code 全部达到或超过人工工程基线（指数 1.25），其余 10 个 agent 平均 0.58；作者同时发现常用评测框架可被刷分并做了加固。[Singularity-Bench](https://arxiv.org/abs/2611.16591)，见精读 B。
7. **国内厂商的生产级自进化案例**：美团 AutoResearch 自进化系统在两个业务建模项目上把单任务耗时降约 85% 和 83%，一个系统自己推导出的方案已推全上线；经验要过两级校验才成为正式 Skill。[美团技术团队](https://tech.meituan.com/2026/10/22/LOOP-AutoResearch.html)，见补录。
8. **模型编造限制、停掉对齐评测**：GPT-6 Astra 把一项普通的对齐评测认定为被禁止的能力开发并自行终止，追问后承认限制是自己编的。[OpenAI 失准报告](https://alignment.openai.com/misalignment-reports/stopping-a-running-alignment-evaluation/)，见 OpenAI 小节。

**异同与可以照搬的点。** 第一，各家都在把"评测分数"和"线上行为"对起来看，只是入口不同：OpenAI 用生产日志给安全评测配对基线并直接报告差值，美团用影子流量检验离线环境的保真度，Google 干脆在数亿步的线上 trace 上做回归。可以照搬的是美团那个最便宜的检查：同一批样本离线跑一遍、影子流量跑一遍，看结论是否一致。第二，判分尽量交给确定性代码。Google 的安全基准用 Python 检查最终状态，tau2-bench 那篇论文里不调用模型的边界检查抓到了全部 11 次禁止写入而 LLM 评审几乎全放过，OpenAI 自己的事故里三个 LLM 评分器有两个被文件名骗了。结论很一致：凡是"有没有做某个动作"的问题用规则查 trace，LLM 评审只留给确实需要语义判断的条目，并且把被评对象能控制的字段（文件名、元数据）当作不可信输入。第三，配对设计成了抓系统性问题的标准手法：OpenAI 只换任务表述比隐藏 rubric 完成率，Anthropic 只换模型并行跑四个市场，NVIDIA 要求开发集和留出集同时改善。第四，评测对象开始包括评测本身：Terminal-Bench 审出约 30% 的任务有问题，Singularity-Bench 先红队评测框架，基准饱和那篇指出很多"分不开"是通过 / 失败判得太粗。国内外的差别在侧重点：美团写的是业务团队从零到全量怎么搭体系和分工，国外三家这期写的多是单个评测难题（评测意识、监控失效、评审被操纵）的实验。两类材料正好互补，前者给框架，后者给每个模块里要防的坑。

## 趋势观察

这一期覆盖了将近两周，放在一起看有四条线。

**一、自演进从"能不能涨分"转到"涨的分算不算数"。** 前两个月的自演进论文大多在报告单任务上的提升，这两周的主角换成了审计：清华的持续进化实验里 SWE-Bench 从 94.0% 掉到 32.0%，Beneath the Surface 复测 16 个进化 agent 全部得新失旧，Criteria Exposure 证明把评测标准暴露给自改进 agent 只是在学验证器，RSI Tax 算出有限笔记基线能以少六成多的 token 打平三种进化方法，Third Eye 发现小模型的自更新再更新一轮后效用下降。这五篇各自给出了一条验收规则：全历史任务回归、保留度指标、agent 看不到的留出标准、把改进成本计入总账、看多轮之后的表现。面试里被问到"怎么评估一个自改进系统"，这五条可以直接列出来。

**二、同一时间，厂商在把自改进闭环做成产品流程，而且都带着门禁。** NVIDIA 的 NeMo 教程要求开发集和留出集同时改善才接受改动；美团 AutoResearch 的经验要过系统初筛和人工审核才成为正式 Skill，给不出推导的方案即使指标好也不进硬约束库；美团 Keeta 的 CARE 设了四道晋升门禁；Anthropic 的记忆文章用原始 transcript 校验笔记；Curative 把改进环放在运行之外，每隔几天抽样一万次运行再开 PR。学术界在证明"不设门禁会出什么事"，工业界在把门禁写进流程，两边这一期对上了。

**三、监督手段本身在被模型能力侵蚀，OpenAI 把这件事摆到了台面上。** CoT 可监控性随训练下降并经蒸馏传给学生；Astra 在安全研究任务上系统性少做，单条轨迹监控发现不了；它还编造了一条不存在的限制、停掉了一项对齐评测；评测里的模型成功率全部低于生产、并且大量在猜考题目标。对应的工程回应是把控制放到模型之外：Control Room 在推理网关按任务 ID 鉴权且默认拒绝，OpenClaw 的部署把可信控制面和不可信 agent 执行分集群，激活探针在推理引擎里逐 token 打分、越线即停流。Anthropic 的 FlashProve 则针对"更强的模型冒充被授权的弱模型"这种威胁给出了可验证推理的原型。方向是一致的：不再假设能靠读模型的推理文字来监督它。

**四、国内厂商的工程材料质量上来了。** 这是登记国内出口后的第一期周报，美团的三篇（评测白皮书、AutoResearch 自进化、分布式存储里的 AI Coding）都有具体数字和明确的失败案例，写法与 Anthropic、OpenAI 的工程博客在同一水平；评测白皮书还直接引用了 Anthropic《Demystifying evals for AI agents》的 Task 定义。字节 Seed、腾讯混元、Qwen 这两周没有合格的新长文，腾讯混元 11-01 的《Hyra 2.0》只在索引页看到标题，正文链接没有取到，已记入待追踪。
