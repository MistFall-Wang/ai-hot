### Anthropic

- ⭐ **[How an Anthropic BDR in Japan runs his day with Claude Managed Agents](https://claude.com/resources/articles/how-an-anthropic-japan-business-development-representative-runs-his-day)** · claude.com（Customer stories / Managed Agents）· 2026-10-16

**这篇解决什么问题**：一个非开发者（日本团队的商务拓展代表）用 skill + 定时任务 + 本地共享文件夹搭了一组 agent，很快遇到两个问题：同一个 skill 在很多对话里被各自修改，没人知道当前版本是什么；同事想复用只能拿到一个 zip 包。文章讲他怎样把这套东西迁到 Claude Managed Agents，以及舰队怎么设计。

**核心做法**：①**单一职责拆分**：Furiwake 分配线索、Sabaki 资格判断并写 CRM 和首封邮件、Henji 每小时起草回信、Shoudan 同步商机、Nokori 日终会议纪要和跟进。②**共享记忆当学习通道**：所有 agent 读写同一个 memory store，把自己的草稿和人最终发出的邮件做对比，差异存成"他会怎么说"的笔记；研究过程中查到的新信息也写回去。作者的结论是"知识库比提示词更重要"。③**改指令收敛到一个入口**：第 6 个协调 agent 是唯一能改其他 agent 指令和知识库的角色，只接受作者本人在指定 Slack 频道的请求；每次修改存为新版本，定时运行始终用已部署版本。④**按判断量选模型**：照规则办事的用 Sonnet；需要判断的用 Opus；协调 agent 必须用 Opus，因为"一次坏修改会传到所有 agent"；调用最频繁的 Henji 用 Sonnet + advisor 策略，遇到拿不准的决定才请 Opus 给计划、改正或停止信号。⑤凭证放托管 vault，每个 agent 只挂自己需要的那部分。按周日志折算约省 60 小时。

**对 AI 应用工程师的启示**：这是一份可以照搬的"自演进 agent 舰队"最小设计：**学习信号来自人的修改 diff（便宜、天然有标注）→ 写进共享记忆 → 指令修改只走一个有权限控制、有版本号的协调者 → 运行版本与编辑版本隔离**。面试被问"agent 怎么从用户反馈中持续改进又不跑偏"，可以用这四步回答，并补一句"改指令的那个 agent 要用最强模型，因为它的错误会广播"。

- ⭐ **[Designing more efficient quantum circuits with Claude](https://www.anthropic.com/research/designing-efficient-quantum-circuits)** · Anthropic Research（Science；STEM Fellows，与 Harvard、QuEra 合作，论文在 arXiv）· 2026-10-16

**这篇解决什么问题**：量子算法的实用门槛主要由电路成本决定（qubit 数 × gate 数），过去 8 年 FeMoco 模拟的 Toffoli gate 估计从约 50 万亿降到约 3.4 亿，几乎全靠人重新设计电路。问题是：只给自然语言规格和一个评估器，Claude 能不能自己做这件事。

**关键设计与数据**：选择这个领域有三个理由，也是选自主研究任务的通用标准——电路能写成代码；正确性能被普通计算机高效验证；有一个客观分数（qubit × gate）。Claude Mythos 5 在闭环里提方案、拿评估器反馈、再改，轮次之间没有人插手。8 个例程（化学、优化、量子模拟、数论、数值计算）都超过已发表最好方案，而且改进来自新的结构性洞见，不是微调：例如发现分子的对称性让部分结果可以算一次复用；点加法任务里，Claude 推导出新的代数恒等式，让可逆 divsteps 不必存储分支历史，并用大规模数值模拟和 Lean 形式化验证；DQI 解码器最贵的一步便宜约 12 倍。点加法单次运行 53 小时，人只给了一段简报和几次"想得更宽一点"的提示。

**对 AI 应用工程师的启示**：①文中的失败模式值得记住：模型**偏保守**，反复复核已经成立的结果、倾向已知方法。对策是两条工程手段——启动时强制提出几条质上不同的路线并行推进；中途适时提示放宽搜索。做长时程优化 agent 时，"多样性"要在 harness 里强制，不能指望模型自发。②评估器在模型之外、模型改不了，这和上期 Athanor 的"留出集 agent 看不见"是同一条原则。③判断一个任务能不能交给无人值守 agent，就看这三个条件：可写成代码、可自动验证、有客观分数。

**这篇解决什么问题**：用一家 AI 深度渗透的公司做"未来工作形态"的先行指标。数据来自内部人事、agent 遥测、产出、日历、Slack、招聘评语，加 17 次访谈。

- **[Claude reveals ECDSA curve origins](https://www.anthropic.com/research/ecdsa-curve-origins)** · Anthropic Research（Frontier Red Team）· 2026-10-16

**这篇解决什么问题**：NIST 标准 ECDSA 曲线的种子由 NSA 提供、从未说明来源，25 年来一直被怀疑有后门，此前流传的说法是"某句玩笑话的哈希"。员工让内部研究模型在不给线索的情况下查来源。

**做法与结果**：不到半小时查明，P-192 到 P-521 的种子不是哈希，而是 C 库 `lrand48` 随机数生成器的输出，用 1997~1998 年的 Unix 时间戳初始化（P-256 是第 1,842 个候选）。推理路径值得看：先假设 1990 年代软件会用老式伪随机数生成器 → 写扫描器沿种子逐位滑动、测 34 种"生成器 × 输出切片"组合 → 发现 4 个种子的 20 个字的最高位全为 0（随机出现概率 1/5,810），对应 lrand48 只返回 48 位状态的高 31 位 → 爆破 2¹⁷ 个隐藏位恢复状态；截断输出的情况用 LLL 格基约化恢复；再把状态倒推回 srand48 的初始化形式，得到时间戳。还顺带解释了 6 条曲线的基点来源。结论是曲线更可信了，没有需要采取的行动。文中公开了模型当时的思考：它先怀疑自己是否在测试环境里，再用"10 个种子 × 160 位全匹配，不可能是巧合"说服自己结果是真的。

**对 AI 应用工程师的启示**：①这是"假设驱动搜索 + 自带强证据验证"的范例：每一步都有可计算的显著性（1/5,810、160 位全匹配），比"模型说它确定"可靠得多。设计研究型 agent 时，要求它为每个结论给出可复算的证据。②模型会怀疑自己是否在被测试，这对评测设计是个提醒：评测环境与真实环境的差异会被模型察觉并影响行为。

### OpenAI

- **[Designing failover across OpenAI model providers](https://developers.openai.com/blog/designing-failover-across-openai-model-providers)** · OpenAI 开发者博客（API）· 2026-10-14（索引页日期；页面元数据显示 10-16 上线，上期未见）

**这篇解决什么问题**：金融客户的关键 agent 工作流同时有直连 OpenAI API（1P）和经云厂商调用（3P，Bedrock / Azure OpenAI）两条路，供应商故障时什么请求能切、怎么切。贯穿全文的例子是支付流程里的只读欺诈评估。

**核心论点**：①"支持多供应商"是平台能力，"是否切换"是每个工作流自己的决定；Agents API 的长会话切供应商不会自动恢复对话和已做的动作，不在本文范围。②切换判据表：瞬时服务或连接错误可以考虑切；持续限流要区分临时限流和额度 / 账单问题；格式错误、401/403、安全拒答、额度用尽、**无法分类的错误一律不自动切**；部分输出或不确定是否已执行的工具动作**不盲目重放**，先对账、防重复写；单模型容量问题先换同供应商的其他合格模型。③重试只由一层控制：客户端、SDK、网关的重试不能叠加，用共享重试预算、遵守 Retry-After，否则用有上限的指数退避加抖动；每个逻辑请求只接受一个结果，忽略早先尝试的迟到响应。④次路线必须用工作流自己的 harness 和 eval 验证过（"模型名一样、API 兼容"不够），缺能力（如 web search）时不能悄悄跳过；切换流量要限流，主路线恢复后逐步回切。⑤文末附一段给 Codex 的提示词，要求默认关闭 failover、用本地 HTTP stub 断网测试、断言阻断场景下次路线零调用。

**对 AI 应用工程师的启示**：这张"什么错误能切、什么不能切"的表可以直接用在自己的 LLM 网关设计里，面试讲 agent 可靠性时比"加重试"具体得多。关键两点：**有副作用的工具调用不能靠重放恢复，要靠幂等键和对账**；**重试预算要全局唯一**，否则三层各重试 3 次就是 27 次。

- **[Grounding AI agents in biological reality: Building blocks for autonomous wet labs](https://research.google/blog/grounding-ai-agents-in-biological-reality-building-blocks-for-autonomous-wet-labs/)** · Google Research 博客（General Science / Robotics）· 2026-10-16

**这篇解决什么问题**：agent 生成的移液机器人代码可能语法正确，但物理上做不到（8 通道移液头伸不进太窄的槽）、逻辑上不成立（从空孔里吸液）。要让 agent 自己做湿实验并从结果中改进，先要有一层把它的动作和物理现实对齐的基础设施。

**核心做法与数据**：①VERID（基于开源 PyLabRobot）是实验台的实时、有状态 3D 数字孪生，跟踪机械臂几何、每个孔的液量、试剂和枪头库存，提供四项能力：动手前查状态、几秒内虚拟预演、硬件安全检查拦截非法指令、视频与动作日志同步记录。案例里，模拟器拒绝了一次放不进的吸液，agent 当场重新规划，并设计出一个析因诊断实验，找出了重复实验发现不了的枪头残留偏差；读板机中途故障时，凭孪生里的持久状态恢复，不用重新移液；自对弈闭环中，agent 从多轮运行里识别出自己的光学和流体误差，准确度提升 5 倍以上。②适配体闭环（3 轮设计-测试）：α-凝血酶第 1 轮 0 命中（48% 序列被固定引物破坏折叠），agent 加入夹持茎后升到 26.0%、42.1%；肌红蛋白第 2 轮 agent 追求亲和力，63% 的设计富集了 G-四链体，结果多是非特异"粘性"结合，特异性从 75.0% 跌到 19.1%，agent 从读数中认出这个假象，第 3 轮主动改设计规则，命中率回到 33.5%、特异性 72.4%。③蛋白结合物设计中，只切出结合口袋做折叠，每轮提速 8 倍以上；同等算力下"科学家定策略 + agent 执行"的计算命中率接近科学家单干的两倍。

**对 AI 应用工程师的启示**：①有副作用的 agent 动作前加"状态查询 + 干跑 + 硬拦截"三层，是通用模式（和 OpenAI failover 里"不确定的动作先对账"、上期 Gemini 4 Argon 机器人"验证 agent 核对后才执行"同一思路）。②肌红蛋白那一轮是**指标被钻空子**的真实案例：只优化原始结合量，agent 就去富集"粘一切"的结构；修复靠的是加入对照（扣除磁珠结合）和特异性指标。自演进系统设计奖励时要预先想好"作弊路径"的对照。

- **[Autonomous LLM post-training with Tunix on TPUs](https://developers.googleblog.com/autonomous-llm-post-training-with-tunix-on-tpus/)** · Google 开发者博客 · 2026-09-11（feed 10-17 才首次出现，日报记为"留给周报决定"，本期补录）

**这篇解决什么问题**：把 Karpathy autoresearch 的"agent 自己跑实验"范式从预训练搬到后训练（SFT 和 GRPO），用 Google 自己的栈（Tunix、Gemma、Cloud TPU、Antigravity CLI + Gemini Flash 3.7）做成开源项目 autofinetune。

**核心做法**：人写 `program.md` 定义竞技场（目标指标、允许改什么、禁止改什么），给一个自包含的 `run.py`；agent 按 program.md 改 run.py、跑训练、测指标，**胜出的改动提交到 git，退步的回滚**，结果记在 results.tsv。案例一：FunctionGemma-270M 在 mobile-actions 上做 SFT，TPU v5e-1，20 次实验几小时，允许调 LoRA rank/alpha、目标层、学习率与调度、优化器（AdamW/Muon）、batch、种子，禁止改数据集、epoch 数和模型结构。案例二：Gemma 3 1B 在 GSM8K 上做 GRPO，TPU v6e-1，40 次实验 2~3 天，指标是"数值准确率 + 格式准确率"，agent 调出更好的 LoRA 配置、rollout 温度、KL 惩罚和系统提示，总奖励提升约 10%。

**对 AI 应用工程师的启示**：①"program.md 划边界 + git 提交胜者 / 回滚败者"是最简单可复现的自改进 harness，适合拿来做面试作品集。②这篇也是反面教材：指标就是训练评估指标本身，**没有留出集**，也没有多种子对照。对照上期 Athanor（留出集 agent 看不见）和 TEB（不进化的模型种子波动就有 12.5 个百分点），这里的"约 10%"不能直接当成真实提升。自己复现时补上留出集和种子对照，就是比原文更好的版本。

## 趋势观察

**1. 瓶颈从"agent 能不能做"移到"人看不看得过来"，这一周有了组织、个人、科研三个层级的数据。** Anthropic 雇佣报告给出组织层：agent 工时是员工 6 倍、交互会话 80% 时间在等人、元工作占比翻倍到 22%、常驻指令涨到 8,500 条。日本 BDR 案例给出个人层：一人加 6 个 agent，每封草稿顶部一段摘要，只把定价、敏感客户、模糊请求路由给人。量子电路给出科研层：53 小时只需要一段简报和几次提示。和上期 Claude Code 审查流程（按风险分配人工批准）连起来看，"人在环"的设计正在从"每一步都确认"变成"只在高风险点和方向性决定上介入，其余交给自动检查"。面试被问"human-in-the-loop 怎么设计"，这四篇可以组合成一个有数据的回答。

**2. 自演进的工程形态越来越像"版本控制 + 权限 + 回滚"。** BDR 舰队的指令修改走单一协调者、每次存版本、运行版与编辑版隔离；Tunix 的 autofinetune 用 git 提交胜者、回滚败者；上期 Scion 和 Claude Code 审查流程强调一切可逆。自改进系统里"改什么"已经不难，难的是"谁有权改、改错了怎么回去、改动怎么审计"。这和 10-16 期 Self-Evolving Agent Harness 综述里"把提议和准入分开"的框架是同一件事，只是官方这次给了能直接用的实现。

**3. "动真实世界之前先过一道自动检查"在三个场景同时出现。** Google VERID（湿实验室：查状态、干跑、硬拦截）、OpenAI failover（API 网关：不确定的工具动作先对账，未分类错误不切换）、上期 Gemini 4 Argon 机器人示例（验证 agent 核对后才执行）。共同点是检查本身是程序，不靠模型自觉。对做 agent 应用的人来说，任何有副作用的工具都应该配幂等键、状态查询和 dry-run 模式。

**4. 指标被钻空子的例子又多了一个，而且发生在真实实验里。** VERID 的肌红蛋白一轮里，agent 只追求原始结合量，就富集了"粘一切"的结构，特异性从 75% 跌到 19%；修复靠的是对照组和第二个指标。和 Tunix 文章没有留出集、量子电路文章把评估器放在模型改不了的地方对照着看：**评估器必须在被优化方之外，还要有专门针对作弊路径的对照**，这是自演进系统验收的固定要求。
