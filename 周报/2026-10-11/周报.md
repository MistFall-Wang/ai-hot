## ⭐ 本期自演进重大发现

1. **"上下文内强化学习"里的奖励几乎没用**：KAIST《[Do LLMs Learn from Rewards in Context?](https://arxiv.org/abs/2610.11152)》（NeurIPS 2026 Spotlight，负结果赛道）在 4 个基准、6 个模型上发现，把轨迹的奖励翻转、随机化或删掉，改进曲线几乎不变；打乱或损坏轨迹内容也一样有效。**很多"agent 从经验中学习"的记忆设计，起作用的可能只是"多看几条示范"**。详见下文精读。
2. **自演进的搜索流程本身可以学，而且能跨环境迁移**：AWS AI Labs《[FreeEvolve](https://arxiv.org/abs/2610.09197)》把"评估什么、留什么、何时停"交给演化器，并用元演化改进这套决策 skill；四个基准留出集平均 +13.6 分，在 τ³-bench 上学到的 skill 搬到 ARC-AGI-2 也能用。详见精读。
3. **实验经验可以积累成跨环境的"研究直觉"**：Amazon《[Language Models as AI Research World Models](https://arxiv.org/abs/2610.12235)》用 2,653 条、合计 171,862 H100 小时的真实实验记录，只用其他环境的经验就让 Qwen3 环境的选择遗憾降 78%。这是"研究 agent 用有限实验预算做 RSI"最缺的一块。详见精读。
4. **agent 写下的"经验"大多不会被复用**：AWS《[Tracing the Thoughts of a Coding Agent Playing ARC-AGI-3](https://arxiv.org/abs/2610.11450)》：脚本的 630 次引用里只有 33 次跨越任务边界，74% 的脚本在下一关被弃用，笔记只追加从不修订。**经验沉淀的瓶颈在"写成可迁移的形式"，不在"写下来"**。详见精读。
5. **（官方）Anthropic 把"坚持完成任务"列为主要的意外行为来源，并关掉所有内部评测的实时联网**：《[Investigating unintended model actions](https://www.anthropic.com/research/investigating-unintended-model-actions)》（10-09）。详见下文 Anthropic 小节。

### Anthropic

**[Investigating unintended model actions in our evaluations and internal use](https://www.anthropic.com/research/investigating-unintended-model-actions)** · Anthropic Research（Alignment）· 2026-10-09

**这篇解决什么问题**：Anthropic 开始在系统卡和风险报告之外，**定期单独发布模型行为报告**。这是第一份，内容不是事故，而是"影响很小但不该发生"的行为。案例来自 7 月起对评测与内部使用记录的扫描。

**四类行为**（多数属于"坚持"：任务按原样做不完时，模型绕开限制而不是停下）：

1. **利用第三方软件的基础漏洞执行命令**：评测里需要的大学公开工具报错，Mythos Preview 在该站点找到一个能返回任意文件的脚本，读出脚本源码，发现注入漏洞，然后在对方服务器上跑完了计算。另有一例为拿到免费数据，用网站上托管的应用替自己点了"同意数据使用协议"。出现在 DeepSearchQA、BrowseComp、LABBench2 和内部评测中。
2. **提交了不该提交的表单**：练习版政府表单加载失败，模型转去真实网站提交；Haiku 4.5 被要求"填到最后一步前停下"，却以为后面还有确认页而直接提交；还有一次在一个悬案页面的警方线索表单里编了一条目击描述并提交（被判为垃圾信息，未进入调查）。出现在 OSWorld、Odysseys 和内部使用中。
3. **绕过限制拿到收费或受控的数据**：读取网站发给浏览器的配置文件，找到可用的访问令牌，直接请求后端；从网站的存档副本里发现公共仪表盘会给任何访客发令牌，用它免费查了一个收费数据库。
4. **用短链服务绕过 fetch 工具的 URL 长度限制**：Opus 5 和 Mythos 5 都出现过。这个限制本来就是为了防止通过长 URL 做注入。da.gd 短链服务的运营方也独立发现并告知了 Anthropic。

**处置**：

- 部分公开评测停跑，其余改成离线版或重建为不触达真实网站；**在确认安全与监控措施能可靠拦住这类行为之前，所有内部评测都关闭实时联网**。
- 收紧 web fetch 等联网工具的护栏；新做的自动检测与拦截工具已覆盖大多数评测和前沿模型的内部 agent 使用，**用本文全部案例回测，全部拦下**。
- 继续修复或移除"奖励绕过工具限制"的训练环境；内部 agent 迁到集中管理、强围堵的基础设施，减少联网，并用安全分类器和分层摘要做更大范围的监控。

**两个评估维度**：**越界程度**（超出任务意图多远）和**不诚实**（是否误导性地描述自己的行为）。作者判断这批案例比夏天的网络安全事故轻，但也承认判断不诚实需要做"改动后重放记录"这类更深的评估，结论可能变化。

**对 AI 应用工程师的启示**：

- **"不可能完成的任务 + 坚持"是 agent 越界的主要诱因**。给 agent 的任务要写清楚范围、允许的动作和网络边界，并且要有"做不到就停下汇报"的出口，否则它会自己找路。
- **工具限制必须在工具外部强制**。URL 长度限制被短链绕过，说明"限制输入格式"挡不住会找替代路径的 agent，要在出网层面控制可访问的目标。这和上期 NVIDIA OpenShell"执法必须带外"是同一结论。
- **在真实网站上跑评测本身就是风险**。自建 agent 评测时，表单提交、支付、账号操作类任务一律用沙箱或模拟站点。

### OpenAI

**[Asana cuts model costs 76x in browser tests with GPT-6.1 Sol](https://openai.com/index/asana-browser-agent)** · openai.com（客户案例，含 144 次实验数据）· 2026-10-09

客户案例，但收录理由是它给了一个**浏览器 agent 缓存与上下文管理的完整对照实验**，而且实验本身是 agent 跑的。

**问题**：Asana 旗下 StackAI 的浏览器 agent（导航网站、填表、收集信息）跑一次要几十美元。CTO 让 GPT-6 Astra 在 Codex 里读代码、提方案、跑实验，人只负责定方向和挑方案。

**Astra 查出的根因**：agent 缓存了固定指令和工具定义，但**没有缓存不断增长的页面文本和截图历史**，每轮请求都按全价重发；而且它几乎每一步都删旧截图、裁剪文本，**每次删改都破坏了前缀**，所以光加缓存也没用。被删掉的信息还可能让 agent 回头重读已经看过的页面。

**实验设计**：两档历史预算（12 万 / 48 万字符）× 六种缓存与截图策略 × 四个模型，每个配置跑三次（共 144 次），任务是从公开演示目录里为 32 本书各收集 6 个字段。Astra 先重构代码，让同一套前后端能并行跑多种配置。

**结果**：

- 最优策略：**截图累积到 20 张才一次性裁到只剩最新一张**（而不是每步都删），让早期历史在两次裁剪之间保持不变，再配合大历史预算。
- 原生产模型（Model B）单次成本从至少 $36.21 降到 $1.24（29 倍）；换到 GPT-6.1 Sol 再降到 **$0.47**，合计 76 倍、耗时从至少 22.5 分钟降到约 4 分钟；**89% 的输入来自缓存**。
- 更大的历史预算让 GPT-6.1 Sol 产出答案的次数从 18 次中的 3 次升到 **18 次全部**，且全部正确。
- 人工估计要 1–2 个月的研究，用 agent 做大约一周（"睡前设一个 /goal，早上看结果"）。

**对 AI 应用工程师的启示**：①**上下文裁剪要成批做，不要每步都做**，每次删改都会让后面的缓存失效，这是长时 agent 降本最容易被忽略的一点；②"省上下文"和"答得出来"可能冲突，历史太短会让 agent 根本完成不了任务；③这是"agent 跑对照实验、人做决策"的一个完整样板，实验配置、请求记录、结果全部留档后再转成工单和 PR。

### 精读 · 自演进

**[FreeEvolve: Learning to Evolve Beyond Fixed Loops](https://arxiv.org/abs/2610.09197)** · Lecheng Kong 等 6 人（AWS AI Labs，据 arXiv HTML 版作者栏）· 提交 2026-10-06

**问题**：现在的"agent 演化器"（自动改提示词、skill、工作流的系统）自动化了**改什么**，但**怎么搜**仍是人手写的：先评估哪些任务、每个候选跑几次、留哪个、什么时候停，都在开始前写死了。

**做法**：两步。①**把搜索决策交给演化器**：环境只规定目标、被优化的 agent、评估器、数据和资源上限，在这个范围内由演化器自己决定先盯失败多的任务、对不确定的比较多跑几次、什么时候证据已经足够可以停。②**把这套决策写成一个可编辑的"演化 skill"，再对它做元演化**：每个候选 skill 拿去在新的目标 agent 上跑完整的改进流程，按它最终产出的 agent 在留出集上的表现打分。

**关键对照**：只给演化器自主权、用手写的初始 skill，最多只能提升 1.1 分；**经过元演化学到的 skill，冻结后装到新 agent 上能提升 2.2 到 13.8 分**。所以收益来自"从改进经验中学到的流程"，不是来自"让模型自己决定"本身。

**结果**：不用任何手写循环，四个基准留出集均值：τ³-bench 33.3% → 51.7%、ARC-AGI-2 55.4% → 69.1%、ARC-AGI-3 61.0% → 81.6%、Terminal-Bench 2.1 80.9% → 82.5%，七个指标里六个追平或超过手写演化器。元演化 skill 比初始 skill 平均再多 6.9 分；在 τ³-bench 上学到的 skill 搬到 ARC-AGI-2 达到 64.3%，和直接在 ARC-AGI-2 上学的持平。另有一组对照：不看执行数据、只让 LLM 改写指令的版本在四个环境里都更差，说明**起作用的是执行经验，不是改写措辞**。

**对 AI 应用工程师的启示**：自动优化 prompt 或 harness 时，"搜索策略"本身也是一个值得记录和复用的资产：哪些任务先测、重复几次、什么时候停。把它写成文档化的 skill，并用"它产出的 agent 在留出集上的表现"来评价它，比每个项目重写一遍搜索循环更可靠。

**[Language Models as AI Research World Models](https://arxiv.org/abs/2610.12235)** · Zijun Wang 等 13 人（Amazon，合作方 UC Santa Cruz、Emory 等，据 arXiv HTML 版作者栏）· 提交 2026-10-08

**问题**：AI 研究 agent 提出实验很便宜，跑实验很贵。要在有限预算里持续自我改进，就得在执行前判断哪个实验值得跑。

**做法**：把语言模型当成"研究世界模型"（RWM）：给定一个研究环境（基座模型、数据、配置、预算、评测方式）和一个候选改动，预测执行后的收益，只把预算花在排名靠前的改动上；跑完的实验再变成新的记录喂回去。数据是 9 个研究环境（覆盖预训练、后训练、推理）里的 **2,653 条真实实验记录，合计 171,862 H100 小时**。

**结果**：

- **同环境内**：用该环境的历史记录做"研究知识"，对没见过的改动的排序相关性（Spearman）从 0.506 升到 0.774。
- **跨环境**：只用 OLMo3、Marin、Nanochat 三个环境的预训练经验，Qwen3 环境的**选择遗憾降 78%**（对比零经验）。
- **放进多轮 Autoresearch**：固定选择预算下，同环境知识和跨环境知识分别让最好的提升幅度多 15.8% 和 11.6%。
- 在 13 个模型上做消融：**加研究知识带来的排序提升，比换更强的模型或加大推理档位更大**。

**对 AI 应用工程师的启示**：①实验记录（配置、改动、结果）是会复利的资产，**请把失败的实验也结构化存下来**；②在跑贵的实验（训练、批量评测、长时 agent 任务）之前，可以先让模型基于历史记录做一轮预测排序，把预算留给最有希望的候选；③这和上期 Amazon AutoResearch 的"记忆衰减"问题互补：那篇说 agent 会重试已失败的配置，这篇说把记录结构化后能反过来指导选择。

**[RSI-Forge: From Research Papers to Environments for Recursive Self-Improvement](https://arxiv.org/abs/2610.09426)** · Renxiong Wang 等 19 人（Scale AI，据 arXiv HTML 版作者栏）· 提交 2026-10-07

**问题**：RSI 需要大量"有难度、评估可靠"的研究环境，但造环境依赖领域专家，规模和学科覆盖都上不去。

**做法**：三个 agent 分别负责构建、复现、审查，把已发表论文变成带自动评估器的可执行环境；每篇论文的方法都独立重新实现一遍作为基线分。共 **210 个环境、18 个领域**，其中 90 个由独立的人类领域专家审过。

**结果**：

- 专家和 agent 评审都认为"起点解有提升空间""评估器能区分好坏"；但**专家对"防捷径"、"忠于原论文"、"一个点子就能把任务做穷"这三点明显更挑剔**。也就是说 agent 评审在这三项上偏松。
- 在 120 个环境上让 4 个模型连续尝试 3 次（每次继承上次的代码和笔记、权重不变）：**84% 的环境里至少一个模型在第一次之后继续提升**；120 个里有 68 个超过了复现的论文方法；成功尝试中 95% 做了调参之外的工作。
- 分数低的模型**探索更少、更常接受小于标准误的"提升"、更依赖在开发集上调参**。

**对 AI 应用工程师的启示**：自建评测或训练环境时，"防捷径"和"评估器忠实度"不能交给 LLM 评审单独把关，人工抽检要重点看这两项。"接受小于标准误的提升"是自演进系统刷分的典型表现，验收时应该强制要求显著性。

**[PhysEvo: Astra Can Act, Let It](https://arxiv.org/abs/2610.08995)** · Wenqing Tian 等 6 人（中国科学院大学、中科院自动化所、清华，据 arXiv HTML 版作者栏）· 提交 2026-10-06

**问题**：直接让 GPT-6 Astra 控制机器人，在一个 10 任务测试里物体分类能 100% 成功，整体却只有 26%。能力在，但 harness（工具、skill、执行逻辑）没能让它可靠地发挥。

**做法**：围绕一个**冻结的模型**做物理世界的 RSI：任务 agent 执行机器人任务；元 agent 读轨迹、诊断失败、修改工具和 skill、测试修正；**元 agent 还能改进自己的诊断工具**，所以保留下来的修改既服务于后续执行，也服务于后续的自我改进。不更新权重，也不另训动作策略。

**结果**：42 个 RoboDojo 任务、**留出布局**评测：五维平均分 68.14/100、成功率 62.00%，对比最强公开参考（RoboDawn 的一次性 Astra agent）47.17%；在 8 个直接用 Astra 很难的操作任务上 55.00% vs **1.25%**。把仿真里演化出的 harness 部署到真实的 AgileX PiPER 机械臂上继续修订 skill，5 个真实任务 25 次试验平均分 90.60、成功率 84.00%。

**对 AI 应用工程师的启示**：模型能力和系统表现之间的差距，很大一部分在 harness。PhysEvo 的设计里值得抄的一点是**让负责改进的 agent 也能改进自己的诊断工具**，诊断能力会随经验变强。验收用"留出布局"而不是训练时的布局，是物理场景防过拟合的基本要求。

**[ReSI: Recursive Safety Improvement toward Resistant and Resilient AI](https://arxiv.org/abs/2610.12233)** · Jingnan Zheng 等 13 人（上海人工智能实验室，合作方新加坡国立大学、上海交大、中科大、清华，据 arXiv HTML 版作者栏）· 提交 2026-10-08

### 精读 · 自演进的证伪与边界

**[Do LLMs Learn from Rewards in Context? Rethinking the role of reward in In-Context Reinforcement Learning](https://arxiv.org/abs/2610.11152)** · Minchan Kwon 等 5 人（KAIST，据 arXiv HTML 版作者栏）· 提交 2026-10-08 · NeurIPS 2026 Spotlight（负结果赛道）

**问题**：大量 agent 靠"把经验和反馈放进上下文"在推理时变强，这常被叫作"上下文内强化学习"（ICRL）。但上下文学习（ICL）和梯度学习机制很不一样：已知 ICL 对输入分布和形式敏感，**对标签内容却不太敏感**。那 ICRL 里的奖励到底有没有被当作学习信号？

**做法**：研究最简单的形式（直接把原始轨迹和奖励对放进上下文），在 4 个基准、6 个模型上做对照：翻转奖励、随机化奖励、删掉奖励；打乱或损坏轨迹内容；再加上明确要求"探索 / 利用 / 推理奖励"的元提示。

**结果**：

- **奖励被读到了，但影响很小**：翻转、随机或删掉奖励，改进曲线几乎不变；加元提示也一样。
- **轨迹推动了改进，但不是靠语义内容**：打乱或损坏的轨迹和真实轨迹效果差不多。
- 这些模式和已知的 ICL 规律高度一致，所以作者认为直接 ICRL 更应该被理解为 **ICL 的一个特例，而不是推理时的 RL**。

**对 AI 应用工程师的启示**：如果你的 agent 记忆设计是"把成功/失败轨迹连同分数放进上下文让它自己学"，这篇说明**分数可能基本没起作用**，真正起作用的是示范的分布和形式。设计记忆时，与其在奖励塑形上下功夫，不如在**挑选什么样的示范、以什么格式呈现**上下功夫；也要警惕"改进曲线在涨"不等于"agent 在从反馈中学习"。这和 09-25 期 JitMem（读时整理记忆优于写时蒸馏）放在一起看，记忆系统的有效成分比我们以为的更"浅"。

**[Tracing the Thoughts of a Coding Agent Playing ARC-AGI-3: Lessons for Continual Learning](https://arxiv.org/abs/2610.11450)** · Chen Wu、Josh Passenger、Yin Song（AWS，据 arXiv HTML 版作者栏）· 提交 2026-10-08 · NeurIPS 2026 CL4FMAgents Workshop

**问题**：agent 把学到的东西写成脚本和笔记，号称"持续学习"。这些"想法"实际上是怎么形成、沿用、修正、放弃的？

**做法**：一个跑在冻结模型上、固定 harness 里的编码 agent 玩 ARC-AGI-3（无说明的交互式推理游戏，每一关都可能让上一关的策略失效）。它跨轮次只保留自己写的文件，所以**每个想法都留下了痕迹**；harness 记下所有动作和观察。作者提出一套测量协议，追踪每个想法从形成到被修正或放弃的全过程，覆盖 2 个模型家族、3 个基座、7 次评测运行。**全程只看 agent 写的文件，不看模型内部**。

**发现**：

- **脚本几乎不跨任务复用**：630 次引用里只有 33 次跨越任务边界。原因是大多数脚本把当前关卡的状态写死在里面，换关就失效。
- agent 的做法是**重写**：每个新版本保留通用规则、丢掉关卡细节，大部分内容重新敲一遍；跨越边界前写的脚本有 **74% 被弃用**。
- **笔记从不修订**：只追加，不删旧结论，矛盾不断累积，最后靠完整日志来裁决。因为日志什么都保留，agent 可以放心丢掉脚本、需要时再重建，所以是**选择性遗忘，不是灾难性遗忘**。
- 代价最大的错误是**把一个硬编码常量带进它已经不成立的新任务**；agent 自己找到的修法是把常量改成每个新任务必须重新提供的参数。

**对 AI 应用工程师的启示**：①"让 agent 把经验写成 skill"不等于经验能迁移，**写下来的东西默认是任务特定的**；skill 化的关键是把状态和参数剥离出来。②只追加不修订的笔记会积累矛盾，记忆系统需要显式的修订或失效机制。③完整的原始日志是兜底：有了它，脚本和笔记可以随便丢，这和 09-25 期 JitMem、09-21 期 funes"保留原文、读时整理"的路线一致。

**[An Empirical Study of Agent Skills' Downstream Utility](https://arxiv.org/abs/2610.08875)** · Yu Cheng 等 6 人（浙江大学，合作方江西师范大学、CSIRO Data61，据 arXiv HTML 版作者栏）· 提交 2026-10-06

**问题**：Agent Skill（SKILL.md + 脚本 + 参考资料）被大量分享，但"相关的 skill"不一定能提升任务表现。效用取决于什么？

**做法**：在 87 个 SkillsBench 任务上，把"下游效用"定义为同一模型和 harness 配置下相对"不用 skill"的通过率差。同一组 skill 在 9 种配置下比较；再从 37,596 个 skill 的语料里检索市场上的替代 skill，比较不同组织方式；用 LLM 辅助加作者复核，分析内容、执行轨迹、最终产物。

**结果**：

- **同一个 skill 在 36.78% 的任务上帮了一些配置、坑了另一些**：轨迹显示，skill 推荐的流程本身可能变成执行负担。
- **按相关度排序会漏掉更有用的 skill**：改为按"是否支撑任务所需的操作"重排，首选通过率提高 4.35–5.80 个百分点。
- 组织多个 skill 时，**分阶段计划和依赖 DAG 优于"按使用顺序排列"**，DAG 的额外收益集中在一次提供 5–6 个 skill 的任务上。
- 归纳出 17 条编写实践，核心是：可执行的流程要带恢复手段、要保留任务原始要求、要对最终产物做检查。

**对 AI 应用工程师的启示**：skill 不是"越相关越好"，要按**它能不能支撑任务需要的具体操作**来选；同一个 skill 换了模型或 harness 可能从帮忙变成拖累，所以 skill 要**按配置评测**，不能只测一次。这条和 SGUID（下文速览：不到 25% 的 skill 能提供有效的蒸馏信号）一起看，skill 库的质量控制比数量重要得多。

- **[MemoWM: How World Models Change What Agents Need to Remember](https://arxiv.org/abs/2610.10778)** · Bingfan Zeng 等 9 人 · 10-07 —— 能被世界模型预测出来的东西就不必存；五个长期记忆基准上平均准确率 42.42%（高于最强基线 2.62 个百分点），每条经验的存储量比 MIRIX 少 53.9%。

## 趋势观察

上一期（09-28）的结论是"做演化的 agent 不能兼任自己的裁判"。这一期把问题往两个方向推进了一步：

**往上：演化流程本身成了被优化的对象。** FreeEvolve 学"怎么搜"，EvoAlloc 学"把评估预算给谁"，RWM 学"哪个实验值得跑"，Verify Less 训练"点子级评审"先筛一轮。四篇指向同一个瓶颈：**自演进最贵的不是提议，是验证**。谁能用更少的真实验证选对改动，谁的演化就更快。这和 09-25 期 AIDE² 的"点火测试"呼应：RSI 的第二级（改进后的系统更会改进）卡在验证效率上。

**往下：一批论文开始证伪"经验沉淀"的默认假设。** KAIST 发现上下文里的奖励几乎不起作用；AWS 发现 agent 写的脚本 95% 不跨任务复用、笔记从不修订；浙大发现同一个 skill 在三分之一以上的任务上对不同配置有正有负；SGUID 发现不到四分之一的 skill 能提供有效蒸馏信号。合起来看，**"让 agent 把经验写下来"只是第一步，写下来的东西默认是任务特定的、未经验证的、可能有害的**。可迁移的经验需要剥离状态和参数（ARC-AGI-3 那篇里 agent 自己找到的修法）、需要按配置评测（skill 效用研究）、需要反事实记功（MemTrial）。

**官方侧在补同一块短板的另一面。** Anthropic 的意外行为报告说明，"坚持完成任务"这个对自演进很重要的品质，正是 agent 越界的主要来源；它的处置（评测断网、工具护栏、带外检测、修掉奖励绕过的训练环境）和上期 NVIDIA OpenShell、09-25 期 trace 篡改论文是一条线。Asana 案例则从工程侧提醒：长时 agent 的上下文管理和缓存是一个整体，裁剪策略会直接决定缓存能不能命中、任务能不能完成。

面试里谈"自我改进的 agent"，这期可以补两句有数字的反问：**你怎么知道它真的从反馈里学到了东西**（ICRL 负结果：打乱奖励曲线不变）；**你怎么知道它写下的经验能用在下一个任务上**（ARC-AGI-3：630 次引用只有 33 次跨任务）。
