## ⭐ 本期自演进重大发现

1. **自主研究 agent 做后训练，过半结果比起点还差，而且挑不出自己最好的模型**：Alibaba Token Hub × 中科大《[MMPostTrainBench](https://arxiv.org/abs/2610.05398)》，8 个多模态任务上 52.1% 的"模型 × 任务"均值低于基座，迭代过程中性能不单调上升，最终提交平均落后于自己评估过的最佳候选（最多 5.38 个百分点），还伴随非目标能力退化。**RSI 的瓶颈不只在"能不能改进"，还在"能不能保住改进、选对版本"**。详见下文精读。
2. **自学习循环里起决定作用的是"独立验收"**：NUS《[MedForge-RSI](https://arxiv.org/abs/2609.36549)》冻结 8B 检测器权重，20 轮自改进让留出集 4,000 张图的准确率从 76.5% 到 87.9%；49 条注册轨迹的对照显示**验收测试是单项最大贡献者**，并给出失败改动的分类。详见精读。
3. **（厂商）Meta：多 agent 的推理计算可以跨回合累积**：Meta Superintelligence Labs《[GitSwarm](https://arxiv.org/abs/2610.04862)》用 Git 仓库做共享记忆（持久、可分支、带 `informed_by=` 溯源），IMOProofBench-Advanced 一次跑解出全部 30 题，ProgramBench 79.4%（最强基线 65.1%），94.7% 的贡献被后续 worker 接着用。详见精读。
4. **自蒸馏的新红线：正确率在涨，解法多样性在塌**：剑桥 × 复旦《[SPECTRUM](https://arxiv.org/abs/2610.07237)》，代码模型反复用自己的输出训练自己，五轮后普通自蒸馏只保留初始模型 66.4% 的"正确解结构丰富度"。**只看 pass@1 的自演进验收会漏掉这种退化**。详见精读。
5. **agent 还不能可靠地为 RSI 设计评测**：《[EvalResearchBench](https://arxiv.org/abs/2610.04184)》，最好的 agent 评测器与 14 个目标基准的候选对排序一致率约 75%（目标基准之间的上限是 91%），开发集上最好的评测器在密封目标上并非最好。详见精读。

### 精读 · 自主研究循环的验收

**[MMPostTrainBench: Benchmarking Autonomous Research for Multimodal Post-Training](https://arxiv.org/abs/2610.05398)** · Yuxin Liu 等 12 人（中国科学技术大学、Alibaba Token Hub，合作方中国科学院大学、清华、上海交大，据 arXiv HTML 版作者栏）· 提交 2026-10-04

**问题**：让 LLM agent 自主做"后训练研究"（改数据、改训练配方、跑实验、交模型）已经在纯文本任务上有不少演示，但多模态任务能不能持续改进，没人系统测过。

**做法**：8 个任务，覆盖图像、音频、视频、音视频联合理解和"看图修代码"。所有 agent 从同一个基座模型出发，在固定预算内用开发集反馈迭代，最后提交一个模型做独立评测。评测不只看目标任务，还看**非目标任务有没有退化、迭代过程是否持续改进、最终选的是不是自己评估过的最好候选、研究过程是否诚信**。

**关键数据**：

- **52.1% 的"模型 × 任务"均值低于基座**，提交的模型普遍带非目标能力退化。
- 性能**不随研究轮次稳定上升**；agent **选不对要提交的版本**，最终提交比它自己评估过的最佳候选最多低 5.38 个百分点。
- 从纯文本扩展到多模态，多出了感知、跨模态对齐、时间定位三类新错误来源。
- 作者据此做了 MMResearch 框架（把媒体证据连到假设和干预、用分层记忆跨轮携带发现、按开发集评估保留候选），装进现成的代码 agent 运行时后，Claude Opus 4.8 + Claude Code 的提交模型准确率最多 +7.75 个百分点，GPT-5.6-sol + Codex 最多 +2.33。

**对 AI 应用工程师的启示**：

- 做"agent 自动调 prompt / 微调 / 调 harness"的系统，**版本选择要从 agent 手里拿出来**：保留每一轮候选和它的开发集分数，由外部规则（而不是 agent 的自我判断）决定提交哪一个。
- 验收要同时跑**非目标回归集**。只看目标指标，会把"目标涨了 3 分、其他能力掉了 5 分"的版本当成进步。
- "跨轮携带发现"要有结构（分层记忆），否则每轮从头试错，迭代曲线不会单调。

**[MedForge-RSI: Medical Deepfake Detection via Recursive Self-Improvement](https://arxiv.org/abs/2609.36549)** · Zhihui Chen、Mengling Feng（新加坡国立大学，据 arXiv HTML 版作者栏）· 提交 2026-09-28

**问题**：一个 8B 视觉语言检测器在训练分布上准确率 99.2%，部署后却把 40% 的真实影像判成伪造，遇到没见过的生成器只有 77%，经过传输失真只剩 59%。重新训练要大量标注和专家规则，代价太高。

**做法**：权重全程冻结。每轮让检测器分析已核实的错误、积累可复用经验、自己写图像分析工具；**一个独立的验收测试决定改动能否留下**，没过的就回滚。共跑 20 轮，注册了 49 种配置。

**结果**：

- 四个测试集平均准确率 75.0% → 84.4%。
- 留出的 4,000 张图上，干净图像 76.5% → 87.9%，传输失真图像 59.0% → 70.5%，提升最大的是真实图像的召回（也就是误报减少）。
- 跨 49 条轨迹的对照分析找出了**哪些自改进机制能跨随机种子复现**，结论是**验收测试是单项最大贡献者**；同时给出失败改动的分类。全部轨迹（包括被拒绝和回滚的改动）公开。

**对 AI 应用工程师的启示**：

- 部署后漂移是 agent 系统的常态。"冻结模型 + 经验库 + 工具自写 + 独立验收"这一套不需要重训，适合生产环境。
- 把预算优先花在**验收集和回滚机制**上，比花在更聪明的反思提示词上回报更高。
- 公开或至少内部保留**被拒绝的改动**：它们是调试自改进系统最有用的数据。

**[EvalResearchBench: Can AI Agents Design Their Own Evaluations?](https://arxiv.org/abs/2610.04184)** · Yaolun Zhang 等 6 人（Oregon State University、AG2 AI、UC San Diego、宾州州立大学，据 arXiv HTML 版作者栏）· 提交 2026-10-02

**问题**：RSI 靠评测反馈判断进展，但反复跑复杂基准又贵又慢。人类专家会挑子集或设计紧凑的评测套件，agent 能不能自动完成这件事？

**做法**：给"研究员 agent"目标材料、开发参考、可调用的 API、固定的时间和 API 预算，让它挑选或合成任务、实现评分器、做小规模试跑并修改，最后**冻结**一个可执行的评测器（覆盖编码、协作办公、推理）。测了 9 个研究员 agent、13 个候选模型，把冻结的评测器和 14 个目标基准比分数一致性和两两排序一致率。

**结果**：

- 最好的评测器对约 75% 的候选对给出与目标基准相同的排序，而目标基准彼此之间的一致率上限是 91%。
- 没有哪个研究员在所有指标上领先；**开发目标上最好的评测器，在对研究员隐藏的密封目标上不是最好的**。
- 人工挑选的公开任务样本仍是很强的基线；执行成本最低的评测器反而两两一致率最高。
- agent 会根据试跑反馈修任务和评分器，但做出来的评测器仍会截断答案、耗尽评测预算，或让少数几道题主导某个领域的分数。

**对 AI 应用工程师的启示**：用 agent 帮你搭评测集是可行的起点，但**必须留一组它没见过的密封基准**来校验它的评测器；评测器本身也需要回归测试（答案截断、预算耗尽、单题权重过大都是这篇列出的具体故障）。"便宜的评测器不一定差"也值得记住：先从小而稳的子集开始。

### 精读 · 自演进的结构与红线

**[GitSwarm: Decentralized Compounding Inference](https://arxiv.org/abs/2610.04862)** · Vedant Shah 等 14 人（Meta Superintelligence Labs，合作方 Mila、哥伦比亚大学、CMU、普林斯顿，部分作者注明"Work done at Meta"，据 arXiv HTML 版作者栏）· 提交 2026-10-04

**问题**：长时程问题和科研需要计算在多次尝试之间累积：部分解、实验发现、失败的路线都应该被后来的工作用上。但现在的推理时计算大多围绕单条轨迹或单个候选组织，做完就散。作者把"让中间工作持久保存、可被检查、扩展、组合和质疑"称为**复利式推理**（compounding inference）。

**做法**：

- **共享记忆就是一个 Git 仓库**，满足三个性质：**持久**（中间发现比作者活得久）、**可分支**（竞争路线可以并行发展）、**可溯源**（每次提交必须在 `informed_by=` 字段声明用到了哪些已有贡献，包括跨分支的）。
- **同一模型的 worker，不分角色**，各自在独立 worktree 里检查仓库、选起点、决定怎么推进。每个回合只能三选一：**贡献**一个经过校验的原子提交（校验的是格式要求，不是正确性）、**提名**一个现有候选并写理由、或者**弃权**（认为没有有用的工作可做或已有人在做；弃权不占预算）。
- harness 只负责调度执行和提供看板（剩余预算、在跑的 worker、提名票数，并注明"票数不是正确性证据"），**不分配任务、不规定阶段**。

**结果**：

- IMOProofBench-Advanced：用 GPT-5.5 一次运行解出全部 30 题。
- ProgramBench：平均 79.4%，同预算下最强已报道基线 65.1%。
- 三个神经网络架构研究任务（Residual Matrix Transformer、Looped Transformer、NanoChat）上，通过连续实验改进了起始架构；Looped Transformer 那次运行还**把一个起初被否掉的想法重新评估后救了回来**。
- **计算是否真的累积了**：ProgramBench 上 94.7% 的贡献后来被别人接着用，最终选中的解的祖先覆盖了整个贡献图的 82%–93%。

**作者自己承认的局限**：依赖关系是 worker 自报的，执行轨迹只能证明"用了"，不能证明"因此变好"；要隔离持久、分支、溯源各自的贡献，需要"同一候选、有无历史"的对照实验，论文没做。

**对 AI 应用工程师的启示**：

- 和上期 AWS 的 ARC-AGI-3 跟踪研究（630 次脚本引用只有 33 次跨任务）对照，**经验能不能被复用，关键在共享记忆的结构**：版本化、能分支、强制声明依赖。多 agent 协作时，与其设计复杂的角色和消息协议，不如先给它们一个带这三个性质的共享工作区。
- "弃权不扣预算"是一个便宜而有效的设计：让 worker 敢于不做重复劳动。
- 提名票数和正确性要明确分开，这一点同样适用于任何多 agent 投票的系统。

**[SPECTRUM: Proximal Spectral Modulation for Looped Self-Distillation](https://arxiv.org/abs/2610.07237)** · Yunbo Long 等 7 人（剑桥大学、复旦大学，据 arXiv HTML 版作者栏）· 提交 2026-10-05

**问题**：模型用自己的输出训练自己时，继承的不只是正确性，还有"它倾向于产出哪些解"。作者定义了"循环自蒸馏"：代码模型在固定信息预算下，反复用自己的原始输出训练自己，**不做外部评估、也不按测试结果筛样本**。

**关键发现**：**正确率可以在上升，同时正确实现的多样性在收缩**。用 64 次采样中正确解的 AST 结构丰富度来量化，MBPP 上五轮之后，普通自蒸馏只保留初始模型的 66.4%，子空间投影对照 65.5%。

**做法**：每轮从固定的参考锚点重新估计对损失敏感的 key/value 几何，转成全秩的近端谱调制，只在生成时干预；所有生成结果训练同一个学生，学生推理时不需要任何干预。五轮后保留 89.9% 的正确解丰富度；在正确样本数相同时优势仍在；不重新训练或校准，这个多样性优势在 HumanEval+ 和 APPS Intro 上也成立。

**对 AI 应用工程师的启示**：

- 任何"用自己的产出再训练或再沉淀"的循环（自蒸馏、skill 库自更新、prompt 自优化），**验收指标里要加多样性**：同一问题有几种不同的正确解、skill 库里有几种不同的策略。只看通过率会错过这种"越练越窄"。
- 这与 8–9 月收录的 Co-Evolving 论文"fit 被破坏"、EvoUndo 的"可恢复性"是同一类风险：**自演进的退化往往在主指标之外**。

**[EvoIn: Bridging Evolution and Internalization for Agent Fine-Tuning](https://arxiv.org/abs/2609.35290)** · Shihan Dou 等 11 人（复旦大学、中国人民大学，据 arXiv HTML 版作者栏）· 提交 2026-09-28

**问题**：现在很多"agent 自改进"工作把新工具、新决策流程、模型适配一锅炖，分不清到底是哪部分在起作用。这篇只研究一件事：**agent 怎样改进自己的决策流程**，并且让改进在去掉 harness 之后依然存在。

**做法**：三步。①分析执行轨迹，**演化出新的决策流程**，临时写进 harness 里验证；②用验证通过的流程引导 agent 生成更好的推理轨迹，再**改写成不提及 harness 指令的自洽推理**，把流程表达成模型"自己的想法"；③在改写后的轨迹上微调，把流程内化进权重，推理时不再需要演化出的 harness。

**结果**：域内通过率 +10.9 个百分点，**域外 +9.2**；内化的决策流程能泛化到没见过的任务，在另一个模型家族上也有一致提升。案例里，agent 学会了"先决定怎么做再做"，比如先看文档长度，再决定是全文读还是检索。

**对 AI 应用工程师的启示**：harness 里沉淀下来的 skill 和决策规则，不一定要永远留在 prompt 里。成熟、稳定的那部分可以**蒸馏进模型权重，腾出上下文**。关键是第②步：训练数据要把"遵守外部指令"改写成"模型自己的推理"，否则学到的是对 harness 的依赖。这和本期速览里的 D-OPCD（把 skill 内化进扩散模型后 harness 可以"卸下饱和的 skill 继续演化"）是同一个方向。

**[Assembling Insights for Agentic Machine Learning Engineering Systems](https://arxiv.org/abs/2610.04927)** · Bihui Jin 等 4 人（滑铁卢大学、Google，据 arXiv HTML 版作者栏）· 提交 2026-10-04

**问题**：agentic MLE（让 agent 自主做 Kaggle 式机器学习工程）被视为 AI 系统递归自改进的一步。已有系统会从相关任务里收集"洞见"（专家知识、往期解法、记忆）注入新任务，但做法很随意，评测也不控制洞见来源，**数据泄漏**是有效性威胁。

**做法**：MLE-InsightBench，160 个 Kaggle 比赛覆盖 12 个领域，每个领域留一个比赛做目标，其余 148 个只有在**不可能受目标影响**时才能当来源（排除后续届次、复用解法等）。再做一个洞见组装 agent，从来源比赛、人类顶尖方案和赛后总结里提炼三类洞见：12 条领域最佳实践、148 条比赛获胜方案、16 条通用调试与优化策略；注入方式分两种：**按需加载的 skill**和**开头一次性给的 playbook**。

**结果**：洞见让私有测试集归一化分数比无洞见基线**提升 123.9%**；三类洞见互补；skill 和 playbook 哪种更好因任务而异，**skill 总体更省成本**；收益在不同后端 LLM 上都成立。

**对 AI 应用工程师的启示**：评估"经验复用 / 记忆"带来的提升时，第一件事是**排除泄漏**（来源是否可能见过目标的答案）。在洞见注入方式上，这篇给了一个可直接用的结论：默认用按需加载的 skill（省 token），只有任务高度同质时才考虑一次性 playbook。

**[Recursive Self-Improvement in Unified Multimodal Models](https://arxiv.org/abs/2610.03002)** · Huijuan Wang 等 6 人（南加州大学、UC San Diego、CMU，据 arXiv HTML 版作者栏）· 提交 2026-10-02

**问题**：统一多模态模型既能理解也能生成图像，所以能给自己造训练数据。但现有自改进只在视觉一侧打转（用看图能力评判生图能力），错误会跨轮累积。

**做法**："跨能力递归自改进"：每轮模型生成图表、读图找自己的不足，然后**写程序**针对这些不足重新渲染，**执行结果对照规格逐一校验**。校验通过的渲染训练生图，带标注的渲染和模型自己写对的程序训练看图与写程序。**程序执行是模型之外的事实来源**，所以错误不会跨轮累积。

**结果**：在措辞与训练不同的请求上，四轮 RSI 把分数从 45.7% 提到 60.2%，同等继续训练只有 46.3%；大部分收益来自"经过校验的构造"，针对失败点再加 3.5%。过程中通过校验的程序比例从 48.9% 升到 95.2%，读图准确率从 55.6% 升到 87.4%。

**对 AI 应用工程师的启示**：自改进循环最怕"自己评自己"。只要任务能找到一个**可执行的外部校验器**（程序运行、测试、编译、SQL 执行结果），就用它来过滤自产数据，而不是用模型自评。

### 精读 · Agent 记忆的成本

**[When Evidence Changes: Evaluating Memory Repair and Re-reading in Language-Model Agents](https://arxiv.org/abs/2610.03902)** · Wenhui Chu（纽约州立大学奥尔巴尼分校，据 arXiv HTML 版作者栏）· 提交 2026-10-02

**问题**：agent 从文档里推出的事实存进了记忆，后来文档被撤回或替换了，应该**修记忆**还是**重新读当前证据**？

**做法**：用公开 ICU 病历上的用药清单、问题清单任务，构造撤回、替换和对照三类事件；比较全量重读、按来源过滤重读、缓存、重建和图局部修复，用两个 7B 模型。记忆全量提供不走检索，**成本把写入、修订和每次使用都算进去**。

**结果**：

- 短病历上，局部修复的修订 token 比重建少 5–10 倍，但**在留出条件下，每一种记忆流水线的总成本都至少是全量重读的两倍**。
- 预先设定的小规模开发实验里，加入与任务无关的文档把病历拉长到约 1 万 token，这时记忆的平均累计成本在被使用 2–14 次后才低于全量重读（部分原因是抽取被截断），而**按来源过滤的重读始终最便宜**。
- 替换场景下，四项预注册的主要检验没有一项显著。

**对 AI 应用工程师的启示**：给 agent 加长期记忆之前，先算一笔账：**基线不是"不用记忆"，而是"按来源过滤后重读原文"**。对于会被修订的权威文档（病历、合同、配置），记忆的维护成本可能高过它节省的阅读成本。记忆最划算的场景是原文很长、被反复查询、很少修订。

## 趋势观察

**1. 自演进研究的重心从"怎么改"移到"怎么验收"。** 9 月的论文主要在比谁的演化器更聪明；这一批里，最有分量的结论几乎都关于验收层：MedForge-RSI 发现独立验收是最大贡献项，MMPostTrainBench 发现 agent 选不对自己的最好版本，EPOCH 和 CISE 都在处理"假阳性被当成发现"，Kinetic Theory 从理论上给出"评估者必须留在被评估者之外"。这和 Anthropic 10-09 的意外行为报告、上期 KAIST"奖励几乎不起作用"的负结果连成一条线：**自演进系统的可信度取决于它之外的那部分**。面试里被问"怎么设计一个能自我改进的 agent"，答案的重点应该放在留出集、回滚、外部校验器和版本选择规则上。

**2. 多样性是自演进的第二个盲区。** SPECTRUM 的"正确率涨、解法变窄"，加上 8–9 月的 Co-Evolving"fit 破坏"、EvoUndo"可恢复性"，说明主指标之外的退化会被只看通过率的验收漏掉。实践上，自演进验收至少要加一个多样性指标和一组非目标回归集（MMPostTrainBench 的非目标退化是同一问题）。

**3. harness 能力"内化进权重"成了一个小方向。** EvoIn（决策流程，域外 +9.2）、D-OPCD（文生图 skill）、SpatialOPSD（空间编码轨迹）都在做同一件事：harness 里验证有效的东西蒸馏进模型，然后 harness 可以卸下它继续演化。这对应 09-04 Brockman 访谈里"skill 是训练轮"的说法：skill 和 harness 是能力的临时容器，成熟后进入权重。

**4. 记忆研究开始算账和找失效条件。** 本期记忆论文少有"新架构刷榜"，多的是成本与失效：重读原文可能比维护记忆便宜一半以上（When Evidence Changes）、旧值靠注意力漂移压过新值（CICM）、存储没写下生命周期状态就谁也读不对（Knowing the Store）、价值观类断言只有 77.9% 有来源支持（Category-Conditioned Retention）、部分重叠的记忆会误导推理（MEMTRIM）。这些都可以直接变成记忆系统的设计检查表。

**5. 厂商侧唯一的自演进论文来自 Meta。** GitSwarm 的贡献不在分数，而在把"共享工作区要持久、可分支、可溯源"讲清楚并给了复用率数据。和上期 AWS 的 ARC-AGI-3 跟踪研究对照，可以得出一个可操作的结论：**多 agent 经验沉淀的问题主要是工作区结构问题，不是模型能力问题**。
