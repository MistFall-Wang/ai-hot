## 本周新文章

### Anthropic

- **[Previewing the Model Hardware Standard](https://www.anthropic.com/news/model-hardware-standard-research-preview)** · 8 月 27 日 ·（发布于 Newsroom，非工程博客）

  **本期最值得读的一篇。** 解决的问题：agent 想操作实验室或工厂里的物理设备（显微镜、移液工作站、机械臂、激光器）时，每台设备各有各的编程接口，既没有统一的接入方式，也没有让 agent 安全操作它们的共同协议——一个实验室把硬件接起来通常要几周到几个月。MHS 的做法**和 MCP 是同一个套路，只是把「工具」换成了「硬件」**：① 定义一套标准化 driver，只暴露极少的原语（`read`「读温度」/ `write`「设温度」），任何设备都能实现；② 设备以标准格式**可被发现**，agent 与设备跨网络互相找到，不需要中间的定制翻译层；③ driver 里带**自然语言 tag**，把过去只写在纸质手册里或存在老工程师脑子里的隐性知识（比如机械臂自重、安全限位）写进去，自动生成一份 agent 可读的设备说明文件——用户可以自己写，也可以让 agent 采访自己来写；④ 三种控制通道并存：MCP、CLI、代码文件（API）。

  最值得 AI 应用工程师抄的是**「探索 → 固化」这个执行模式**：Claude 先像科学家一样调一下激光、用摄像头看结果、再调——把过程摸清后，把学到的东西打包成一个确定性脚本，此后整套对准动作一条命令跑完，不再需要每步推理。这正是「在线推理贵且慢，就用推理去生成确定性代码，把热路径交给代码」的通用解法（对照 Anthropic 自己的 *Code execution with MCP*）。合作方数据也很硬：CMU 用 MHS 从零写四台异构设备（机械臂、移液器、酶标仪、监控摄像头，分布在三台互不兼容的电脑上）的 driver + 编排层到跑完一条稀释曲线，**共 8 小时**，而找厂商做同样的集成通常要数周；其中酶标仪那一版软件**完全没有 API，MHS 就像人一样直接驱动 GUI**。QuEra 让 agent 接管量子计算机激光系统，自主恢复激光锁频成功率 **99.3%**。文章同样诚实地写了边界：Claude 的空间与物理推理有限（Genentech 遇到样品起泡时，要人教它这是物理故障而不是软件 bug），且尚不支持无编程接口的硬件。启示：**agent 的下一个战场是「协议化地接入世界」**，而通用配方永远是这三样——统一原语、可发现性、把隐性知识显式写进机器可读的说明。面试里聊 MCP 时，把 MHS 当作「同一设计范式向物理世界的延伸」举例，会比只背 MCP 三件套加分。

### Google

- **[Decoding cosmic signals with deep learning and Keras](https://developers.googleblog.com/en/decoding-cosmic-signals-with-deep-learning-and-keras/)** · 8 月 27 日

  偏建模、不涉及 agent，但这是本期唯一一篇讲**「怎么把领域知识编码进网络结构」**的硬工程文，对做垂直领域 AI 应用的人有直接价值。问题背景：Pierre Auger 天文台用 1660 个地面探测器捕捉宇宙线在大气中产生的粒子簇射，传统方法把每个探测器的波形压缩成「总电荷 + 到达时间」两个数，**信息在特征工程这一步就丢光了**。方案是端到端训练一个 Keras 模型直接吃原始时空数据：以最大信号站为中心裁出 13×13 的站点网格，每站 3 条波形 × 120 个时间步（25ns 一步，共 3 微秒）。四个设计决策值得记：① **时空解耦**——站间距 1.5 km，波形之间因果独立，所以先用一个**跨全部 169 个站共享权重**的双向 LSTM（`TimeDistributed`）把每站波形压成 10 维特征，再交给空间模型，既物理正确又极省算力；② **六边形群等变卷积**——探测器阵列是六边形且簇射沿方位角旋转不变，于是让卷积核不仅跨位置共享、还跨 6 个旋转方向共享，参数效率直接来自物理对称性；③ **缺失要显式建模**——「探测器坏了没数据」和「探测器好好的但没测到信号」在物理上完全不同，所以额外喂一张 status map（1= 正常，0= 缺失），训练时主动 mask 站点来教会模型这件事；④ **多任务塔**——能量、质量、到达方向共享 DenseNet 主干、各自出头，联合训练同时改善了泛化和训练稳定性。结果：可用观测数据量提升 **10 倍**，等价于同一台探测器多跑一百年，且推翻了「最高能宇宙线是纯质子」的旧假设。文末两段更值得读：作者承认**模拟数据与真实探测数据的域偏移**是这条路线的主要天花板（必须靠 domain adaptation + 独立探测器交叉标定 + 严格的不确定度量化），并直面 Sutton 的「苦涩教训」——今天他们会用 GNN / point cloud transformer 取代 CNN+LSTM，物理归纳偏置可能只是数据不足时的中间态。启示：**当训练数据昂贵到「模拟一个事件要一周」时，把对称性和缺失语义写进架构就是最高杠杆的工程动作**；而当数据变便宜，先撤掉的也正是它。这条张力对所有做小数据垂直场景的人都成立。

## 论文速递

> 自本期起新增小节：收录各厂商研究团队以论文形式发布的、与 agent 工程直接相关的前沿工作。官方博客越来越滞后于 arXiv，只盯博客会漏掉最先进的东西。

- **[WikiSkill: Compiling Agent Experience into Persistent Knowledge for Skill Evolution](https://arxiv.org/abs/2608.27454)** · Google（Liyan Tang, Cyrus Rashtchian, Chun-Sung Ferng, Andrew Tomkins, Da-Cheng Juan, Tu Vu）· 8 月 27 日提交

  **skill 自进化方向目前最系统的一篇。** 解决的问题：让 agent 从自己的执行经验里自动进化出 skill（SKILL.md 那种文件系统模块）这条路线已有 EvoSkill、Trace2Skill、SkillOpt 等方法，但它们学到的教训都**散落在优化历史里**——一次迭代的洞见没有沉淀成可复用的知识，下次迭代还得从 trace 里重新挖。WikiSkill 受 Karpathy「LLM Wiki」构想启发，在原始经验和可执行 skill 之间插入一个**持久知识层**，把工作区分成三层：`raw/`（不可变的完整执行轨迹）、`wiki/`（结构化知识：patterns/ 里一个失败模式或成功策略一个 md 文件，外加 logs.md 进化日志和 skill-impact.md——由外层 harness 程序化记录每次 skill 提案的 diff、验证分数和采纳结果，构成客观审计轨迹）、`skills/`（当前生效的 skill，每个附一份 PURPOSE.md 回链到启发它的 wiki pattern）。进化循环四个角色：Inference Agent 带着当前 skill 跑任务、Wiki Maintainer 把轨迹里的模式合并进 wiki、Skill Proposer（ReAct 式，按需读 pattern 和 trace）每轮提**一个原子化** skill 修改、Gating 用验证集分数决定采纳或回滚——关键设计是 **skill 可以回滚，wiki 永不回滚**，知识只增不减。

  三组数据最值得记：① 收益随模型规模**递增**——Qwen 家族 4B/9B/27B 平均提升 +12.3/+17.5/+23.9 分，且 9B+skill（47.4%）反超 27B 裸模型（39.4%），说明进化出的程序性知识和模型规模是互补的两条腿；② **skill 可跨模型迁移，且别人进化的有时比自己进化的还好用**——ALFWorld 上 Qwen-9B 用 27B 进化的 skill 拿 70.2%、用自己进化的只有 63.4%，作者由此拆出一对常被混为一谈的能力：「发现程序性知识」和「执行程序性知识」是两回事（但也有反例：4B 进化的 skill 里全是给小模型兜底的低级 workaround，会把 Gemini-Flash 在 SpreadSheet 上从 50.5% 拖到 18.1%）；③ 消融实验里最反直觉的一条——给 Skill Proposer 开放 wiki 平均 +15 分（48.7%→63.7%），但**给 Inference Agent 在训练 rollout 时开放 wiki 反而掉分**（63.7%→60.9%）：agent 直接从 wiki 抄答案解题，轨迹就不再暴露 skill 的真实缺陷，进化信号被污染了。

  启示：这套「经验 / 知识 / 程序三层分离 + 知识永不回滚 + 程序受验证门控」的架构，就是你在 Claude Code 里手工维护 memory 文件和 CLAUDE.md 的**系统化、可评测版本**；而「训练时隔离知识层以保住进化信号」这条，对任何做 self-improvement pipeline 的人都是一个此前没人明说的坑。面试聊 agent 记忆/自进化时，用「WikiSkill 把 EvoSkill 们的散落经验升级成持久知识层」一句话就能定位整个方向。

## 趋势观察

本期两篇同日发布、看似毫不相干，其实指向同一件事：**AI 工程正在往「模型之外」的两端同时扩张**。MHS 往外扩到物理世界——Anthropic 把 MCP 那套「统一原语 + 可发现性 + 机器可读说明」原封不动搬到硬件上，还补了一条只有物理世界才需要的东西：把安全限位和设备自重这类隐性知识用自然语言写进 driver。值得注意的是它**没有发在工程博客而发在 Newsroom**，但内容密度（driver 原语、三种控制通道、合作方的真实集成耗时与失败案例）完全是工程长文规格——这提示以后不能只盯 `/engineering`。Keras 那篇则往里扩到架构层：在数据昂贵的领域，**归纳偏置就是数据增强的替代品**，而作者又老实承认这是「苦涩教训」下的中间态。两篇合起来是同一个母题的两面：**通用能力不够用的地方，就用结构去补**——对硬件是协议结构，对模型是架构结构。

另外，上期观察到的「三家安静、Google 独跑」格局本期出现松动：**Anthropic 工程博客虽仍停在 4 月 23 日（已连续四个月），但 Newsroom 端拿出了一份实打实的新协议标准**；Google 本期只产出一篇且是纯 ML 建模文，agent 方向反而空窗；OpenAI 开发者博客本期唯一新帖是生命科学产品发布；xAI 继续全是上架公告。如果把 MHS 计入，Anthropic 实际上是本期唯一给出**新抽象**的厂商。下期继续观察 Anthropic 工程博客是否复更。另外，本期起新增的论文速递恰好补上了官方博客的时间差：WikiSkill 讲的 skill 自进化正是 Anthropic《Agent Skills》和 OpenAI《Testing Agent Skills with Evals》两条博客线的下一步——skill 从「人写、评测」走向「agent 自己从经验里进化出来」，而它依赖的三层知识架构又和 MHS 的「把隐性知识显式写进机器可读文件」是同一个母题。
