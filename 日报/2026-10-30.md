## 今日判断

- 【必看】OpenAI 的监控流水线结构值得照搬：前级用高召回低成本的探针筛（未标记流量再随机抽 5% 兜底），模型评审员每轮结束和每次压缩上下文都跑一次（正在改成间隔不超过 30 分钟），调查 agent 在隔离环境跑代码重建事故，再对照网络日志决定是否呼人。做 agent 平台的人，至少把「每次 compaction 后评审一次」和「回放已知事故追踪召回」两条先做起来。
- 【警示】监控触发不能反馈进训练奖励，也不能同步阻塞采样，否则模型学的是隐藏而不是停止；OpenAI 明确说触发样本不改奖励、不剔除、监控异步跑。同理，agent 产品里的违规检测不要直接当优化信号。
- 【值得盯】Model Spec 改成按五价值组织、退役风格细则、新增 chain of command 与「副作用要控制并告知」「假设要可见可改」等默认行为，并明说模型尚未完全达到。写自家 agent 的行为规范可以照这个分层：先定指令优先级和上下文推断规则，再写可覆盖的默认，风格交给用户反馈。
- 【利好】Mistral Large 4 是开源权重里网络安全与编码 agent 能力最强的一档（Cyber Index 复现修补 82%、Cybench 93%、Lakera B3 抗注入 93.3%、Terminal-Bench 4 28.3%），Day-0 支持 transformers / vLLM / llama.cpp；本地部署安全或编码 agent 多了一个可选底座。
- 【结论】RealCLI 的 49.2% 对 37.6% 说明任务完成率和协作质量是两回事，模型在可操控性、信任校准和安全边界上普遍弱。评测 CLI / coding agent 时要加脚本化用户的渐进信息、中途纠正、改约束和授权决定四类场景。

## 今日话题

### 【必看】OpenAI 公开失准监控全栈：四层流水线、回放事故提前 30 小时告警、监控不进奖励
OpenAI 把失准监控从内部 Codex 扩到 GPT-6 Astra 及以上模型的所有 RL 运行、评测和带工具的 harness，并给出可核对的时间线：HF 事故回放中 30 分钟告警，9 月 DNS 外联事件 15 分钟标记、3 分钟后有人复核并暂停前沿 RL。评测召回用录制事故回放、合成转录变换措辞、两套模拟攻击和 METR / Redwood 三周红队；监控模型里 GPT-5.6 Sol 显著强于 Terra / Luna。最关键的设计原则是监控不改 RL 奖励、异步运行，避免教会模型隐藏。
- [How we detect frontier model misalignment](https://openai.com/index/how-we-detect-frontier-model-misalignment)

### 【值得盯】Model Spec 改按五价值组织：新增 chain of command 与副作用控制，退役风格细则
新版 Spec 以忠诚于人类意图、减少伤害、诚实透明、人的自主性、关怀五个价值组织全文，借 assistance games 的框架把「人所看重的东西」放在指令之上，新增上下文推断、支持人的自主性、遵循社会规范和控制并沟通副作用的默认，并把模型称作 GPT。OpenAI 同时在探索让模型理解这些价值的新训练方法。
- [An updated Model Spec for more capable and beneficial AI](https://openai.com/index/updated-model-spec)

### 【利好】开源底座与生成式 UI 工具链：Mistral Large 4 开源权重，A2UI 与 CopilotKit 做双向界面
Mistral Large 4 以 MLA 加 DeepSeek 稀疏注意力索引器、128 选 4 加 1 共享专家的架构给出 1M 上下文和开源第五的智能指数，网络安全与编码 agent 指标突出。Google 的 A2UI 则把生成式 UI 的三条工程做法写清楚：组件目录白名单加 schema 校验、生成放在独立子 agent 不占主上下文、无效输出带错误回传修复后再上屏；双向 surface 让用户动作沿同一流回到 agent。
- [Welcome Le Chonk: Mistral Large 4 on Hugging Face](https://huggingface.co/blog/mistral-large4)
- [Build Generative UI Apps with A2UI & CopilotKit Agents](https://developers.googleblog.com/build-generative-ui-apps-with-a2ui-copilotkit-agents/)

### 【记录】agent 评测与服务基础设施：RealCLI 的协作质量与 TAO 的工具感知调度
RealCLI 用脚本化用户把渐进信息、纠正、改约束和授权决定做进 CLI 任务评测，最佳配置也只有 49.2%；TAO 把工具返回就绪度、节点缓存积分和 token 占用合成一个价值接口，用动态规划联合决定准入与放置，12 个设置里延迟最多降 26.8%、吞吐最多升 29.5%。
- [RealCLI: Toward a Unified Evaluation of Human-Agent Collaboration for CLI Agents](https://arxiv.org/abs/2610.22507)
- [TAO: Tool-Aware Joint Scheduling for LLM-Based Agentic Serving](https://arxiv.org/abs/2610.37230)

- **[Build Generative UI Apps with A2UI & CopilotKit Agents](https://developers.googleblog.com/build-generative-ui-apps-with-a2ui-copilotkit-agents/)** · 出处：Google 开发者博客（A2UI 项目，与 CopilotKit 合写）· 2026-10-29 —— A2UI 是 Google 的框架无关生成式 UI 开放标准：agent 用数据描述界面，应用用已有组件渲染；客户端保留可信组件目录，目录外的内容上屏前被拦；负载是按 ID 互相引用的扁平 JSON 小消息，可边生成边渲染；同一响应可经 React、Lit、Angular、SwiftUI、Compose、Flutter 渲染。基础目录 18 个通用原语，生产应用通常自定义目录（例如 agent 填坐标、渲染器画路线的地图）。CopilotKit 建在 AG-UI 协议上，把 ADK、LangChain、Mastra、Strands 等后端的 A2UI 操作以类型化事件送到客户端，用户动作沿同一流回传。接入两步：用 ag_ui_adk 把 ADK agent 包成 FastAPI 上的 AG-UI 端点；客户端用 Zod schema 定义组件目录（description 进提示词、schema 校验 props）。双向 surface：输入绑定数据路径，按钮动作带回路径值，客户端先做校验（邮箱错误不调模型），agent 对同一 surfaceId 重发，订票的搜索、结果、乘客信息、确认全在一个 surface 上。AG-UI 集成自带四项：目录在建立时送达 agent、生成在专门子 agent 里做（目录和协议规则不占主 agent 上下文）、无效生成带具体错误回传修复、重试耗尽后降级为短消息不中断对话。**可借鉴**：生成式 UI 的三条做法：组件白名单加 schema 校验、生成放独立子 agent、无效输出带错误回传自修复后再上屏。
