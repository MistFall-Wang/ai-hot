## 今日判断

- 【必看】OpenAI 探针的三步设计（推理流里逐 token 打分 → 越阈值停流并挂起工具调用 → 交更强模型复判）是做 agent 安全栅栏的现成模板；外挂文本分类器退到第二层，因为它既慢又容易被编码绕过，而探针状态只有 O(头数)、更容易做 fail-closed。
- 【利好】harness 本身可以被自动优化而不动模型权重：RoboArchitect 4.5 倍、MetaVul 帕累托搜索、EvoMCP 三基准 +10–16.5 分。落地的最低配置是 RoboArchitect 那种「在训练 episode 上进化、在 held-out 场景上验收」的分离，否则进化出来的只是对训练集的记忆。
- 【警示】CLR-Bench 说明自演进不等于学会规则：六种方法 75–98% 只往状态里记被揭示的个例、几乎不记类名，最多比冻结 agent 高 5 分，还不如保留原始历史。验收自己的自演进系统时要查状态是在归纳还是在加长例外清单，并注明基座模型，因为换成 GPT-6-Sol 同样方法就到 78%。
- 【值得盯】Claude 消息线程把长会话 agent 的首 token 时间压了三分之一，但线程 5 分钟过期、内存态不落盘，客户端必须保留「过期或失败即全量重发」的回退逻辑；token 计费不变，省的是延迟不是钱。
- 【结论】评测正从学术基准转向真实任务流：LifeVal 从时间使用调查选任务、HALO 用 20 名专家标 8,000 条主动性回复、xAI 用「一周承接 70 小时工作」衡量 Data Bot。做 agent 产品的评测集应从用户时间花在哪出发，并把每个任务定义成要用工具真正完成的动作。

- 【必看】**[Training activation classifiers for safety and alignment](https://alignment.openai.com/training-activation-classifiers/)** · 出处：OpenAI Alignment 研究博客（alignment.openai.com）· 2026-11-02 —— OpenAI 首次成体系公开生产中的「激活探针」：从 GPT-5.6 起所有助手输出都经过一个读取模型中层残差流激活的轻量分类器，与文本分类器、模型复审、自动调查、人工响应并列为失准监控的一层。架构是注意力探针（MLP + QV 注意力）加指数滑动平均，流式状态从 O(窗口 × 头数) 降到 O(头数)；训练时用 softmax 聚合各前缀分数而非硬 max，召回率 / 标记率帕累托前沿更好；训练数据最多 100 万条消息、标签由推理模型评审给出；每组超参至少跑 32 个随机种子，因为约 85% 的性能方差来自初始化。部署上探针在推理引擎内逐 token 输出 logit，越阈值立即停流、工具调用挂起并升级到推理模型复判。实证：跨后训练阶段迁移好、跨预训练检查点迁移差，需按基座模型重训；对未针对探针优化的越狱比文本分类器更稳；探针精度随被监控模型能力一起上涨。**可借鉴**：agent 栅栏按「流式打分 → 越线停流并挂起工具调用 → 交更强模型复判」三步设计；探针只需单层激活、状态 O(头数)，比外挂文本分类器更容易做 fail-closed。
