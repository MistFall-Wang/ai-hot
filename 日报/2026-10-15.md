## 今日判断

- 【必看】选模型要按「每个有效结果的成本」算，不是按单价算：OpenAI 清理过期实验时，Sol Ultra 拿到 Astra 92% 的发现，成本只要 14%；NVIDIA 只改工具描述就把轮次从 155 降到 53。上线 agent 前，先在一个小任务上横向比较模型和 effort，再用错误模式反过来修 prompt。
- 【结论】agent 可靠性大部分来自工具层，不来自模型：Siemens 的 agent 没有换模型，只是合并重叠的 file/shell 接口、给工具输入加明确的 JSON schema，验证分数就从约 55% 涨到约 95%。排查 agent 失败时，先查 MCP 工具描述和 skills。
- 【利好】agent 可观测性进入标准件阶段：Claude Platform 按 OpenTelemetry GenAI 语义约定导出 trace，Langfuse、Datadog、Grafana 等十几家工具可以直接接。自建 agent 平台时，trace 字段直接按 OTel GenAI 约定定义，以后不用重新埋点。
- 【警示】让 agent 自己决定记什么会很不稳定：RBC 论文发现，同一套流程写出的 playbook 可能比完全不用 playbook 还低 69.6 分。做 agent 记忆时，经验条目要经过对照实验验证，不能让 agent 自己说了算。
- 【值得盯】「agent 造环境训练 agent」开始有硬数据：Microsoft 的 AutoEnvScaling 让同一个模型既出题又解题，有效环境率最高提升 25 倍；WorkRover、ClawLoop 同一天也在做环境和任务的自我演进。RL 环境的供给可能很快不再依赖研究员手工设计。

- 【必看】**[Maintaining software with the GPT-6 family](https://developers.openai.com/blog/maintaining-software-with-the-gpt-6-family)** · 出处：OpenAI 开发者博客（Codex）· 2026-10-14 —— OpenAI Core Experimentation 团队的维护实践。删死代码：以前靠复杂的静态分析加运行时日志，GPT-5.6 Sol 时代要给出明确的范围和验证标准；GPT-6 Astra 能处理一句带错字的模糊指令，会自己翻历史 PR、Slack、项目追踪和生产 profiling 表来证明代码确实没人调用。5 名工程师两周业余时间合了 1,400 多个 PR、删了 80 多万行，一个容器镜像从 3.31 GB 降到 1.72 GB。清理过期实验时，Astra 用 CPU 埋点给发现排优先级，找出一个把测试开关映射到所有 feature 的「Permanent」flag，删掉后主服务 CPU 省 0.42%。同一个任务（6,000 个文件、100 万行）横向比较：Astra Ultra 花 $109 找到 142 个，Sol Ultra 花 $15 找到 131 个，Sol Medium 花 $5 找到 86 个。另外有约 30 个 CI 优化 PR，中位 CI 耗时从 10 分钟降到 4.5 分钟。**可借鉴**：用「每个有效发现的成本」来选模型和 effort；先拿一个小维护任务做试点，把 review 意见写回下一版 prompt，再按「子目录、项目、整个代码库」的顺序扩大；遇到便宜模型的系统性漏检（比如常量 flag 依赖），用 prompt 补上。
- 【注意】**[Optimizing Agent Reliability and Tool Calling Efficiency for Chip Design Using NVIDIA NeMo Gym](https://developer.nvidia.com/blog/optimizing-agent-reliability-and-tool-calling-efficiency-for-chip-design-using-nvidia-nemo-gym/)** · 出处：NVIDIA 开发者博客（Agentic AI）· 2026-10-14 —— Siemens Solido 标准单元表征 agent 通过 MCP 和 skills 接入 Claude Code、Codex、Cursor 等 harness。它的难点是：出错时常常产出「看起来合理」的结果，而不是直接报错，早期的配置错误会一路传到最后。团队用 NeMo Gym 搭了一个可复现的评测环境（版本化任务、干净初始状态、记录轨迹），验证器按覆盖率、文件有效性、数值精度、完整性（防止 agent 复用或截断已有结果）四道门打分，任意一道不过就记 0 分。模型固定为 Claude Opus 4.8，跑了约 25 次 rollout，期间不断修改 skills 和 MCP 工具描述：合并重叠的 file/shell 接口，给工具输入写明确的 JSON schema。最后综合分从约 55% 升到约 95%，轮次从 155 降到 53，输出 token 从约 81K 降到 29K。**可借鉴**：验证最终产物，不要只看每次工具调用是否成功；验证器里专门加一道「防作弊」门；agent 不可靠时，先合并重叠工具、给参数写 schema，再考虑换模型。
- 【注意】**[Analyzing technical documents with Deep Review](https://research.google/blog/analyzing-technical-documents-with-deep-review/)** · 出处：Google Research 博客 · 2026-10-14 —— Google 把内部的 Paper Assistant Tool 升级成 Deep Review 正式发布。它在 STOC 2026、ICML 2026、NeurIPS 2026、ICLR 2027 四个会议做过试点，现在每人每周免费审 2 份文档，也可以用 Gemini API key 走 API 接入 CI。文章指出单次 LLM 调用审长文档会出三类问题：推理预算耗尽、漏掉跨章节依赖、对细微的论断不加审查就接受。解决办法是一条四阶段 agent 流水线：分段 agent 把文档切成可以重叠、但必须完整覆盖的逻辑段；每段由一个专门的推理 agent 并行审查（能看到全文，但只负责自己那一段）；最后由综合 agent 汇总，做跨段一致性检查，必要时重跑逻辑校验，并调用外部检索做事实核验防幻觉。同时在 Antigravity 的 Teamwork 框架里提供了同款「Deep Document Review」模式。**可借鉴**：长文档审查和长代码 review 可以用「全文可见、按段负责、并行核验、最后统一综合和外部校验」这个结构，代替一次性把整篇塞进 prompt。

- **[Putting Earth AI to work: Geospatial agents for our planet's biggest challenges](https://research.google/blog/putting-earth-ai-to-work-geospatial-agents-for-our-planets-biggest-challenges/)** · 出处：Google Research 博客 · 2026-10-14 —— Google 把 Earth AI 的地理空间推理 agent 从原型推进到实验系统，同时发布技术报告（arXiv 2610.15750）和两个新基准 GeoKTools、GeoExpertQueries。agent 把 WeatherNext、洪水预测、人口动态等基础模型包装成按需调用的模块化 skills，复杂操作前先生成分步计划，覆盖不足时选备用数据集，大图层在专门的工作区里处理，不塞进上下文。评测有两个结论：只给网页搜索、地图和代码执行的 agent 在定量空间任务上表现差，加上领域 skills 后在三个基准上明显提升；开放式问题还需要先做计划，否则多步分析会跑偏。另外开放了 agent-to-agent API 的早期访问。**可借鉴**：领域 agent 的三件套是「按需加载的领域 skills、先做计划、大数据放工作区不进上下文」，可以直接用在数据分析类 agent 上。

## 论文（自演进优先）

- ⭐ **[Harness^2: Recursive Agent Harnessing for an Open World](https://arxiv.org/abs/2610.14224)** · Ruiyao Xu 等 9 人（HF 组织 Google）· 2026-10-09 · HF ↑77 —— 开放世界任务在设计 harness 时没见过，也没有标准验证器，现有的递归自改进方法很难用。Harness^2 分两层递归：任务层用对比式的「提出、探测、组合」步骤改当前任务的 harness，不需要标准答案，也能并行或串行加预算；harness 层从这些修改中提炼经验，更新一个持续改进用的 harness，让下一个任务适应得更快。在三个专业基准、四种模型和 harness 组合上，只做一步就能提升 GLM-5 和 Gemini 3.5 Flash：WorkBuddy-Bench 最多 +11.5，JobBench +4.5，LAB +11.8 个百分点。**可借鉴**：没有验证器时，可以用「多个候选修改互相对照探测」代替打分，再把每次修改的经验单独沉淀成可复用的改进层。
- ⭐ **[AutoEnvScaling: Automating the Data Flywheel with Terminal Agents](https://arxiv.org/abs/2610.14163)** · Simon Yu 等 11 人（HF 组织 Microsoft）· 2026-10-09 · HF ↑10 —— 把「设计 RL 环境」本身当成一个终端任务：出题 agent 根据正在训练的解题 agent 的 rollout 造新环境，解题 agent 的新 rollout 再指导下一轮。和只靠 prompt 生成相比，有效环境率最高提升 25 倍，每个有效环境的成本最多降 75%。用 GPT-5.6 Sol 造的环境训练 Qwen3.5-35B-A3B，Terminal-Bench 2.1 比同等基线高 4.3；让 Qwen3.6-35B-A3B 同时当出题者和解题者，TB 2.1 提升 12.2，TB 4.0 从 1.6 升到 3.2。方法也能推广到软件工程、计算机使用、GPU kernel 等领域。**可借鉴**：让 agent 在真实终端里造环境、跑验证，比让模型在 prompt 里直接写环境可靠得多；环境的难度要根据当前策略的 rollout 动态调整。
- ⭐ **[ClawLoop: Self-Improving Agents via Harness-Native Training Loop](https://arxiv.org/abs/2610.14118)** · Hansi Yang 等 7 人（HF 组织 Meituan LongCat）· 2026-10-09 · HF ↑19 —— 针对沙箱或 shell 型 harness agent 的后训练。现有流程大多是一次性的，依赖更强的教师模型。ClawLoop 把三个阶段串成一个循环：任务合成（两种构造方式，根据诊断结果加大难度，再经过不带 agent 和带 agent 两种验证）、训练（SFT 或 RL）、诊断（分析 rollout 生成能力报告，作为下一轮出题依据），全程不用外部教师。以 Qwen3.6-27B 为循环模型，SkillsBench、Claw-Eval-Live、ClawGym-Bench 都有提升，生成的任务迁移到 4B 和 9B 小模型上也有效。**可借鉴**：「能力诊断报告、定向出题、训练」的闭环里，诊断报告是关键，它决定下一轮练什么。
- ⭐ **[WorkRover: Scaling Long-Horizon Cowork Agent Training Via Recursive Environment Evolution](https://arxiv.org/abs/2610.18067)** · Hang He 等 17 人（HF 组织 Nex AGI）· 2026-10-13 · HF ↑64 —— 用构造 agent 一起生成工作上下文、可执行任务和基于证据的验证器，并让三者保持一致。环境有缺陷时，用 Factorial Compatibility Replay 对各组件的修订组合做依赖闭包重放，选出最小的有效修复；训练时用 VTCA 把确定性的工作区进度检查分摊到前置轮次，做细粒度归因。WorkRover-35B-A3B 比基座在 JobBench 上 +26.27 个百分点，OfficeQA Pro +29.32，GDPval v2 +413 Elo。**可借鉴**：环境、任务、验证器要一起修订、一起验证，改一个就要重放检查依赖它的部分。
- ⭐ **[ReTerm: Recovery Training for Self-Improving Terminal Agents](https://arxiv.org/abs/2610.18484)** · Wei Xie 等 6 人 · 2026-10-13 · HF ↑18 —— 终端 agent 长时间执行时经常没法从命令错误或错误实现里恢复。ReTerm 先用 ReTerm-10K 恢复演示数据做 SFT 冷启动，再用 ReTerm-GRPO 从 agent 自己的失败状态分叉出多条独立的恢复尝试，以是否最终完成任务作为奖励。ReTerm-9B（基于 Qwen3.5-9B）在 Terminal-Bench 2.0 上 Pass@1 达 34.8%，比基座高 14.6 分，各类错误的恢复率都高于普通 GRPO。**可借鉴**：从失败状态分叉重试，比从头采样更能集中练「出错之后怎么办」。
- ⭐ **[Reliable Memory from Unstable Growth: Curating Self-Written Agent Playbooks with Randomized Experiments](https://arxiv.org/abs/2610.18427)** · Hoang Pham 等 5 人 · 2026-10-13 · arXiv 关键词补扫 —— ACE、Dynamic Cheatsheet 这类系统让 agent 每次任务后自己写经验，存进 playbook。作者发现由 agent 自己判断哪些经验有用会很不稳定：同一套流程写出的 playbook，可能比完全不用 playbook 还低 69.6 分。RBC 把相关经验分成足够大的块，在练习任务上随机决定每个块用或不用，用有无该块的成功率差来估计它的效果，只保留有用的块；同时养几份 playbook，在新的练习集上选「筛选后、完整、不用」三者中最好的上线。实验覆盖两种记忆系统和三个模型。**可借鉴**：agent 记忆要用 A/B 式随机对照来验证，不能让 agent 自己说了算；同时保留「不用记忆」这个选项作为兜底。
- **[Agent-Reflex: Teaching Language Agents to Act Reflectively](https://arxiv.org/abs/2610.17953)** · Guanting Dong 等 12 人（HF 组织 RUC NLPIR）· 2026-10-13 · HF ↑192 —— 针对 MCP 工具返回噪声、用户中途纠正的情况，分三步训练反思能力：往环境里注入工具反馈扰动，从成功和失败配对中挖出可复用的「反思元技能」；把元技能转成 SFT 监督；再用 RL 加反思引导的在线蒸馏。Qwen3-8B 在五个长程工具基准上综合 58.6，AgentNoiseBench 29.1。**可借鉴**：评测 agent 时主动往工具返回里注入噪声，看它会不会发现问题并纠正。
