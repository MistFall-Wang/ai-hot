## 今日判断

- 【必看】"模型一直做不对"的题先怀疑题本身：SWE-Gym 里 9B 基座从未解出的任务有 74% 是测试误判，而有时能解出的任务只有 20%。维护评测集时把全失败的题单独拉出来，人工或用另一个模型重新写一个正确解去跑测试，再决定留、修、删。
- 【警示】不要让 agent 在没有任务反馈的情况下反复改写 skill：所有被测模型在所有基准上都变差，SkillsBench 三十轮后平均降 15 分，最先丢的是模型自己不会写的专家知识。自动维护 skill 必须带验证任务，每次改写都跑一遍，不升就回退。
- 【利好】skill 可以由 MCP 服务器分发了：工具说明只讲"能做什么"，skill 讲"怎么做一件事"，按需加载且随服务器更新。做 MCP 服务时，把常见的多步流程写成 skill 一起发布，用户端不用单独安装。
- 【结论】同一个模型换一套动作接口，成绩能差一倍：RUIBench 只换机器人使用接口，前沿 agent 成功率从 45% 变到 81%；AutoPILOT 让模型写一段能自己继续跑的控制程序，实时游戏成功率从 38.3% 升到 68.6%。比较模型前先固定 harness，优化系统时先改接口再换模型。
- 【值得盯】按路径分级的自动审批有了可抄的配置：先用"只观察"跑一到两周，重点看"策略会批准、但评审人要求修改"这一类，修好规则再强制。注意 Claude 的批准在 GitHub 上算真实批准，分支规则要一起改。

## 今日话题

### 【必看】奖励标签也会错：三个团队都在审计"谁来判对错"
AMD 团队逐题执行验证 SWE-Gym 的测试，上海交大团队量评审器覆盖面对 GUI agent 训练的影响，HEP-Ex-Bench 用程序生成的封闭数据集和注入信号来检验整条分析流程。共同结论是：只用参考解验证过的评审器不够，要主动找"正确但被判错"和"错误但被判对"的情况。SMB Bench 则说明诊断出问题、改变行为、改善结果是三件要分开量的事。

### 【警示】自演进要靠外部反馈：没有验证的自我改写会退化
Litao Guo 等人的系统研究给出了明确的负面结果，skill 在无反馈改写下会向模型自己的先验靠拢。Self-WSP 显示模型改自己的权重有时能大幅提分，但它并不理解自己的修改，随机搜索有时效果相当。反过来，MMMem、Embodied-Harness、MORSE 三个有效的系统都带外部证据：已完成的任务、真实执行记录、留出的验证数据。
- [How Feedback-Free Self-Evolution Reshapes Agent Skills: A Systematic Study](https://arxiv.org/abs/2611.25534)
- [Self-WSP: Can Language Models Improve Themselves Through Weight-Space Programming?](https://arxiv.org/abs/2611.28833)
- [MMMem: Self-Improving Agents with Task-Aware Multimodal Experience Consolidation](https://arxiv.org/abs/2611.30287)
- [Embodied-Harness: Towards Recursive Self-Improvement for Robotic Manipulation](https://arxiv.org/abs/2611.27689)
- [MORSE: Optimizing Streaming Memory Design via Open-World Auto-Research](https://arxiv.org/abs/2611.30011)

### 【结论】harness 的关键是怎么把模型输出变成动作，越简单的接口越占便宜
AutoPILOT 让一次模型调用产出一段能持续运行的控制程序，RUIBench 横向比较 13 种机器人接口，Embo-Harness 得出"少写手工计划和 skill，多用模型原生的看图和调用工具能力"，VideoJSON 用"每分钟一条 JSON 记录加 agent 自己写搜索程序"超过专门设计的视频记忆系统。四篇都发现，减少不必要的决策次数、保留必要的反馈，比加更多组件有用。

- 【必看】**[A practical guide to shipping with Claude Code](https://claude.dev/blog/the-work-after-you-open-a-pr/)** · 出处：Anthropic · claude.dev 开发者博客（Playbooks）· 2026-11-24 —— Claude Ship 的实操指南，写给没有管理员权限的开发者和技术负责人，按"自己的 PR、仓库、团队"三层推进。第一层用 `/code-review`、`/ship`、`/steward` 在本机会话里评审、开 PR、看护 PR，最多看护七天，同一个问题最多推三次，修不好就上报作者；重新设计、没解决的安全问题也上报。第二层把反复出现的东西写进文件：代码约定放 CLAUDE.md，评审规则放 REVIEW.md，启动和操作应用的步骤写成 verify skill，PR 维护规矩写成 steward skill；他们团队的门槛是同一模式在至少 2 个 PR 上出现才考虑立规则，并由人批准。第三层是 approvals.yml：按路径定需要几个人批准，先用 observe 模式跑一到两周，拿"策略判断"和"评审人实际做法"对成四格表，再决定收紧还是放宽。文中写明了风险：看护期间会合并主干并在你的凭据下跑测试，只能用在信任所有合并者的仓库；PR 里的文字可能影响评审结论。**可借鉴**：用四格表评估任何自动审批或自动评审，优先修"策略会批准、评审人却要求修改"那一格；给 agent 的修复循环设三次上限，失败就把尝试过程报给人。

- **[GPT-6 models demonstrate intrinsic protein-design capabilities](https://openai.com/index/gpt-6-models-demonstrate-intrinsic-protein-design-capabilities)** · 出处：OpenAI · openai.com/index · 2026-11-24 —— OpenAI 配合预印本发布的研究：GPT-6 系列只用推理和写代码，不调用专用生物模型，就能设计蛋白质骨架和序列。计算评测覆盖 14 项任务，最新内部模型在多数任务上与专用模型持平或更好，例如 MotifBench 骨架搭建通过率 43.7% 对 RFdiffusion 的 27.8%；GPT-6.2 在 PoseBusters 对接任务上 93% 的预测接近实测结构，DiffDock-L 是 50%。实验室验证由合作方 Onava 做：322 个微型结合蛋白里 35 个（10.9%）与目标结合，五个靶点都有命中。文章明确写了边界：序列生成和候选筛选仍用了专用模型，不能说明端到端独立设计；从序列预测完整结构明显落后（TM-score 0.38 对 ESMFold2 的 0.93）；部分高分可能来自记忆。**可借鉴**：报告能力时逐步骤写清哪一步由模型完成、哪一步靠外部工具，并用未公开的样本和湿实验排除记忆的影响。

## 论文（自演进、评测优先）

- 【必看】⭐ 🧪 **[How Feedback-Free Self-Evolution Reshapes Agent Skills: A Systematic Study](https://arxiv.org/abs/2611.25534)** · Litao Guo 等（机构未能从 abs 页或 HF 核实）· 2026-11-19 · HF ↑4 —— 让模型在没有任务、运行结果或评判的条件下反复改写专家写的 skill，再用同一模型的 agent 去跑。所有被测模型在所有基准上都变差，三十轮后 SkillsBench 平均降 15 分。原因是改写把 skill 拉向模型自己的先验，最先丢掉先验之外的知识；把这些知识补回去能恢复大部分损失。据此提出的 SkillDiff 在原文里标出这部分知识，不改文字就让通过率平均提高 4.8 分（周报 2026-11-20 已收）。**可借鉴**：写 skill 时重点写模型自己写不出来的内容；先让模型只凭题目写一份，对比出差异部分并加标记。
- 【必看】🧪 **[What Makes Good Data for Training Coding Agents? A Systematic Study on SWE-Gym](https://arxiv.org/abs/2611.30207)** · Yikai Zhang 等（HF 组织：AMD）· 2026-11-23 · HF ↑14 —— 用两个 LLM 家族审计 SWE-Gym 的奖励标签，疑似错误必须能执行复现才算数。9B 基座从未解出的任务里 74% 有测试拒绝正确修复，有时能解出的只有 20%。修复或移除这些任务后，同样规模和难度下，模型在 SWE-bench Verified 和 SWE-bench Pro 的留出任务上高 2.4 和 2.7 分；只删掉"从未解出"的题没有这个收益。另外通过的补丁里约四分之一其实是错的，但补测试抓出其中四分之一后留出成绩没有可测的变化。已开源 1,087 个审计任务。**可借鉴**：评测集的每条判错结论都附上可执行的证据；误判正确解的危害要优先处理。
- 🧪 **[How Complete Must an Environment Be to Train a Capable GUI Agent?](https://arxiv.org/abs/2611.23946)** · Jingxing Wang 等（HF 组织：Shanghai Jiao Tong University）· 2026-11-18 · HF ↑3 —— 把 GUI 训练环境的完整度拆成三个维度：评审器认可多少条成功路径、应用里有多少无关数据、有多少无关功能，分别调节后训练同一个 4B 模型并在完整环境里评测。评审器只认一条参考路径让成功率降 10.53 分，删掉无关数据也降分；删掉无关功能反而从 51.61% 升到 56.13%，原因是长绕路的成功轨迹按长度加权时占了过多比重。**可借鉴**：搭建 agent 评测环境时，评审器要接受所有能达成目标的路径，干扰数据要保留，无关功能可以裁掉以节省成本。
- 🧪 **[Measuring and Teaching Language Model Agents to Act on Delayed Consequences](https://arxiv.org/abs/2611.28158)** · Shardul Bansal 等（HF 组织：ORO AI）· 2026-11-19 · HF ↑3 —— 提出 SMB Bench：一个 90 天的批发生意模拟器，含 18 个因果配对任务和 859 次前沿模型运行轨迹，考察 agent 能否注意到并处理几周后才显现的后果。16 个前沿模型里只有 3 个胜过固定采购规则；模型常在笔记里写出正确诊断，却没有及时改变采购。**可借鉴**：长周期 agent 的评测要把"诊断对了""行为改了""结果好了"分三项打分，并配一个简单规则基线。
- 🧪 **[HEP-Ex-Bench: Evaluating Agentic Performance in High Energy Physics Experiment Data Analyses with Sealed Worlds](https://arxiv.org/abs/2611.28194)** · Andrzej Novák 等（HF 组织：hep-ex-bench）· 2026-11-20 · HF ↑1 —— agent 在公开数据上开发一条分析流程，评测时在程序生成的封闭数据集上跑，数据里注入已知信号并改变模拟参数。四个任务上最好的 Gemini 4 Argon 平均达到专家参考分析的 60%，GPT-6 Astra 为 38%，Claude Opus 5.5 为 31%。**可借鉴**：要求 agent 交付一条可重复运行的流程，用多份隐藏数据测稳健性，比只看一次答案更难钻空子。
