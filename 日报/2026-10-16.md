## 今日判断

- 【必看】agent 的评测门禁要用「零回归」，不能只看总分：Google 的规则是总通过率达标（例如 95%），并且任何原本通过的指标都不能退步；judge 一律用是/否问题，代替 1~5 分打分。自己做 agent 项目时，可以直接照这两条写进 CI。
- 【结论】harness 是独立的能力维度，不只是模型的附属：最弱模型配完整流水线能超过最强模型单跑（0.948 对 0.806），可是让模型自己从文档搭 harness，最强的也只过 53%。面试讲项目时，要把 harness 设计（任务拆分、持久化状态、确定性查表工具）单独讲成一项贡献。
- 【警示】自演进的经验库必须先「清洗」再写入：只要执行记录或结果配对里混进普通噪声，自演进的收益就会掉到 25%~42%；十种自蒸馏方法里也没有一种稳定超过 GRPO。做 skill 或 memory 自进化时，写入前要校验经验来源，并保留一个不做自进化的基线做对照。
- 【值得盯】只读 agent 的汇报不够用：只读汇报能还原的任务状态比读完整上下文少 40.7 个百分点，失败的尝试和绕过的办法最容易漏掉。做 agent 产品时，要么强制汇报列出「失败和绕过」，要么让人审时能直接翻 trace。
- 【利好】独立评估方拿到「类员工」权限并能自主发布，是行业里第一次：METR 已经驻场，SecureBio 和 Accenture 在推进。之后模型风险报告的可信度，可以看是否有第三方独立署名。

## 论文（自演进优先）

- ⭐ **[When Non-Adversarial Noise Hurts Learning: Benchmarking Skill Self-Evolution in Agents](https://arxiv.org/abs/2610.19910)** · Tao Yu 等 22 人 · 2026-10-14 · HF 未收录（arXiv 关键词补漏）—— 这是第一个测试「技能自演进在普通噪声下是否稳健」的基准 RSE-Bench，覆盖 4 个领域、6 个基准，分别给指令、环境证据、执行记录、「结果和记录的配对」加受控扰动，不改任务本身和评分规则。配套的 RSEClaw 框架负责统一注入噪声，并诊断 agent 实际接触到了什么、技能库更新了什么。在 3 种方法和 2 个基座模型上，带噪声学到的技能只保住干净自演进收益的 25.5%~42.1%。执行记录和配对上的噪声，造成的损失和输入噪声差不多。**可借鉴**：技能库写入前要校验执行记录和结果是否对得上，不能默认日志是干净的；评估自演进时，要把「学习时有噪声」和「测试时有噪声」分开测。
