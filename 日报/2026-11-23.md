## 今日判断

- 【必看】OpenAI 首席科学家把"AI 加速预训练研究"的时间点放在最早 2027 年，并承认对齐与监控的进展跟不上。做 AI 应用的人要按"模型能力每隔几个月跳一档、现有评测很快饱和"来规划：评测集要能持续加难度，不要把产品护城河押在当前模型做不到的事情上。
- 【结论】下游基准的寿命比模型代际更短：Pachocki 指出 GPT‑2、GPT‑3 时代的基准到 GPT‑4 前后基本饱和。自家评测体系应该分两层，一层是随模型更新的任务集，一层是长期可比的稳定指标（成本、每任务成功率、线上会话异常率）。
- 【利好】"带截止时间、问完不等"成了平台原语：OpenAI Agents API 提供时间感知和异步函数工具，手写 Responses 循环也可以每次请求前追加一条时间提醒。做个人助理类 agent 时，这套结构可以直接照搬，用户不回答也能按时交付。
- 【值得盯】线上 agent 监控正在从"单次调用是否违规"转向"整段会话是否漂移"：Google 的例子里每次调用都合法、没有报错，但整段会话是在系统性抓取目录，只有按会话看才抓得到。自建监控时，至少要有一层按会话聚合的行为检查。
- 【警示】把规划和执行拆开并不能自动减少越权：Intent Contracts 实验里，规划模型不持有工具后，完成用户原任务的比例从 16/30 升到 27/30，但未授权动作没有减少，40–49% 的改动落在错误对象上。权限设计要补上"执行方看得到环境"这一环。

- 【必看】⭐ 🧪 **[Perplexity and Intelligence](https://openai.com/index/perplexity-and-intelligence)** · 出处：OpenAI · openai.com/index（Research；作者 Jakub Pachocki，首席科学家）· 2026-11-22 —— 文章主张：现代 AI 的各种方法大多是在"利用"同一个来源的智能，也就是在大规模语料上训练出的压缩器（预测器），而衡量它的指标多年来一直是留出集上的困惑度。作者首次公开 OpenAI 内部主评测集上的对数困惑度：GPT‑3.5 约 0.99（能流畅对话），GPT‑4 约 0.91（能有效使用思维链），现在低于 0.8（网络安全与数学出现变革性能力），约 0.76 的模型开始接连解决数学开放问题；预计 0.68–0.70 区间会再出现一批今天可能没在测的能力。他认为 AI 参与预训练算法研究可能带来阶跃，最早 2027 年会出现类似数学领域的"雪崩"，而对齐与监控的进展跟不上，思维链监控和评测感知问题还会恶化。因此提议各前沿厂商共享透明度标准，并以困惑度等指标设定共同上限，在达到具体里程碑（例如出现思维链监控的继任方案）之前不越线。文中也列了困惑度的四个局限：跨厂商数据集不可比、与具体任务脱节、不反映思维链等预训练之外的进步、熵下界未知。**可借鉴**：下游基准到下一代模型就会饱和（GPT‑2/3 时代的基准在 GPT‑4 前后基本失效），自家评测要配一个长期可比的稳定指标，再配一套随模型换代更新的任务集。
- 【注意】**[Time awareness and async input for personal agents](https://developers.openai.com/blog/time-awareness-and-async-input-for-personal-agents)** · 出处：OpenAI 开发者博客（Kevin Whinnery）· 2026-11-20 —— 以"15 分钟后开会、留 3 分钟阅读、12 分钟内交简报"为例，讲个人助理类 agent 的两个机制。一是时间感知：Agents API 新增 `experimental.time_awareness`，周期性把当前时间告诉模型，让它在临近截止时优先核实最强的发现并动笔，而不是再开一条调研线；时间宽裕时则可以查得更深。二是异步函数工具：把"向用户提问"定义成 `async` 工具，agent 提问后继续搜索，回复到了再并入，没等到回复也能交出可用的简报。手写 Responses API 循环的做法是只算一次截止时间，然后在每次模型请求前追加一条新的时间提醒。文中说 ChatGPT 等 harness 就是用这个模式边问边做。**可借鉴**：澄清问题不要阻塞主流程；把提问做成异步工具，并在每轮请求前注入"还剩多少时间"，让模型自己在"继续查、核实、收尾"之间取舍。
- 【注意】🧪 **[Agent Anomaly Detection: Safeguarding agents across other clouds](https://developers.googleblog.com/agent-anomaly-detection-safeguarding-agents-across-other-clouds/)** · 出处：Google 开发者博客 · 2026-11-20 —— Agent Anomaly Detection（私有预览）只读 agent 的 trace 和日志，不需要访问运行时，所以现在能覆盖跑在 AWS Lambda、Microsoft Foundry 或自建机房的 agent：遥测经 Telemetry API 送达、遵循 OpenTelemetry 约定、把 prompt 和回复记成日志事件、有资源属性标明 agent 即可（ADK for Python 2.12.0 起支持，身份用 Workload Identity Federation，不放密钥）。两个测试例子说明它按整段会话而不是单次调用判断：库存 agent 的两个会话都只调用被允许的 `list_inventory`，只有按偏移量每次取 100 条的抓取会话被标出"级联失败"和"资源耗尽"；换成 Amazon Nova Lite 后 40 个会话有 10 个被标出。客服 agent 的 6 个会话里 4 个越权的全部被标出，包括订单备注里写"SYSTEM OVERRIDE"导致 15.99 美元订单退款 999 美元，并给出校验退款参数、超过阈值加验证的建议。**可借鉴**：线上监控按会话聚合看行为模式，分析与 agent 运行解耦、不拖慢主流程；高风险工具（退款）加参数校验和金额阈值。
- **[Multi-Turn Agentic Reinforcement Learning with Tunix and Gemma 4 on Google TPUs](https://developers.googleblog.com/multi-turn-agentic-reinforcement-learning-with-tunix-and-gemma-4-on-google-tpus/)** · 出处：Google 开发者博客 · 2026-11-19 —— 上期漏扫，本期补入。教程用 Tunix 的 agentic RL 管线，在单台 Cloud TPU v6e-8 上训练 Gemma 4 E2B（思考模式）玩 Plane Strike：6×6 棋盘藏一架占 8 格的飞机，模型每轮看到上一步结果和棋盘，推理后调用 `strike(cell=...)` 工具，最多 23 步。管线分四块：任务环境（`BaseTaskEnv`，同一组 8 条 rollout 用同一个种子，保证 GRPO 组内面对同一盘棋）、工具与聊天模板解析、对话 agent、轨迹收集加 GRPO 学习器。未训练时在留出棋盘上胜率 9.4%、平均 22.44 步；100 步 agentic GRPO 后胜率 95%、平均约 16 步。**可借鉴**：多轮 RL 的组内 rollout 要固定同一个环境种子，奖励按步累加成轨迹级奖励；先在留出任务上量出基线，再看训练增益。

## 论文（自演进、评测优先）

- ⭐ **[AeroRSI: Recursive Self-Improvement for Aerial Vision-Language Navigation](https://arxiv.org/abs/2611.24077)** · Shiwei Wu 等（HF 组织：Tsinghua University）· 2026-11-18 · HF ↑4 —— 无人机视觉语言导航的递归自改进框架：策略在自己到达的失败状态上采样修复动作，判断标准是"从这个动作接着飞能不能成功"，这样连直接模仿会有害的规则动作也能变成可靠监督。一轮飞行在第一次失败处终止，后面的失败要等前面的修好才暴露，所以每轮都要重新收集监督。TravelUAV 上三轮把 2B 监督策略的成功率从 46.4% 提到 67.5%，碰撞减半，比此前最好结果高 10.6 分，没有新增人工标注和推理开销。**可借鉴**：自改进数据不靠人标，靠"修复后继续执行的结果"做验证；失败是分层暴露的，循环要按轮重新采集。
- **[MemOnce: A Scalable Memory Architecture for Large Language Models](https://arxiv.org/abs/2611.27973)** · Chang Nie 等（HF 组织：Nanjing University）· 2026-11-20 · HF ↑12 —— 面向长程、持续交互的记忆架构：只缓存少量最后一层隐状态作为紧凑记忆，需要时再解码回各层的 KV cache；稀疏注意力的检索索引只算一次、各层共用。用它改造 Qwen3.5-4B，在 1M 上下文下记忆状态缓存缩小 1313 倍，预填充延迟降低 6.9 倍，吞吐提高 3.5 倍，记忆任务总体 +5.77%。**可借鉴**：agent 长期记忆的成本瓶颈在 KV cache，"存紧凑表示、按需解码"是 RAG 和全量上下文之外的第三条路。
- **[Intent Contracts: Taking Tools Away from Agents](https://arxiv.org/abs/2611.24025)** · Ziyuan Wang 等（机构未能从 abs 页或 HF 核实）· 2026-11-18 · HF ↑2 —— 规划模型不持有工具，每一步只提交一份记入日志的"契约"（目标、逐字引用的用户原话、范围字段）；代码校验后，由一个小的可信模型对照用户原话写出工具调用。在 AmPermBench 三类任务上，规划模型擅自加活时，契约方式完成用户任务 27/30，审查方式 16/30，因为审查只能整条拒绝。但契约没有减少未授权动作，40–49% 的改动落在错误对象上。**可借鉴**：权限控制可以"部分执行"而不是整条放行或拒绝，但执行方必须能看到环境，否则挡不住指代歧义。
- 🧪 **[AgentRoboCritic: Understanding the Capability of Frontier Agents on Direct Robot Control](https://arxiv.org/abs/2611.26613)** · Yiyang Du 等（HF 组织：Chenyan Xiong Research Group at CMU）· 2026-11-19 · HF ↑3 —— 现有基准只报整局成功率，看不出 agent 怎么成功、在哪失败。本文让策略 agent 在每个动作旁写明局部意图，评审模型对照意图判断动作结果和失败模式，覆盖 12 个操作基准。发现前沿 agent 能闭环恢复局部失败，但抓取和对齐是瓶颈。评审器在 400 个人工标注动作上验证，并发布 12,844 个标注动作和微调后的开源评审模型，失败模式准确率从 32.58% 升到 74.24%。**可借鉴**：让被测 agent 每步先声明意图，评审对照意图打分，就能把整局成败拆成动作级的失败模式；评审器先用几百条人工标注校准。
