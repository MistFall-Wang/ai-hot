## ⭐ 自演进重大发现

- **自我改进循环首次有生产级线上 A/B 数据**：Spotify 的对话式推荐 agent（arXiv 2609.30297）在冷启动阶段用两件事代替人工调 prompt：一是把单轮 prompt 扩展成多轮合成对话，用来在上线前评测；二是一个自我改进循环，先用「同一输入多次运行结果差异大」的样本做对比优化，再交给 coding agent 迭代修复规划和工具调用错误。离线质量在一个已经高度人工优化的 prompt 基础上再涨 8%；系统已上线，线上 A/B 相比只支持会话内调整的旧版本，收听时长 +14%、周活 +5%、跳过率 −5%。这是这套日报里第一篇有线上业务指标、而不只是基准分数的自改进案例。→ 见下文论文第一篇。

## 今日判断

- 【必看】**agent 的权限检查要放在 agent 进程之外执行**。OpenShell 的结构是：沙箱内核限制文件和进程、出网只经外部 supervisor、凭据只给占位符、agent 可以申请但不能自批。自己做 agent 平台时，把这四点当作最低配置。
- 【利好】**「合成评测 + coding agent 自动修 prompt」的自我改进循环已经在生产环境拿到了线上收益**。Spotify 的冷启动做法是：先把单轮 prompt 扩展成多轮对话做离线评测，再挑出结果方差大的样本让 coding agent 去修，最后用线上 A/B 验收，而不是只看离线分数。
- 【值得盯】**harness 优化应当同时看准确率、安全和 token**。MoMHa 显示，把三个目标放进同一个奖励里一起优化，比「先调准确率、再压 token」效果好，安全得分也最高。只按准确率迭代 harness，容易换来更贵、更不安全的版本。
- 【警示】**skill 自演进会过拟合**。多轮更新会累积冗余指令和只对特定任务有效的规则，还会把原来能做对的事改坏。每次改 skill 都要跑回归反例，并限制 skill 的体积增长。
- 【结论】**能力强的 agent 不一定守边界**。ScopeBench 上 8 个模型的越界遵守率在 34.4% 到 86.7% 之间，和原始能力不同步；只靠自动验证器会漏掉 331 次越界。安全类 agent 的评测要单独测范围遵守。

## 今日话题

### 【必看】把 agent 关进「外部执行」的笼子：NVIDIA 开源运行时与两篇边界研究同一天到达

OpenShell 在工程上把权限执行、凭据和审批都移到 agent 之外；AGATE 用确定性检查在 harness 边界同时判断「谁授权了这个动作」和「这份数据从哪来」，但也指出参数改写能绕过检查、按内容溯源会误拦正常文件处理；ScopeBench 证明模型能力高不等于会守范围。三者合起来的结论是：边界判断不能交给模型本身，而且外部检查自身也需要单独评测它的漏报和误拦。

### 【利好】自我改进从基准走进生产：Spotify 拿到线上 A/B，harness 搜索改成多目标

Spotify 的案例给出了线上业务指标，MoMHa 把 harness 自动搜索的目标从单一准确率扩展到准确率、安全和成本三项。两篇都把 coding agent 当作优化器，读的是执行轨迹和评分结果。说明「让 coding agent 改自己的 prompt 和 harness」正在成为一种可以落地的标准做法，关键是事先把评测设计好。

## 官方长文（工程/研究）

- 【必看】**[Add Runtime Controls to AI Agents with NVIDIA OpenShell](https://developer.nvidia.com/blog/add-runtime-controls-to-ai-agents-with-nvidia-openshell/)** · 出处：NVIDIA 开发者博客（Agentic AI / Trustworthy AI） · 2026-09-28 —— **整体概括**：OpenShell 0.1.0 是开源的 agent 运行时，属于 NVIDIA Open Agent Safety Platform 的运行时层，支持 Codex、Claude Code 等，不需要改写现有 agent。结构分三部分：Gateway 管理大量沙箱的生命周期和策略；每个沙箱配一个运行在 agent 之外的 Supervisor，检查所有出站请求；Sandbox 用内核级控制限制文件、进程和权限提升，除了经过 Supervisor 没有其他网络路径。策略用 YAML 写，编译成 OPA/Rego 逐请求判定，可以检查 HTTP、GraphQL、MCP 流量，做到同一 API 放读拦写，且对子进程、生成的代码和子 agent 同样有效。凭据只以占位符形式进入沙箱，发往未授权目的地就拒绝。agent 遇到拦截可以通过 policy advisor 提出最小范围的放宽申请，默认等人工批准，不能自己批准。策略证明器用形式化方法检查授权是否越界：在对抗实验中，削弱安全措施的前沿 agent 花了最多两小时游说 AI 审核者放权，受保护仓库仍然没有被写入。**可借鉴**：权限设计按「执行在外、凭据在外、审批在外」三条做；工具权限要细到操作级别（读或写），不能只到服务级别；给 AI 审核者看的应该是形式化证明的结果，而不是 agent 自己的解释。
