## ⭐ 自演进重大发现

**OpenAI 首次公开一套生产级自改进系统的架构，同一周三家大厂论文都在做 harness 自演进。** OpenAI 10 月 21 日的广告栈长文说，他们用最强、推理最深的模型「观察并评判」整条广告链路的结果，再用这些反馈训练负责编排和召回的小模型，把它称为「powerful self-improvement loop」；系统上线不到 200 天年化收入超过 10 亿美元。论文方面，Microsoft Research 的 Self‑HPO 让策略模型分析自己的失败、提出新 harness，再在选中的 harness 下做 RL，Qwen3.5‑35B‑A3B 平均解决率从 57.8% 升到 64.8%，超过只改 harness 或只改策略的基线。Tencent Hunyuan（RiseHarness）、Google（TEAL）同一周也发了 harness 或工具库自演进的工作。

## 今日判断

- 【必看】OpenAI 广告栈给出了把 agent 放进生产链路的范式：agent 跑在主链路旁边、彼此不依赖，超时直接放弃，「不出结果」也算正常结果。做 AI 应用时，凡是非核心的 agent 功能（推荐、补充信息、提醒）都可以照这个思路设计，先保证它挂了不影响主回答。
- 【警示】OpenAI 说 AI 发现的严重漏洞「未来几个月会急剧增加」，PHP 只是第一批。自己项目的依赖升级节奏要提速：订阅上游安全通告，把打补丁做成例行流程，别等季度升级。
- 【结论】harness 自演进已经从「只改 prompt 和工具」走到「harness 和模型一起改」：Microsoft 的 Self‑HPO 交替优化两者，Tencent 的 RiseHarness 专挑时成时败的任务来改。自己做 harness 优化时，每个改动都要在重复运行或保留集上验证过再留下，单次通过不算数。
- 【利好】Google ADK 把语音 agent 的慢工具改成流式工具后，首句响应从 14.4 秒降到 1.2 秒，改法只是把 `return` 换成 `yield`。做语音或实时 agent 的，慢工具一律改成非阻塞。
- 【值得盯】Anthropic 说「接下来几天」会公布 Claude Duet 的安全设计细节。这个常驻、主动联系用户的 agent 如何处理凭据、敏感信息分级和审批，是做个人助理类 agent 的现成参考，已加入待追踪。

### 【必看】生产级 agent 的共同做法：旁路运行、人工批准再执行、管控放在 agent 碰不到的地方
OpenAI 广告栈、xAI 事故工单机器人、NVIDIA Sentry 和 Claude Duet 虽然场景完全不同，安全边界的思路却一样。agent 不进主链路，或者只能在人批准过的范围里行动；监控和策略执行放在 agent 改不了的地方（独立服务、DPU、分类器）；出错就停下来报告。四篇合起来，基本就是一份 agent 上生产的检查清单。
