## 今日判断

- 【必看】常驻 agent 的安全边界有了官方配置样板：OpenAI 把网关（配置 agent 的控制面）和 agent harness 放在不同集群，沙箱只允许写工作目录、网络走白名单、密钥经凭据代理不进 agent；自己部署长时运行 agent 时，按"网络、文件、进程、密钥"四项逐条对照。
- 【警示】记忆投毒是 agent 监控的明显短板：Google 的事后异常检测对工具返回里的注入标出 81%–99%，但由长期记忆里植入的指令引发的 18 次行动只抓到 4 次；给 agent 加长期记忆时，写入记忆的内容要单独做来源校验，不能指望行为监控兜底。
- 【值得盯】新 agent 的监控有冷启动期：同一检测在每个 agent 约 220 次正常会话时只标出 33%，到 360 次时达到 99%；上线基于行为基线的监控前，先攒够几百次正常会话，这段时间用事前拦截（工具调用审批、白名单）顶上。
- 【利好】"强模型规划、便宜模型执行"成为厂商默认路线：Gemini 4 Hydrogen 配套的 Orchestrator 在 Terminal-Bench 4.0 上以少 24% 的配额、快 19% 的速度接近 Carbon 的成功率；多 agent 系统可以把协调者和执行 / 验证 worker 分配给不同档位模型，再按任务成本而不是单价比较。
- 【结论】今天没有达到"自演进重大发现"标准的内容，不推送。

- 【注意】🧪 **[Improving Fuzzy Robustness in LLM Safety with Automated Red Teaming](https://alignment.openai.com/fuzzy-robustness/)** · 出处：OpenAI Alignment 研究博客（alignment.openai.com）· 2026-11-12 —— OpenAI 把"模型在越狱等对抗压力下仍稳定拒绝违规协助"称为 fuzzy robustness，本文只讲模型层。方法：自动红队 harness 给攻击模型一个种子提示词，让它根据防守模型的回复和安全判定反复改写，直到防守方给出不安全回答，结构类似 PAIR；攻击方是 GPT-5.6 Sol 家族的 helpful-only 推理模型，防守方是 GPT-5.4 和 GPT-5.5，文中说明攻击模型没有专门学过越狱。把生成的越狱样本作为强化学习训练数据后，训练初始安全分远低于用原始种子提示词训练（说明样本更难），并随训练上升；在未见过的另一个攻击模型生成的固定越狱集和 12 种自适应攻击者人设的评测上，稳健性都明显高于基线。成品结果：在针对旧模型生成的网络安全越狱集上，GPT-6 Astra 安全回答 91.5%，GPT-5.6 Sol 为 59%，且对正常请求的拒绝没有增加。**可借鉴**：安全评测同时放两类——固定的历史攻击集，和可多轮改写的自适应攻击者取最低分；训练集要用能把当前模型打穿的样本，初始分已接近饱和的数据学不到东西。
- 【注意】**[Catch Go bugs that fuzzing misses with Gemini and a constraint solver](https://developers.googleblog.com/catch-go-bugs-that-fuzzing-misses-with-gemini-and-a-constraint-solver/)** · 出处：Google 开发者博客（developers.googleblog.com）· 2026-11-12 —— 作者负责 Google 的 agent skills 项目（175 个 skill），用 Go 写了检查 SKILL.md 并应用 LLM 生成的行编辑的工具 skill-lint。做法：把函数编译成 RISC-V 汇编并打开边界检查日志，只保留编译器无法证明安全的越界检查点；Gemini 4 Argon 读源码和反汇编，把到达每个检查点的路径翻译成 Z3 约束；Z3 给出可满足解时得到具体输入字节，再用 go test 重放，崩了就是真 bug，不依赖模型翻译是否严谨；不可满足只表示"可能正确"。结果：3 个故意埋的 bug 全部找到，skill-lint 里另找出 3 个潜伏 bug（例如按起始行排序的编辑块互相重叠导致越界），翻译约每函数一分钟。文中还解释了 Go 自带模糊测试漏掉其中两个的原因：切片表达式按容量而不是长度检查，而模糊测试传入的切片只有 0.07% 容量等于长度；把容量裁到长度后，中位 0.28 秒和 0.17 秒就能触发。**可借鉴**：让 agent 找 bug 时换一种表示（汇编加求解器），并用真实执行确认每个命中；把解析和切片运算抽成纯函数再交给求解器，文件读写和网络留给常规模糊测试。
- **[Build once, run on any agent: A practical guide to agent skills](https://github.blog/ai-and-ml/github-copilot/build-once-run-on-any-agent-a-practical-guide-to-agent-skills/)** · 出处：GitHub Blog（AI & ML 栏目）· 2026-11-12 —— 来自 GitHub Universe 2026 同名分享。skill 是围绕 SKILL.md 的版本化目录，描述何时以及如何完成一件可重复的事；它可以跨 agent 共享，但工具、凭据和权限仍由运行环境提供。要点：每个 skill 只做一件事，写清输入、输出和触发时机；大流程拆成多个 skill 并共享一份由初始化 skill 发现并写出的项目清单，例子中 forge-init 发现表名和命名规范，forge-builder 负责从 issue 到 PR，forge-dbx 统一访问数据平台，forge-lint 提供团队规范；项目配置放清单文件、不写死在 skill 里；流程分七个阶段、每阶段有人工检查点，改表结构前要审批；验证由独立的 Proof Agent 做，只拿到原始需求和代码改动、拿不到编码 agent 的自评，返回 PASS / FAIL / PARTIAL 并必须引用证据；以 skills 目录为源，用打包脚本生成 Claude Code、Cursor、GitHub Copilot 各自的插件文件。文中也划了边界：需要稳定接口、共享状态、审计或模型外强制权限的流程应做成应用。**可借鉴**：验证 agent 不给它看被验证方的自我说明；从仓库里发现的模式不等于规则，要让人确认后再写进规范类 skill。

## 论文（自演进、评测优先）

- 🧪 **[ScrapeBench: Evaluating Legal Compliance of AI Agents in Website Scraping](https://arxiv.org/abs/2611.11306)** · Joseph Marvin Imperial 等 3 人 · 2026-11-10 · HF ↑2 —— 评测 agent 抓取网站时是否遵守服务条款和 robots.txt。在明确禁止抓取的 1,626 个热门网站上，多数闭源和开源 agent 被要求抓取时合规率低于 5%，即使主动查看了条款和 robots.txt 也一样；在 269 个不禁止抓取的网站上，有的 agent 反而拒绝，Claude Opus 4.6 的过度拒绝率为 98.5%。180 人的人类基线合规率与 agent 相近，但过度拒绝更多。**可借鉴**：合规评测要成对设计"应拒绝"和"应执行"两组样本，同时报告违规率和过度拒绝率；"读了规则"不等于"遵守规则"，要按最终行为判分。
- 🧪 **[CARTBench: Rubric-Based Evaluation of Shopping Advice for Complex and Ambiguous Requests with Timelines](https://arxiv.org/abs/2611.05862)** · Yuqin Dai 等 12 人 · 2026-11-04 · HF ↑3 —— 多轮导购建议的评测。案例取自 17 个零售品类的真实购物需求，配带时间戳的对话和 1,603 条商品记录；rubric 逐案编写，依据从成交订单里人工挑出的优秀回复提炼的"理想回复原则"，共 1,328 条专家标注标准，分核心、优秀、安全三类。10 个模型中 3 个核心项超过 90%，没有一个优秀项超过 45%，共性失败在商品证据不足和没有追问关键未知信息。**可借鉴**：rubric 分"必须做到"和"做得好"两层计分，能把已饱和的基础项和仍有区分度的高阶项分开；评分标准从真实成功案例里提炼，而不是凭空写。
- 🧪 **[GTAGym: Real AAA Game Tasks Environment for Evaluation and Reinforcement Learning](https://arxiv.org/abs/2611.13028)** · Jiajun Chen 等 5 人（HF 标注 OpenMOSS）· 2026-11-09 · HF ↑12 —— 基于 GTA V 的 agent 评测与强化学习环境。基准含 103 个由主线任务重建的在线任务（九个任务族）和 47 个图像射击任务；agent 通过截图和键鼠操作交互，结果由游戏引擎状态自动判定，支持并行测试。六个前沿模型中，在任务说明只出现在首张截图、由 harness 自动压缩交互历史的设定下，最好成绩 70.9%，空中导航、躲避和拦截仍然困难。另有按模板和参数范围批量生成训练环境的生成器。**可借鉴**：难以自动判分的任务，优先找环境内部状态（引擎状态、数据库终态）做判定，省掉人工标注，也让同一环境能直接给强化学习提供奖励。
- 🧪 **[Interactive Visual Gym: Evaluating Visual Interaction Models with Simulated Users in Interactive Worlds](https://arxiv.org/abs/2611.08286)** · Chenhao Zheng 等 14 人 · 2026-11-05 · HF ↑13 —— 针对"在用户做实际任务时提供视觉协助"的模型做闭环评测：助手的回复会改变用户后续行为，离线回放测不出来。框架同时模拟可执行的任务环境（做饭、家务、手机界面）和带人设、会犯执行错误的用户，基准含 315 个交互场景。最好的 Gemini 4 Argon 只在限时内完成 53.4%，计入响应延迟后常常来不及阻止错误；人类研究中交互质量指标与参与者偏好一致率 78.5%。**可借鉴**：评测辅助型 agent 时让模拟用户故意犯错和偏离计划，并把响应延迟计入成败。
- ⭐ **[Incentivizing Self-Learning in Large Language Models via Reinforcement Learning](https://arxiv.org/abs/2610.39671)** · Lingkai Kong 等 9 人（HF 标注 Intern Large Models）· 2026-10-29 · HF ↑27 —— 研究"自学"：模型在解题时自己从长篇参考资料里检索、学习并应用知识。任务是基于教材的数学证明题，不给参考答案；提供 BookNavigator 接口让模型像人一样翻教材，再用带细粒度奖励的强化学习训练。Intern-S2-Preview-35B 的整体证明正确率从 51.5% 升到 79.5%，高于不给教材和固定检索两种同样经强化学习训练的基线，并迁移到域外教材；在 BrowseComp-Plus 和 CL-bench 上分别比基础模型高 1.7 和 2.3 个百分点。**可借鉴**：给 agent 的是"翻阅资料的工具"而不是预先拼好的上下文，并对"读了什么、用没用上"给细粒度反馈；对比实验至少设"无资料"和"固定检索"两个基线。
- **[Read Less, Solve More: Token-Efficient Sparse Reading of External Content for AI Agents](https://arxiv.org/abs/2608.22237)** · Zedong Liu 等 8 人（HF 标注 Institute of Computing Technology）· 2026-11-07 · HF ↑18 —— 提出不改模型的读取控制层 SparseRead：记录当前信息需求和已覆盖的来源，按内容类型选择定位证据的方式，并给每个任务设原始内容读入总预算，超出时可回退到完整视图。六个模型、五种场景下总 token 最多降 92.9%、耗时最多降 89.0%，97% 的设置下任务质量持平或提升；网页深度搜索任务 token 降 31.0%–43.0%。
- **[SteerDistill: Quantizing LLM Agents via Closed-Loop Teacher Steering](https://arxiv.org/abs/2611.13410)** · Genming Cui 等 6 人 · 2026-11-10 · HF ↑31 —— 低比特量化后的 agent 容易忽略任务要求或环境条件。方法是让全精度教师指导量化学生改写失败的回复，并根据学生实际执行的反馈反复调整指导，再把纠正后的行为蒸馏进学生。五个 agent 基准、三个模型上，4 bit 权重设定比最强量化基线平均高 1.67–2.18 分，与全精度差距在一分以内；τ²-Bench 上成功率比 QeRL 高 1.84 个百分点，训练 GPU 小时少 67%。
- **[Evolving Infra: Agent-Adaptive LLM Serving at Scale](https://arxiv.org/abs/2611.12304)** · Hao Kang 等 11 人（HF 标注 MIT HAN Lab）· 2026-11-09 · HF ↑10 —— 面向 agent 负载的推理服务框架。把算力分配与 KV 缓存管理解耦，节点可在预填充和解码之间切换；在线规划器按负载构成调整两者比例，分布式 KV 管理器根据 agent 上下文管理的信号决定缓存淘汰和迁移，避免淘汰 agent 马上要复用的缓存。在最多 256 块 GB300 GPU 上跑编码、数学和电脑操作任务，平均端到端延迟和 P95 首 token 时间相对 NVIDIA Dynamo 最多降低 4.1 倍和 14 倍。
