## 今日判断

- 【必看】OpenAI 官方给 RSI 划了红线：「完全自主的 RSI 今天没有发生，除非能安全地做，否则不应追求」。做 AI 应用的人要读的不是政治部分，而是它列出的三类标准——RSI 进度评估、什么样的自动化研究流程必须触发人工复核、对齐事故的分级与上报阈值。这三条早晚会变成企业内部 agent 系统的合规清单，现在就可以把「哪些自动化动作必须人工签字」写进自己的 harness。
- 【必看】NVIDIA 这篇把一句话说透了：**端到端成功率才是发布门禁，步级打分只用来定位断在哪一步**。可直接抄的做法：成功率必须报 3–5 次试验的区间而不是点估计（90% 和 74% 两次跑出来不等于 84%），工具调用精度必须和参数准确率成对报（否则掩盖填参失败），成本指标要用「每次成功的成本」而不是总 token。
- 【利好】记忆工程今天有了生产级数字。V7 的 Context Graph 证明「写入时做结构化 + 图谱检索」比长上下文便宜一个数量级，工具调用错误率 2.7%→0.2%；Designer-RSI 证明在没有可编程 oracle 的任务上，靠「重放门控」筛选技能改动就能让执行成功率从 72.7% 到 99.3%。两者共同点：都不改模型权重，都把改进沉淀在模型外部的记忆/技能层——这正是应用工程师能独立做的那部分。
- 【警示】RecreationWorld 给混合 computer-use agent 的真实水位：GPT-6 Astra 总分 58.1%，但「通过全部程序化测试」的任务只有 2.8%。也就是说当前 agent 能做出「看起来像」的界面，做不出「行为正确」的应用。任何宣称 agent 能端到端交付应用的说法，问它这两个数的差。
- 【值得盯】三条待追踪仍全部未兑现（OpenAI Habitat 第二篇、METR 对 Anthropic 四起事故的独立调查、Anthropic Institute 递归自改进后续）。但今天 OpenAI 这篇政策文里主动引用了自己的「研究加速度报告」和「失准上报框架」，说明各家正在把 RSI 相关披露常态化，METR 那份（最晚 11 月初到期）的到期表现值得盯。

## 官方长文（工程/研究）

- 【必看】⭐ **[Building standards for the next phase of AI](https://openai.com/index/building-standards-next-phase-ai)** · 出处：OpenAI（openai.com/index，Global Affairs 栏目）· 09-21 —— OpenAI 把自己的三大目标重述为「造自动化 AI 研究员、与它一起迭代对齐问题、找到让人类留在自我改进循环里的办法」，然后用整篇文章论证为什么这需要国际标准。**RSI 部分**：明说自动化 AI 研究会让 AI 越来越多地承担下一代 AI 的开发工作，从而推动递归自改进、使进展速度可能急剧加快；并给出红线——完全自主的 RSI 今天没有发生，除非能安全地做否则不应追求，是否推进取决于能否保持人类控制以及知情的民主选择；做得不慎的后果是「人类对 AI 开发失去实际控制，无法监督自己已经看不懂的研究过程」。**标准部分**：提出两个机制，一是依托已在澳、加、德、法、肯尼亚、日、韩、新、印、英建立的 AI 安全研究所网络，经 CAISI 与各国行业机构制定标准（明确不是许可证、不是发布前强制审查）；二是共同的度量与事故上报协议，具体包括 RSI 相关进展与公司内自主研究量的评估、自动化研究的人类监督触发线、对齐与自动化研究事故的分级与上报阈值。文章点名要避免碎片化、集体行动失败、能力分布不均三个问题，并说中美在这些领域的对话是积极一步。**可借鉴**：把它列的三类标准直接当成自己 agent 系统的治理清单——给「自动化程度」定一个可量化指标（对标 Anthropic 的 R&D 自动化指数）、明确写死哪几类动作必须人工签字才放行、给失准事故定义严重度分级与上报阈值；这三件事现在做是工程选择，一两年后大概率是合规要求。

- 【必看】**[How to Evaluate AI Agents From Tool Calls to Task Completion](https://developer.nvidia.com/blog/how-to-evaluate-ai-agents-from-tool-calls-to-task-completion/)** · 出处：NVIDIA 开发者博客（Agentic AI）· 09-21 —— 一篇讲清 agent 评测演化路径的方法论长文。**核心论点**：BFCL 那一代只评单次函数选择与参数填写，但一个格式合法的 `issue_refund` 调用若底层检查未做、状态未更新，任务仍然失败——调用准确率是必要非充分条件。完整评测需要一个会执行每次调用、跨步跟踪状态、事后读世界状态判定的执行环境，在其上叠两层打分：**步级（过程）**问「在当时状态下这次调用是否有效、相关、有用」，**端到端（结果）**只看最终状态（退款到账没、工单路由对没）。两者是同一个对象「trace」的两种读法：过程打分评行，端到端评最终状态。**层级与指标**：Benchmark → Trial → Task → Turn → Step 五层固定汇总；六个指标分三轴——任务成功率（发布门禁）、一致性（3–5 次试验的区间，90%/74% 不等于 84%）、工具调用精度、参数准确率（分离「用错 API」与「用对 API 填错参」）、每次成功的步数（冗长度）、每次成功的成本（经济单位）。**可比性三维度**：任务复杂度、有无状态、验证方法（可执行验证 > 参考答案 > LLM-as-a-Judge，后者在用人工评分校准前只能当临时值）；并警告污染已从训练数据泄漏扩展到「联网 agent 在评测中检索到答案」和「HF 上的数据集被重新爬进预训练语料」。文末给了一条 SWE-bench Verified 真实 trace（OpenHands harness，`pytest-dev__pytest-5262`）的逐步判分：4 步里 1 步冗余，端到端 1 分、步级 3/4、工具调用精度 3/4、参数准确率 4/4。**可借鉴**：三步落地——先用公开 agentic 套件跑出「公共地板」并记录 3–5 次试验区间；再用自己的真实工单、trace、API 建域内评测，门禁必须卡在环境状态（某行数据库记录、某个合并的 PR、某个关闭的工单）而不是评委对最终回复的观感；最后才是把模型和 harness 适配到这个分布上。

- 【注意】⭐ **[How V7 gives AI agents institutional memory](https://openai.com/index/v7)** · 出处：OpenAI（openai.com/index，Startup 栏目）· 09-21 —— 企业 agent 记忆层的生产案例，数字比多数论文实。**问题定义**：业务上下文散落在文档、数据室、表格、邮件与内部工具里，agent 每次请求都要重新发现上下文，导致几十次搜索、烧时间烧 token，还常漏掉藏在关系里的关键信息。**做法**：V7 Go 用 GPT-5.6 Luna 从数百万文件抽取信息，组织成 Context Graph——连接实体、关系与带引用的证据；新文件到达时识别本体中的公司/基金/人员等实体，把每条事实挂到新建或已有记录上并保留到原文的引用；图谱不够时仍可回落到 RAG 检索原文。长跑 agent 的近期对话留在活动上下文里，更早的材料沉到图谱按需取回。**数字**：HERB（跨企业系统找信息并串联的基准）上仅检索系统就比官方基线高 69%，不可答问题的幻觉降 38%；图谱遍历比长上下文方案便宜快一个数量级；GPT-5.6 Sol 把 Context Graph 上的工具调用错误率从 GPT-5.5 的 2.7% 降到 0.2%；最难一档的图谱查询上 Sol 78%、GPT-6 Astra 89%；从 Chat Completions 换到 Responses API 让部分 PDF 密集流程 token 降约 5% 且缓存更稳；客户侧 50–100 步流程分钟级完成、准确率 99.9%，资产管理的尽调筛选快 21 倍。**可借鉴**：两个直接可抄的设计——一是分层模型路由（抽取用便宜模型、推理与工具用强模型，按 fast/medium/smart 三档映射每个步骤）；二是把「记忆」实现成带引用证据的实体图而不是向量堆，并在图上跑持续维护的基准套件（引用准确率、抽取质量、指令遵循、时延、成本各一项）来决定换不换模型。
