## 今日判断

- 【必看】工具接口不是透明管道：MICA 证明 MCP 与 CLI 暴露同一能力时 agent 行为仍系统性不同，94.3% 的配对轨迹早期分歧并持续传播。设计 agent 工具时要同时提供两种渲染做 A/B，单独计量 MCP 的 token 开销（论文里最多每任务 27.1k），并把「语义动作校验」和「接口实现修复」拆成两层。
- 【值得盯】NVIDIA 把 agent 定义成模型 + harness + 工具/skill + 运行时四层，并用 LangChain 的例子说明不重训、只调 harness 就能把开放模型拉到接近前沿且成本约低 10 倍。换开放模型时先做 harness 侧调优（提示、工具、中间件），再谈微调；凭据交给运行时而不是放进 agent 上下文。
- 【利好】EasyProver 说明 harness 工程本身已能把 Lean 证明基准打到饱和（PutnamBench 669/672、VERINA 189/189）：隔离上下文的递归 agent、异步搜索、并行策略试探、弹性 elaboration 服务，模型是现成的。代码形式化验证正在从研究课题变成可搭的流水线，Aegis 这类「从真实实现造更难任务」的思路也适合其他饱和基准。
- 【记录】Apple 的结果给 UI agent 训练定了方向：在真机环境做在线 RL、用 LLM 评审给步级稠密奖励、规划与定位解耦，8B 模型对 Android 的分布外泛化比 SFT 高近 7 倍；SFT 背静态轨迹的路线在 UI 任务上已经吃亏。
- 【警示】OpenAI 的安全干预从单轮拒答升级为跨对话信号、自动结束对话、暂停账号三级，并对预测未成年人收紧信息；同时承诺遵守 IETF 的 robots.txt 训练偏好信号。做对话产品的人应预留「会话级中断」能力，做爬取与数据管道的人要开始识别 aipref 信号。

## 官方长文（工程/研究）

- 【注意】**[Build Specialized Agents on a Stack You Control with NVIDIA NemoClaw](https://developer.nvidia.com/blog/build-specialized-agents-on-a-stack-you-control-with-nvidia-nemoclaw/)** · 出处：NVIDIA 开发者博客（Agentic AI 类）· 2026-10-30 —— 把生产级 agent 拆成四件：会推理的模型、定义 agent 如何运作的 harness、扩展能力的工具与 skill、管控生产访问的运行时。NemoClaw 既不是 harness 也不是运行时，而是一组开放蓝图：在开发者已选的 harness（OpenClaw、Nous Research 的 Hermes Agent、LangChain Deep Agents）之上装配 Nemotron 开放模型、NeMo Relay 观测与路由、OpenShell 安全运行时，不要求重写 agent。核心论点是模型与 harness 要联合调优：两者不匹配时模型会反复要上下文、提前停止或空转；LangChain 不重训、只改提示、工具和中间件，把 Deep Agents 调到适配 Nemotron 3 Ultra，达到接近前沿的表现且每次运行成本约低 10 倍，这套调优已打包进蓝图和 GitHub 上的模型 profile。示例「记忆驱动的 Chief of Staff」是一个 Hermes profile，维护人、项目、优先级和工作模式的持久可读模型；OpenShell 管文件系统、进程和网络访问，把托管推理与 MCP 连接的凭据放在沙箱外，记忆或检索把 agent 带偏时仍受策略约束；NeMo Relay 原生接入 Hermes 会话，在新建、重置、过期等真实会话边界关闭 trace span 并导出轨迹供审计与再优化。可在云、数据中心、DGX Spark 和 RTX 上跑，也可作为 Claude、Codex、Cursor 的领域子 agent。**可借鉴**：换开放模型时先做 harness 侧调优（提示、工具、中间件）再考虑微调；凭据交给运行时层而不是放进 agent 上下文；trace span 按会话边界切而不是按请求切，方便回放整段轨迹。
