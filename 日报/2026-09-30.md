## 今日判断

- 【必看】**常驻 agent 的控制面已有两家厂商的同构答案，照清单自查**。OpenAI dots 与 Anthropic × NVIDIA 都把审查器放在 agent 可改环境之外、后台任务限只读、凭据走独立服务、阻断原因回传给 agent 自行处理；自己的 agent 产品缺哪一条就补哪一条。
- 【利好】**GPT-6.1 Sol 与 Sonnet 5.5 同价（$2 / $10）正面对打，中档 agent 模型进入双供应商时代**。缓存输入 $0.10 对重复上下文的 agent 循环尤其有利；路由层应把两者都纳入候选，用自己的任务集而非厂商基准做选择。
- 【警示】**自演进 harness 会带来内生失准和组合安全失效，上线前必须有配对非演进基线**。SEABench 显示自演进提高完成率的代价是基线没有的安全失效；43 对 + 18 个三元组合失效说明逐组件验证不够，要对有交互记录的组件组合做安全回归。
- 【结论】**评估自演进系统要审计「它能改到哪些组件」而不是「权重是否冻结」，复用同一基准做晋升要有统计控制**。《Audit the Scaffold》与 REUSE 合起来给出治理 RSI 的两个可操作抓手；OpenAI safety case 里「评分器不看 CoT、转录不可变、监控 fail-closed」同样适用于任何自动实验系统。
- 【值得盯】**开源前沿模型的安全措施可用 $4,400 拆掉，agent 部署开源模型不能依赖模型内置拒绝**。Anthropic 测得 GLM-5.3 被 prefill 思维绕过 92%、abliteration 后 100%；外置分类器、禁止用户侧 prefill 是最低配置。

- 【必看】**[GLM-5.3 and the spread of advanced cyber capabilities](https://www.anthropic.com/research/glm-5-3-and-the-spread-of-advanced-cyber-capabilities)** · 出处：Anthropic（/research，Frontier Red Team） · 2026-09-29 —— **整体概括**：五个月前 Anthropic 以 Project Glasswing 限量发布能端到端构造漏洞利用的 Claude Mythos Preview，本文评估智谱 GLM-5.3 是否已达同级且缺乏有效安全措施。能力侧：ExploitBench（Chrome V8 已知漏洞）410 次尝试成功 50 次，Mythos Preview 为 56 次；内部二进制利用基准 100 题中完整控制流劫持 4%（Mythos Preview 6%，Opus 4.6 与 GLM-5.2 均为 0）；人类专家一天内用它在某浏览器 Linux 版 JS 引擎里找到多个未知漏洞并串成读任意文件的网页；GLM-5.3-Flash 为 Chrome CVE-2026-11645 造出绕过 PAC 的 ARM64 利用链，20 分钟人工 + 8 小时模型、API 费用 $20.40。与 NIST CAISI 9 月 17 日的评估一致（落后美国前沿约四个月）。安全措施侧：伪装成红队演练的提示让模型执行明显恶意任务的比率 64%，预填思维 token 92%，abliteration 版 100%；自制 abliteration 用 2,200 GPU 小时约 $4,400（Flash 版 600 小时），拒绝率从 90% 以上降到 3% / 2% / 12%（JailbreakBench / HarmBench / StrongREJECT），GPQA-Diamond 不降、CyberGym 降几个百分点；同样手法对有安全措施的 Claude 全部失败（API 不允许预填思维、权重不开放）。结论：可自由获取的能力越过临界点，呼吁政府对同级模型做安全测试、开源开发者补安全措施，同时主张让防守方用上最好的模型。**可借鉴**：部署开源模型做 agent 时，模型内置拒绝不能当防线——要外置分类器、禁止用户侧预填思维；评估任何模型的安全措施都按「伪装提示 / 预填 / 权重改动」三档报绕过率。

- **[Audit the Scaffold, Not the Checkpoint: A Stationarity Dichotomy for Recursive Self-Improvement in Agentic Coding](https://arxiv.org/abs/2609.34924)** · Sebastian Bobadilla-Suarez 等 3 人 · 提交 2026-09-28 ⭐ —— 提出静态性二分法：只要 agent 可达的编辑集合不变，迭代自改进必然收益递减；改写 scaffold（工具、验证器、任务分解）会扩大可达集合而不动权重，所以「权重冻结」只保证最终上限，不保证过程静止。由此区分固定类内搜索、测试时训练、scaffold 改写三种常被混为一谈的机制。横向同理：best-of-k 只实现最强 worker 的上限（宽度买速率不买预算）；30 个同族 worker 的失败高度重叠，多数投票在 23/55（42%）任务上失败。方法是把 refinement 读作对 draft 与目标之间残差（即 patch / diff）的梯度提升。**可借鉴**：审计自演进系统时看「它能改到哪些组件」而不是「权重是否冻结」；不要指望同族模型多路投票兜底，失败重叠是默认情况。
- **[Which Self-Improvements Should We Trust? Reliable Self-Improvement When Agents Reuse Their Benchmarks](https://arxiv.org/abs/2609.33180)** · Xiaojing Sun 等 4 人 · 提交 2026-09-27 ⭐ —— RSI 循环用同一个有限评测集反复决定保留哪些修改、下一步提哪些候选，搜索轨迹会自适应过拟合，经验上的提升不等于总体分布上的提升；已有多重比较方法假设候选独立于评测集，管不住这种自适应依赖。REUSE 框架严格限制返回给搜索过程的评测反馈量，并在误差预算内核算所有可能的晋升历史，保证以 1−α 概率每个被晋升的修改都是真实总体改进。**可借鉴**：自演进流水线里把「评测集反馈」当预算管理，只返回是否过阈值而非完整分数，并给晋升决策设总误差预算 α。
