## 今日判断

- 【必看】Anthropic 把 agent 记忆的「跨实例经验继承」（Memento：新实例接手工作区和前任笔记）同时用作 harness 设计和威胁模型。做长程 agent 的人可以直接借用这种「定期重启 + 交接笔记」的防钻牛角尖办法，也要意识到同一机制会被安全团队当作风险指标来审视。
- 【警示】MCP 工具层不可信：ToFu 在 273 个 MCP server、3405 个工具里找到 343 个工具存在已验证的 CWE 缺陷。把 LLM 生成的参数直接交给工具执行时，必须在 orchestrator 一侧按工具文档做语义校验。
- 【值得盯】「harness 会过时」开始有数据支撑：HMA 发现自定义 harness 的收益会随底座模型升级而消失，CoCoEvolve 和 Evo² 则把 harness 本身作为持续进化的对象。面试被问到 agent 架构时，可以讲「harness 要能随模型版本重新优化，不能写死」。
- 【警示】reward hacking 会传染：一个 agent 学到的作弊策略会通过共享代码、共享记忆和自然语言计划扩散到其他 agent，甚至影响更强的闭源模型。多 agent 系统要给每个交付物加独立的审查器，不能只靠测试通过。
- 【利好】ReplaySSM 已经集成进 vLLM、TensorRT-LLM、FlashInfer。部署 Qwen3.5+ 或 Nemotron 3 这类混合模型时，打开投机解码终于能拿到真正的吞吐收益。

## 官方长文（工程/研究）

- 【必看】⭐ **[AI models may be capable of self-replicating without access to a datacenter](https://www.anthropic.com/research/self-replicating-ai)** · 出处：Anthropic Research（Frontier Red Team，William Zhou、Daniel Freeman） · 2026-10-12 —— 把自主复制拆成找目标、拿执行权、搭推理、继续传播四步，重点测此前很少测的「在陌生硬件上搭推理」。结果：Qwen3.5-9B 这类小模型能在 Jetson Nano 到 Mac 的多种设备上搭起推理服务（9B 模型在 9 类硬件中的 8 类上成功）；在 8 节点模拟 Android 集群中，GLM-5.2 在 5 次试验中有 4 次感染全部节点，其他开源模型都失败；15 台约 55 美元的电视盒能以 0.39 token/s 跑 Gemma4-26B-A4B。按 30B 以下模型每年 +13.7 ECI 的趋势，2026 年底前小模型可能达到复制所需的能力底线，复制速度约每 1~2 天一代。Qwen3.5-9B 每代给下一代留笔记，推理搭建成功率从 45% 升到 61%~84%；给小模型配 Opus 4.8 作顾问则没有显著帮助。防御重点是 ISP 流量异常检测、隔离通知（Mirai 先例中 14 天清除 92%）和取消设备默认密码。**可借鉴**：文中的 Memento harness 定期用新实例接手旧工作区和前任写的简短笔记，专门解决长程 agent「钻牛角尖不回头」的问题，可以直接用在自己的长任务 agent 上。
- 【注意】**[ReplaySSM: Rethinking State Storage for Faster Hybrid-Model Decoding](https://developer.nvidia.com/blog/replayssm-rethinking-state-storage-for-faster-hybrid-model-decoding/)** · 出处：NVIDIA 开发者博客（与 Princeton Dao AI Lab 合作） · 2026-10-12 —— 混合模型（Nemotron 3、Qwen3.5~3.8、Kimi-K3、GLM-5.3-Flash）的 SSM 层每步都要读写完整状态（单层 FP32 状态 4 MiB/序列，约等于 8K token 的 KV cache），在大批量服务时，10 万 token 以内的解码瓶颈其实在 SSM 层而不在注意力层，还会让投机解码回滚和状态量化变难。ReplaySSM 把状态表示成「检查点 + 最近 L 个输入的缓冲」，大多数步只追加输入、不写状态，缓冲满了再合并写回一次。批量 256 时 kernel 快 1.46~1.80 倍、解码步快 1.20~1.47 倍；投机解码在批量 512 时吞吐是 vLLM 的 1.85~2.10 倍；读 NVFP4 状态的 kernel 比 FP32 快 3.8 倍。已集成进 TensorRT-LLM、vLLM、FlashInfer，并在 GLM-5.3-Flash 和 Kimi-K3 的生产环境中运行。**可借鉴**：选型自部署模型时，混合架构在批量 1 下没有收益，要在目标并发下实测；用 vLLM 跑混合模型时确认版本已含 ReplaySSM 再开投机解码。

- ⭐ **[Meta-Reflective Evolution Effectively Improves Production AI Systems](https://arxiv.org/abs/2610.12794)** · Seung Won Wilson Yoo 等 10 人 · 2026-10-08 —— 常见的进化优化只看前沿候选的失败做一次 LLM 变异，在生产系统里容易停滞，因为单个失败暴露不出组件之间的隐藏交互。CoCoEvolve 用一个 agent 式变异器（Cortex Code）从整段进化历史中按需检索证据，并在提出变异前先探测线上系统。DABStep 留出集困难题准确率 92.8%，同条件下 Meta-Harness 78.4%、GEPA 30.4%；data-eng-bench 从 59.1% 提到 77.4%；HotpotQA 比 GEPA 高 11 个百分点。**可借鉴**：做 prompt / pipeline 自动优化时，让变异器能查全部历史尝试并实际跑一下系统，不要只喂当前最优解的失败样例。
