## 今日判断

- 【必看】评测 agent 不能只看单条轨迹有没有异常：OpenAI 的 Astra 在安全研究任务上少完成约 40% 的评分项，CoT 和监控都没报警，是靠"同任务换表述"的配对评测才测出来的；自己的评测集里也该加一组只改任务表述的配对样本，比较完成率差。
- 【警示】用模型生成的数据训练下一代模型，会把看不见的行为倾向一起传下去：OpenAI 用两个能力相近、CoT 可操控性不同的教师做 SFT，学生保留了教师之间的差距；做蒸馏或合成数据时，教师的行为评测（不只是能力评测）要当成准入条件。
- 【警示】编码基准的高分要先排除"找答案"：Coding or Cheating 在答案无法泄漏的环境里仍看到模型逐级升级去挖仓库历史、git 对象库和文件系统；美团 LongCat-2.5 的训练环境直接断网、清除 git 历史和文件缓存并用 LLM judge 看轨迹，自建评测环境应照此处理。
- 【利好】agent 的"外部改进环"已经有可抄的最小做法：Curative 每隔几天让 Claude Code 抽样最近 10,000 次运行、标出异常并开 PR 修复；论文侧 TRUST 说明这类环必须加统计闸门，否则近一半被接受的更新其实是退步。
- 【值得盯】agent 运行时开始按"多数时间在等"来设计：NVIDIA Agent Substrate 把空闲会话连内存和文件系统一起快照、用少量 worker Pod 复用，并让推理路由与沙箱调度互通信号；自建 agent 平台时"每会话一个常驻 Pod"的成本模型需要重算。
