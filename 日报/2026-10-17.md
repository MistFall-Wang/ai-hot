## 今日判断

- 【必看】agent 写代码的团队，审查要按「风险」分配人的注意力，不能按「有没有人读过」：Claude Code 团队用「每个 PR 的人工批准数 + 等待时长」做效率指标、用回滚率和事故率做护栏，审查最多 3 轮。做 agent 项目时，可以把这两组指标直接写进项目介绍。
- 【结论】Anthropic 自己的数据说明，AI 应用岗要证明「自主性和判断力」：初级技术岗招聘占比从 27% 降到 9%，面试评语里提到「会用 AI 工具」的比例在技术岗翻了三倍，自主性和判断力是增长最多的评价项。准备面试时，要准备「我怎么管理和验证一群 agent 的产出」这类故事，只讲会写代码不够。
- 【值得盯】「可执行的评估器 + 长时间闭环」正在产出超过人类最好结果的成果：量子电路（一次运行 53 小时）和 Athanor（4 个 agent 104 小时）都是同一个结构。要做自演进 agent，第一步是先把评估器做成可以自动打分、而且被优化的一方改不了的东西。
- 【警示】agent 的重试和故障切换不能盲目重放：OpenAI 的规则是只读、结果没被用过、还在截止时间内的请求才自动切换；部分输出或不确定是否已执行的工具动作，要先对账再重启。agent 网关里要有统一的重试预算，也要做幂等检查。
- 【利好】把多选决策从大模型手里拿出来，成本能降一个数量级：JevAgentHarness 用 4B 决策模型把工具选择的成本降了 81%~89%，成功率损失不到 3 个点，前提是按每个决策点拟合一个置信阈值。

## 论文（自演进优先）

- ⭐ **[Athanor: An Agent-Native System for Autonomous Post-Training Research](https://arxiv.org/abs/2610.21055)** · Yufa Zhou 等 8 人（HF 组织 ByteDance）· 2026-10-15 · HF ↑10 —— 用「前沿 agent 能否自主后训练一个原始基座模型」来测量弱形式的递归自改进。系统负责冻结的评估、作业调度、去污染数据、持久研究记录和一套 agent 看不到的留出集；agent 在沙箱里自己读数据、造训练集、改算法、调参，不准用外部教师模型。4 个 Claude Opus 5.5 agent 各占一台 8 卡节点、不给任何研究建议，104 小时把 Qwen3-4B-Base 从 15.9 提到 67.3（开发集）、从 9.2 提到 48.2（留出集），官方 Instruct 版分别是 66.5 和 47.9。agent 是靠重组已知方法达到的：SFT、一个 agent 改出来的 rollout 变体、跨 agent 权重合并、多轮自蒸馏。**可借鉴**：自主研究 agent 的基础设施要把「评估」和「留出集」放在 agent 改不到的地方，并保留完整研究记录，才能区分真实提升和刷分。
- ⭐ **[Terminal-RSI: Recursive Self-Improving Terminal Agents via Recursive Self-Rewrite and Policy-Refine](https://arxiv.org/abs/2610.22192)** · Junyao Yang 等 9 人（HF 组织 Tencent）· 2026-10-15 · HF ↑23 —— 让终端 agent 交替做两件事：把通过验证的轨迹重写成更好的训练数据（RSR），再用继承上一轮 critic 的 RL 精修策略（RPR）。为多轮交互设计了跨轮衰减的优势估计，并把「严格成功」和「有界的部分得分」分开奖励。从 Qwen3.8-27B 基座经过 5 个阶段，Terminal-Bench 2.1 达 86.52%、Terminal-Bench Hard 达 79.00%；长程任务 LHTB 的严格完成数从 0/46 升到 5/46。**可借鉴**：自改进的奖励要把「完全成功」和「部分进展」分开记，否则 agent 会只追部分得分。
- ⭐ **[Self-Evolving Agent Harness](https://arxiv.org/abs/2610.18813)** · Chuyang Wei 等 8 人（HF 组织 ZGCAGI）· 2026-10-13 · HF ↑187 —— 一篇形式化综述，研究「权重不变、只改 harness（提示词、记忆、工作流、工具和代码）」的自演进：通过准入的修改会跨运行保留。框架把「改什么」和「怎么提议、怎么准入」分开，区分对解释性状态的修改和对工具、代码、仓库级控制逻辑、插件组合的修改。在明确假设下给出泛化界、基于历史回归预算的保持界，以及一条用全新独立验证数据的高概率准入规则。**可借鉴**：harness 自动改动要过「准入门」：用改动前没见过的验证集评估，并给回归设预算，超了就拒绝合并。
- ⭐ **[AutoSFT: An Agentic System for Automated Data Research in Supervised Fine-Tuning](https://arxiv.org/abs/2610.22194)** · Bingxiang He 等 21 人（HF 组织 Tsinghua NLP Group）· 2026-10-15 · HF ↑35 —— agent 自动做后训练时，大部分精力花在改 SFT 数据上。论文定义了调比例、剪枝、修复、替换、合成这一整套数据操作。单 agent 跑下来只会调类别比例，上下文还会被执行输出塞满、中途丢掉。AutoSFT 用一个元 agent 把执行和分析分开，从多个独立角度收集方案，并调用合成子 agent：执行器让上下文丢失减半，分析子 agent 让 IFEval 提升 6.5，合成再加 3.4。**可借鉴**：长时间自主实验时，把「跑实验」和「分析结果」交给不同 agent，避免执行日志挤掉分析需要的上下文。
- **[JevAgentHarness: Benchmarking, Deploying and Training Decision Models That Share Control with LLMs](https://arxiv.org/abs/2610.21412)** · Kunlun Zhu 等 8 人（HF 组织 University of Illinois at Urbana-Champaign）· 2026-10-15 · HF ↑17 —— agent 的大部分 LLM 调用最后都是多选决策（比如下一步调哪个工具）。不加置信阈值直接交给决策模型，成功率掉 19 个点；按每个决策点在 agent 自己的轨迹上拟合阈值、低于阈值时交回 LLM，再用 agent 犯错后的状态训练 4B 模型，成本降 81%~89%，速度最高快 2.5 倍，成功率损失不到 3 个点。
- **[EdgeWise: Bringing Long-Horizon Agents to the Edge via Selective Cloud Delegation](https://arxiv.org/abs/2610.17560)** · Zeru Shi 等 13 人（HF 组织 NVIDIA）· 2026-10-13 · HF ↑24 —— 长任务里只有少数关键步需要前沿模型。本地小模型当主力，用步级 RL 同时学「解题」和「何时把这一步交给云端」，对每个委派决策单独分配功劳。效果持平或超过全程用大模型，SWE-Rebench 上成本降 62%，Terminal-Bench 2.1 上降 34%。
- **[OpenGCUA: Toward a Fully Open Stack for Generalist Computer Use](https://arxiv.org/abs/2610.22200)** · Hanzhang Zhou 等 15 人（HF 组织 Tongyi-MAI）· 2026-10-15 · HF ↑266 —— 开源通用 computer-use agent 全栈：让模型自己选择用 GUI 还是写代码来观察和操作，并把部分「看什么、任务进行到哪」的决策从 harness 固定规则交给模型。在 OSWorld-v2 上，8 个模型（含 GPT-6 Astra、Claude Opus 5）的平均部分得分都提高了，均值 +19.6 分，步数平均减少 53%。
