## 今日判断

- 【必看】OpenAI 声称模型证伪了 ETH，并且每项结果都先做 Lean 形式化再对外发布。高价值的 AI 产出要靠「机器可检验的证明 + 独立第三方复核」才能被接受。做 agent 时，凡是结论要给人拍板的环节，都应该配一个可自动校验的产物（测试、形式规约、可回放的轨迹），不能只交一段自然语言解释。
- 【值得盯】GPT-6.1 Terra 把计算机使用的单任务成本压到 Opus 5.5 的约九分之一（OpenAI 自测），错误诱导题上的出错率从 53.6% 降到 16.7%。表单填写、单据录入这类大批量 GUI 自动化，现在值得用便宜档模型重新算一遍账。旗舰模型留给复杂编码，Terra 本身也是这么定位的。
- 【结论】OpenAI 内部经验是答案超过 30 秒工程师就会切走注意力，Ultrafast 让排障变成「同时查所有可能原因」。对排障、问答这类交互型 agent，延迟本身就决定了用户会不会把任务交出去，选模型和设计并行检索时应该把「30 秒内给第一个有用答案」当硬指标。
- 【利好】RSIHub 和 HarnessMM 说明自演进开始变得可比较、能省钱：同一套框架下比较四种方法，最大提升 13.5 个百分点，但排名随设置变化，增益也不一定能迁移到留出任务；harness 复用已确定的决策，可以在成功率不降的前提下省 30%–88% 的 token。自己做 prompt / skill 进化时，评测集和留出集必须放在可变部分之外，否则涨分可能只是过拟合。
- 【警示】上海 AI Lab 跑了 52,168 条轨迹，发现 harness 的排名随模型和基准变化，「任务做对」和「正常跑完」偏好的组合也不一样。换模型时不能沿用原来的 harness 结论，至少要按「模型 × harness」重新测一遍有效完成率和 token 消耗。

## 论文（自演进优先）

- ⭐ **[RSIHub: A Composable Framework for Agent-Evolution Methods](https://arxiv.org/abs/2610.32253)** · Zimu Wang 等（字节跳动 / 上海交通大学 / 北京通用人工智能研究院 / UC Berkeley，据 arXiv HTML 作者栏）· 2026-10-23 · HF ↑34 —— agent 进化方法用执行反馈改 prompt、skill、工具和编排，但每个方法都要重造一遍实验设施。RSIHub 用「配方 + 可复用算子 + 声明可变资源」组合方法，框架统一负责执行、评测、故障恢复和谱系记录，评测器放在可变部分之外。不改核心就复现了 AHE、Hyperagents、A-Evolve、GEPA，在 Terminal Bench 2 和 τ³ Banking 上用 MiniSWE 和 Codex 测试：最大 pass@1 提升 13.5 个百分点，但方法排名随设置变化，增益也不一定能迁移到留出任务。**可借鉴**：自己做 skill / prompt 进化时，把「可变资源」显式声明，评测器锁在外面，每个候选都记录谱系和对应的评测条件，再拿留出集确认增益。
- ⭐ **[HarnessMM: Recursive Self-Improvement for Harness Token Efficiency](https://arxiv.org/abs/2610.32813)** · Yuhua Jiang 等 4 人（清华大学 / 微软亚洲研究院）· 2026-10-23 —— harness 在工具返回后经常重复调用推理，哪怕下一步动作早已确定。HarnessMM 把已确定的决策存成「可执行决策图」（精确动作、字面参数、因果依赖、公开守卫条件），在模型和工具的边界上用控制器复用这些决策，替代后续的推理回调；遇到新的语义决策或证据不足时，再交回原模型。harness 配置本身用 RSI 迭代，最后由验证集选定。HumanEval 上 Codex 成功率保持 90.82%，单任务 token 从 66.72k 降到 47.02k（省 29.54%）；DeepSeek Harness 成功率从 71.43% 升到 85.71%，token 从 96.28k 降到 11.62k（省 87.93%）。**可借鉴**：在 harness 里缓存「已定决策 + 守卫条件」，守卫条件满足就直接执行，不再回调模型。这是一种不动模型权重的降本办法。
- ⭐ **[On-Policy Self-Training: Data-Free Self-Improvement in Large Language Models](https://arxiv.org/abs/2610.32770)** · Leon Sick 等 6 人（Google / 乌尔姆大学）· 2026-10-23 · HF ↑12 —— 把 on-policy 自蒸馏改成纯自训练：只给粗粒度的主题描述，模型自己生成问题和带特权信息的推理示范，再蒸馏回自身，全程不用人工整理的题目或答案。在文本和多模态（VQA）上都有一致提升，未自训练的领域能力保持不变。**可借鉴**：领域标注数据稀缺时，可以先试「主题描述 → 模型自出题 + 特权解答 → 自蒸馏」这条无数据路线，同时用不相关领域的基准监控有没有遗忘。
