## 今日判断

- 【必看】agent 工作流要有显式状态机和外置任务记录：Performance Factory 把每个任务的状态和发现记在 agent 上下文之外，配置文件写明允许的状态转移和需要人参与的步骤，等待 PR 评论或部署时用事件订阅唤醒，而不是让 agent 空转；自己做长流程 agent 可以直接照这个结构搭。
- 【必看】给关键结论加一个"专门反驳"的 agent：OpenAI 发现 agent 常停在第一个看起来合理的解释上，于是另开一个 Codex 会话专门做反事实检验，例如没受影响的同类请求是否正常、回滚后指标是否恢复；根因和修复两步都加了这道复核。
- 【警示】自进化的瓶颈常常在评测而不在提案：Resolution Hypothesis 显示，候选改进里确实有好的，但用带噪声的评分去挑，效果和随机差不多；方法之间几个百分点的差距小于同一方法跑两次的差异。做 prompt、skill 或记忆的自动优化时，要先测评测本身的重复运行方差，再看提升是否可信。
- 【结论】回测型评测要防泄题：OpenAI 用历史事故回测时，禁止 agent 读取保存的记忆、事故复盘和之前的运行结果，事后还检查 transcript 看有没有泄露；根因时间和"怪到哪次部署"分开打分。
- 【值得盯】Anthropic 已在纳斯达克上市（ANT），此后它的财报和招股书披露会成为 Claude 业务数据的新一手来源，可以和 OpenAI 的研究加速报告对照看。

## 论文（自演进、评测优先）

- ⭐ 🧪 **[The Resolution Hypothesis: Agent Evolution's Key Is Identifying Improvements](https://arxiv.org/abs/2611.23068)** · Yuanhao Zeng 等（HF 组织：ShanghaiTech University）· 2026-11-17 · HF ↑35 —— 把 agent 自进化概括为"提案者生成候选（prompt、skill、记忆）→ 按评分选择"的循环，提出瓶颈不在提案而在评测分辨率。作者在 7 种进化方法、6 个模型上做了超过 1,000 万次 LLM 调用：候选层面，好候选确实存在，但按评分挑选与随机挑选差不多，误差逐轮累积；方法层面，论文里常见的几个百分点差距，小于同一方法独立跑两次的差异，已发表的排名很多靠运气。**可借鉴**：做自动 prompt / skill 优化前，先对同一候选重复评测，量出评分方差；接受改进的门槛要高于这个噪声，方法对比要报多次运行的区间，不要只报单次分数。
- ⭐ **[Piccolo: Co-Evolving Decision Models and Data through Recursive Self-Improvement](https://arxiv.org/abs/2611.24651)** · Zhenqing Ling 等（HF 组织：agentscope-ai）· 2026-11-18 · HF ↑11 —— 一组 0.8B–27B 的多模态决策模型，给候选答案输出概率，覆盖通用判断、agent harness、数据工作流和游戏。训练由研究 agent 驱动：分析模型行为、构造训练数据、做实验，再按结果修正下一轮提案，各轮之间用语义切片和共享研究记忆衔接。Piccolo-27B 在 Decision Index Vision Full 榜得 75.59。三条反直觉发现：底座与配方要一起调，旧底座可能胜过新底座；定向数据筛选能让 4B–9B 模型在专门工作流上追平 27B；loss 持续下降时离散决策准确率可能不变甚至变差。**可借鉴**：自改进训练循环要直接盯最终的决策准确率，不能只看 loss；研究 agent 之间要共享研究记忆，跨轮次复用。
- 🧪 **[FVScore: Specification-Driven Neuro-Symbolic Video Evaluation](https://arxiv.org/abs/2611.22673)** · Do Xuan Long 等（HF 组织：Google）· 2026-11-17 · HF ↑4 —— 视频生成评测框架：把每条提示编译成显式命题（提示要求）和隐式命题（未写明的物理、时序、跨模态约束），用专门的感知工具逐条打置信度，再用受线性时序逻辑启发的软时序算子汇总，最后只保留人能感知到的违规，输出带时间戳和证据的报告。与人类判断的相关性高于整体打分和 agent 评审。**可借鉴**：LLM 评审可以改成"拆命题、逐条验证、再汇总"，每条扣分都能追溯到证据。
- 🧪 **[Thinking Harder Doesn't Lead to Better Choices: Reasoning Effort Increases the Confidence but Not the Correctness of LLM Shopping Agents](https://arxiv.org/abs/2611.22033)** · Adi Krishnamoorthy 等（HF 组织：University of Chicago）· 2026-11-17 · HF ↑4 —— 在 WebShop、Amazon SQID、Wayfair WANDS 三个选品基准上测 10 个前沿模型：提高推理强度没有在统计上显著提高选择质量，却显著提高了模型报出的置信度；多数模型在各推理档都校准不好，且错误高度重合，多个模型常选中同一个错误商品。**可借鉴**：agent 评测要把推理档位当变量测，置信度要单独做校准评测；多模型投票在错误重合的任务上帮助有限。
- **[Thinking Fast, Anywhere: One System-1 for the Decision Points of Any Agent Workflow](https://arxiv.org/abs/2611.23751)** · Rui Li 等（HF 组织：University of Science and Technology of China）· 2026-11-18 · HF ↑5 —— AnyS1 从 1,000 多个公开 skill 的指令里挖出可枚举的决策点，在隔离容器里采集执行轨迹，训练一个 4B 的校准小模型处理常规选择，置信度低于阈值时回退大模型；在三个未见基准上保持可靠性，同时把单次任务成本降低 75%–91%、模型调用时间降低 63%–92%。
- **[QDA: Closed-Loop LLM Quantization Design with Agents](https://arxiv.org/abs/2611.23388)** · Xingyang Li 等（HF 组织：MIT HAN Lab）· 2026-11-17 · HF ↑8 —— 让 agent 多轮设计每个模型的量化方案，关键是快速评测：用 agent 看不到的推理轨迹上的输出 KL 散度在几分钟内给候选打分，再对有希望的候选做长生成检查重复循环等问题。每次搜索 64 GPU 小时，在四个推理模型上比最强公开方案平均高 0.9–2.2 个百分点。
