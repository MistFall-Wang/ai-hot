## 今日判断

- 【必看】自改进闭环里，被训练的模型不能当自己的裁判：美团把巡检、归因、修复构造全部交给外部强模型，自研模型只负责"把纠正后的行为学进自己的分布"，并保留"无法判断"这个结论。自己做反馈闭环时，先把"发现失败的系统"和"给候选模型打分的系统"分开，再谈训练。
- 【警示】离线通过率高不代表能上线：美团第一版模型模拟测试通过率 93.0%，巡检 Bad Case 率却是 6.42%，比没训练的基座（5.59%）还高，线上满意度落后 4.57 个百分点。AIChipBench 里 69 个通过验收的设计有 45 个在新序列上失败。验收集之外必须留一批候选模型没见过的检查。
- 【结论】修复样本只改"第一个错误决策"，而且不能用事后才知道的信息：首错之后的轮次建立在错误状态上，没有正确答案可言；用事后信息写修复，模型学到的是断言自己看不到的事实。给 agent 做失败回放训练或写 few-shot 纠错例子时，照这两条约束构造。
- 【值得盯】多 agent 要和"同预算的单 agent 多试几次"比：Hugging Face 的实验里，未训练团队试 8 次只解出 37.5% 的题、花约 10.3 万 token，训练后团队一次解出 82.3%、花约 8,000 token。评估自己的多 agent 方案时，先做等预算对照，再谈合作收益。
- 【利好】harness 里"保留可单独访问的历史记录"比"滚动摘要"好，"删掉长期没用的经验"比"合并或升级成规则"好：HKUST 的对照研究在 MLE-Bench 和 KernelBench 上得出这两条，组合后 MLE-Bench Lite 奖牌率 72.7%。NVIDIA 的实验也显示让模型自己决定何时压缩，在 32K 预算下 GPT 6.1 得分从 21% 升到 56%。

## 今日话题

### 【必看】美团公开生产环境的模型自改进闭环：判断交给外部，经验来自自己
美团的实践把 RSI 拆成可审计的几步，每一步只做一个判断，并且每一步都有防止"错误自我确认"的设计：巡检模型看不到会话来自哪个模型版本，归因先排除工具和 SOP 的责任，修复只改首错且不预知，Teacher 是冻结的模型副本。同一天 HF 论文页上的两篇论文走的是相反方向的简化：TT-RSI 完全不用标签，让模型在测试时参考自己上一次的解答再蒸馏进权重；ELITE 在进化循环里不跑任何下游任务评测，只做结构检查。三者放在一起看，分歧点正是"自改进到底需要多强的外部判断"。

### 【值得盯】harness 怎么保存经验：留原始记录、删没用的 skill、让模型自己压缩上下文
HKUST 的对照研究把 autoresearch harness 拆成上下文管理和 skill 管理两个维度单独测，结论是保留可单独访问的历史尝试比滚动摘要好，删除长期不用的经验比合并或升级成常驻规则好。NVIDIA 在自家开源 harness 里把压缩的时机和内容交给模型决定，预算越紧收益越大。SEEK 把同样的思路用到机器人上：把操作写成可执行的程序，再把每个动作的实测效果（包括失败的）存进经验库，十次尝试后成功率从 19.7% 升到 48.0%。

### 【警示】评测在查"结果对了但过程不对"：四个新基准都把过程证据单独打分
ROAM-Bench 用仿真状态和运行记录独立检查任务要求，发现前沿模型有两种互补的失败：结果正确但要求没满足，以及检查都过了但结果错。AIChipBench 发现通过验收的硬件设计有近三分之二在新序列上失败，把反馈指向"第一个状态不一致"能把通过率提高 25 到 46.9 个百分点。AIRIS 只给模型当前时刻之前的画面，惩罚证据不足就下结论。EgoUseBench 测用户意图中途变化时 agent 能否修正，在线场景成功率比普通计算机使用低 26.3%。Hugging Face 的多 agent 文是同一个问题的另一面：成功率、token 用量和沟通结构要一起看。

- 【必看】⭐ 🧪 **[从模仿到自我纠错：Keeta客服模型的RSI实践](https://tech.meituan.com/2026/11/26/Agent-RSI-practice-in-meituan.html)** · 出处：美团技术团队（tech.meituan.com）· 2026-11-26 —— 美团想用自研的 31B 模型替换外卖售后客服背后的闭源强模型，方案叫 CARE，分两阶段。冷启动只做一次：把线上历史会话按准入、分配、精修三步治理成训练数据做监督微调，人工客服会话只提供措辞，不提供业务内容。之后进入递归迭代：模型承接部分流量，全天巡检先粗筛排序，细查名额分给最可疑、拿不准、随机抽查三类，一个模型分析、另一个独立复核，必须指出唯一出错轮次且证据完整才算 Bad Case；归因把工具、SOP、Harness 的问题转给组件负责人；修复只替换第一个错误决策，遵守局部、可行、不预知、按事发时 SOP 四条约束；训练用在线自蒸馏（OPSD），Teacher 是冻结的模型副本加特权信息，损失取 Teacher 前 32 个 token 的 Forward KL 并设零下限。上线前要过模拟测试（559 个冻结用例，只有系统模拟器能改业务状态）和离线巡检，综合分不退步才进线上对比，最后人工审批。五轮后 Bad Case 率 6.42% → 1.97%，综合分 96.07（比线上强模型低 0.03），满意度差值从 −4.57 到 +1.73 个百分点，单均服务成本降 70.5%。文末写明三点不足：模拟器与线上的差距未量化、归因准确率未统计、多版本 SOP 混训的好处未验证。**可借鉴**：做失败回放训练时照搬两条约束——只修"第一个错误决策"（之后的轮次建立在错误状态上），修复内容不能比模型当时拿到的信息更具体；并且让巡检模型看不到会话来自哪个模型版本或实验分组，避免它看标签下结论。
- 【注意】🧪 **[Swarms, Flocks, Gangs: How to build, train, and evaluate multi-agent systems](https://huggingface.co/blog/training-swarms)** · 出处：Hugging Face 官方博客 · 2026-11-26 —— 多 agent 系统系列第一篇，先讲背景再给可复现实验。背景部分提醒大规模 swarm 不等于合作有效：文中引用的估计是 OpenAI 的 Navier-Stokes 结果里不到 10% 来自多 agent 合作，Anthropic 的漏洞挖掘实验按相同目录比较时每百万 token 的产出与独立 agent 差不多。实验复现 s³ 论文的信息汇聚任务：四个 agent 共享一个 Qwen3-0.6B 策略，各拿一个 1–99 的私有数字，靠 message / read_messages / check_notifications 三个工具沟通，至少一人提交完整排序就算成功；奖励是团队共享的，成功后按 token 用量打折；每题采 8 次团队尝试，组内归一化算优势。75 次更新后训练成功率 6.6% → 82.3%，留出题 32 题对 26 题，每队生成 token 从约 1.3 万降到约 8,000（降 37.4%），广播次数反而从 2.38 升到 5.73。原实验用 1 张训练卡加 7 张 H200 跑 rollout；文中给出两张 H200、约 5 小时、约 50 美元的 HF Jobs 复现脚本。**可借鉴**：评估多 agent 方案时固定做两个对照——同等总预算的单 agent，以及"未训练团队重试 N 次取最好"（本文里重试 8 次只有 37.5%，token 是训练后团队的约 13 倍）；成功率、token 用量、沟通结构三项一起报，不单看成功率。

## 论文（自演进、评测优先）

- ⭐ **[Beyond Self-Consistency: Recursive Self-Improvement at Test Time](https://arxiv.org/abs/2611.30965)** · Jianyu Wu 等 10 人（HF 页面标注机构：Shanghai AI Laboratory）· 2026-11-23 · HF ↑14 —— 测试时自改进通常靠自洽性：独立生成多个解再多数投票，早先的推理用不上，训练时还会强化错误的多数。TT-RSI 不用标签，分两部分互相增强：上下文内 RSI 让模型拿上一次的完整解答当参考重新解题，自己决定用不用；权重内 RSI 把逐次改进蒸馏进权重，使第一次作答逼近多步改进的极限。平均准确率比基座高 13.89%，同等测试时预算下比最强的自洽性方法高 4.79%。**可借鉴**：做多次采样时，把上一次的完整解答作为参考传给下一次，让模型自己决定是否沿用，比独立采样再投票更能利用已花的算力。
- ⭐ **[Evaluation-Free Recursive Self-Improvement for Coding Agents](https://arxiv.org/abs/2611.21056)** · Zhe Ren 等 8 人 · 2026-11-16 · HF ↑3 —— 自改进编码 agent 通常靠"在下游任务上评测再选优"决定哪条谱系继续进化，评测成本随探索变大，还容易过拟合基准。ELITE 改成"先探索再整合"：每代从同一父代独立实现多个改进，检查这些程序里互补、冗余、冲突的机制，把相容的子集重新实现成一个后代，循环内只做结构和运行有效性的确定性检查。SWE-bench Pro 上从 60.0% 到 85.6%，对比 DGM 的 86.7% 和 HGM 的 88.3%，候选评测次数为零，进化耗时分别缩短 8.8 倍和 3.2 倍；不再适配直接迁移到 SWE-bench Verified 为 73.3%。**可借鉴**：改进 agent 脚手架时，可以把多个独立改动"读代码后合并"而不是"逐个跑基准挑一个"，评测只留到最后做一次，省掉循环内的评测开销。
- ⭐ **[Demystifying the Autoresearch Harness: How Context and Skills Shape Self-Evolving Agents](https://arxiv.org/abs/2611.28244)** · Kelvin Kiu-Wai Tam 等 11 人（HF 页面标注机构：HKUST）· 2026-11-20 · HF ↑5 —— 现有 autoresearch harness 把多种机制混在一起，说不清各自贡献。作者在同一框架里以"按时间截断"为基线，分别测上下文管理（保留哪些过去的尝试）和 skill 管理（经验怎么存、怎么复用），覆盖 MLE-Bench 与 KernelBench、三个模型。结论：保留可单独访问的历史尝试记录比滚动摘要好，上下文折叠在六个设置里全部最好，最多比基线高 19.2%；skill 方面，删除长期没被用到的经验平均好于合并或升级为常驻规则。两者组合成 MLEvolver，MLE-Bench Lite 奖牌率 72.7%，KernelBench Level 3 的 fast_1 为 94%。**可借鉴**：给长程 agent 做记忆时，历史尝试按条存、按需展开，不要只留一份滚动摘要；skill 库定期删掉长期没被调用的条目，不要一味合并或升级成规则。
