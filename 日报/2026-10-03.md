## ⭐ 自演进重大发现

- **自演进的新红线有了硬数据：环境一变，沿用历史评分会把不安全程序留下来**（arXiv 2610.01073，10 月 1 日提交，10 月 2 日公告）：在有状态的授权任务上做受控的递归自改进实验，固定的 LLM 编辑器反复优化 agent 的可执行组件。新增一条授权依赖让旧测试失效后，**48 条演化史里 22 条因为沿用历史分数而保留了同一批不安全程序**，尽管每个存档里都有正确替代；刷新分数能恢复原测试集的正确性，但独立组合的测试上仍有残余失败。从共同失败点出发，**改初始实现比改失败的那版恢复得更好**；全量验证加带验证的回滚最终得到完全正确的程序，并保留 43% 以上的部署节省。与周报 10-02 的判断一致，本期按日报首次登记。→ 见论文区。
- **冻结模型上的 harness 演化再添两组硬数据，「课程」与「证据」成为新变量**：Microsoft 的 ActiveSaddler（2610.00906）把训练场景建模成非平稳 bandit、把反复失败抽象成可复用的「失败模式臂」，GAIA2 与 Terminal-Bench 2.0 上比固定场景顺序的同一优化器高 4.4 和 7.5 个百分点；GUI-HARVEST（2610.00948）把模型输出、实际动作与前后截图对齐，评测前先记录预测再用重复执行核对，OSWorld-Verified 六个骨干留出集全部提升（Qwen3-VL-32B +12.33 分），冻结 harness 迁移到 WindowsAgentArena 让 GPT-5 +13.87 个百分点。与 10-02 推送的 MILO 是同一方向的独立证据。→ 见论文区。

## 今日判断

- 【警示】**自演进系统里，环境或契约一变，历史评分必须全部重测，回滚目标选初始实现而不是失败的上一版**。22/48 的演化史因沿用旧分数保留了不安全程序，这是能直接写进验收规则的数字；配套的做法是 skill 回归测试查轨迹不只查答案——175 次通过全部终值检查的运行里 162 次（92.6%）仍有过程偏差。
- 【结论】**选模型先选 harness，评测报告必须写明 harness 与重复次数**。同一模型在不同 harness 上差 30 分，模型排名会反转；同一配置重复运行贡献约 54% 的方差。只跑一次、只换模型不换 harness 的对比不能作为选型依据。
- 【必看】**OpenAI 把「决策边界」写进 AGENTS.md，长任务控制面（mid-turn steering、异步工具、委派）成了标准接口**。对照 Anthropic 本周的 effort 与 Sonnet 5.5 指南，两家的建议已经收敛：skill 描述短而明确、把「完成」定义到跑通并修复、用留出任务验收。把自己的 AGENTS.md / CLAUDE.md 按「可自主 / 需审批」两栏重写一遍。
- 【利好】**代码执行型 harness 比 tool-calling 又省又准**：同一个 GPT-6 Astra 规划器下，把原语组合成 Python cell 并只回传请求过的观测，成功率 63.1% → 71.7%，token 少 65%。这与 Anthropic 去年「code execution with MCP」的方向一致，工具多、观测大的场景优先走代码执行。
- 【值得盯】**Anthropic 的 FDE 学院是企业落地岗位需求的官方信号**：1 亿美元、1 万名 Frontier Deployed Engineer、提名制、12 周驻厂实战，首批来自咨询与金融。面向 AI 应用工程师的岗位画像正在被厂商定义，准备面试时值得对照它的考核内容（从用例选择到安全评审到交接）。

### 【警示】自演进的安全红线：旧评分、旧状态会把不安全的东西带进下一代

三篇论文从不同层面说同一件事：自改进系统里，「过去通过」不等于「现在安全」。受控 RSI 实验给出 22/48 的保留率；80 页综述把失败定义为「合法状态在适应过程中扩大了持久性、权限或作用范围」，并指出修复已受影响的后代和演化后再评估是研究空白；企业 skill 的过程级评估则显示只看终值会漏掉 92.6% 运行里的过程偏差。做自演进 skill / harness 的人，验收规则要同时包含全量重测、带验证的回滚和轨迹级检查。

### 【结论】模型与 harness 要配对评测：排名随 harness 反转，一半方差来自重复运行

## 论文（自演进优先）
