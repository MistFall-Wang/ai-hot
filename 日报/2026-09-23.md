**论文（11 篇）**：本期 arXiv 集中在「harness 自演进」这条线上，且出现了两个方向相反但互相印证的结论——RRSI 证明不加约束的 harness 递归自改进会过拟合训练基准（分布内涨 14.1 分，五个分布外基准只涨 4.7 分），Harness-Zero 证明 harness 带来的收益可以被蒸馏进模型权重、部署时把 harness 摘掉仍然更强（23.3% → 44.3%）。另有两篇专门做「自演进的刹车与体检」：Self-Healing Harness 给自我修改加了准入门禁，EvoPathBench 提出按过程而非终点评估自演进。

**最值得看**：RRSI（arXiv 2609.24972，HF ↑152）。它是本期唯一一篇同时给出「自演进有效」和「自演进会骗自己」两组硬数字的论文，而且它开出的药方（提案端退火预算 + 选择端 critic/pruner）是任何做 agent 自优化的团队都能直接照抄的工程约束。工程落地的第二顺位是 OpenAI 那篇 prompt caching——它提供的诊断字段和「用 append-only 方式改工具定义」的写法，可以今天就改进自己的 agent 成本曲线。

## 今日判断

- 【必看】harness 自演进的第一个可信负面结果出现了：**分布内的涨幅不能当能力看，必须有分布外基准做对照**。RRSI 的 14.1 vs 4.7 是这条判断的量化版本——如果你在做自动提示词/自动流程优化，没有 OOD 保留集就等于在测自己的记忆力。
- 【必看】**prompt 缓存已经从省钱技巧升级为可观测性问题**。OpenAI 这次给出的 `cache_miss / reason: tools_changed / cache_missed_tokens` 这类诊断，意味着「工具定义顺序变了导致缓存全失效」这种事故从今天起可以被定位。在自己的 agent 里也该做同样的事：把命中率当指标监控，而不是等账单异常才查。
- 【利好】**同等能力的价格在一天之内被两家同时打下来**：Opus 5.5 缓存读取降到 $0.20（比 Opus 5 低 60%），GPT-6 Sol/Luna 直接对折。长时 agent 的成本结构里缓存读取占大头，这两条叠起来意味着同样的产品设计，本月的单位经济性比上月好一个档。
- 【警示】**自我修改的「局部有效」和「全局无害」是两件事**。Self-Healing Harness 在 16 组对照里拒掉 383 条自改提案，其中 211 条（55%）确实修好了触发它的那个失败，同时弄坏了一个原本能过的用例。任何让 agent 改自己规则/记忆/技能的系统，都必须配一个跑回归的准入门禁，而不是只看「这次好了没」。
- 【值得盯】**harness 的价值正在往模型权重里迁移**。Harness-Zero 说明特化 harness 的行为可以被内化，部署时不需要它还在场。如果这条路走通，「维护一大堆领域专用 harness」这件事在中期会贬值，而「把 harness 行为变成训练数据」会升值。

## ⭐ 自演进重大发现

- **harness 递归自改进的第一组「有效但会骗自己」硬数据**：RRSI（arXiv 2609.24972，HF ↑152）在八个基准上测量了不加约束的 harness 自演进——它演化所针对的那个 split 上最多涨 14.1 分，但换到五个分布外基准只剩最多 4.7 分，说明现有的「自动提议+自动筛选 harness 编辑」在很大程度上是在记忆训练任务。RRSI 给出的约束方案（提案端按时间退火限制单次编辑数量、鼓励未探索方向；选择端用 critic 筛掉基准专用提案、用 pruner 删掉太小/太贵/已失效的改动）把 OOD 收益保住的同时，让产出的 harness 少用 30% 的 policy token。**这是一条新的方法学红线：自演进系统的收益必须报分布外数字，否则不成立。**
- **同期出现的第二个反向结论**：Harness-Zero（arXiv 2609.24974）证明 harness 带来的收益不必永久挂在系统上——用优化过的 harness 作为训练期指导、把它诱导出的行为蒸馏进权重后，基座模型在固定目标 harness 下的宏平均任务成功率从 23.3% 升到 44.3%，甚至高于挂着那个特化 harness 时的 41.7%，并恢复了三个领域 28 种行为模式中 82.3% 的 harness 诱导行为。

## 官方长文（工程/研究）

- 【必看】**[Better prompt caching for GPT-6](https://openai.com/index/better-prompt-caching-for-gpt-6)** · 出处：OpenAI（openai.com/index）· 09-22 —— GPT-6 家族上线的新版 prompt 缓存系统说明，把缓存从「后台自动优化」变成开发者可观测、可诊断、可主动控制的工程对象。**默认行为**：缓存输入 token 最高 90% 折扣，符合条件的共享前缀在 30 分钟窗口内复用，默认命中率比上一代更高。**可观测**：新的 Prompt Caching Dashboard 显示应用有多少输入来自缓存、命中率随时间的变化、缓存与未缓存 token 的构成对比。**可诊断**：未命中时返回 `prompt_cache_diagnostics`，给出未命中类型、原因（示例中是 `tools_changed`）、本可复用的 token 数与实际未命中的 token 数，可以直接定位是哪次改动打断了复用。**四条主动控制手段**：①显式缓存断点，自己选择哪些前缀要复用；②GPT-6 上可以在两次响应之间用 `configuration_update` 改 reasoning effort 而不破坏缓存（难任务提 effort、常规追问降 effort，上下文照样复用）；③工具变更用追加而非删除——保持工具定义、schema、顺序稳定，用 `allowed_tools` 控制可调用范围、`tool_choice: none` 表示不用工具，新指令用 developer message 追加到上下文末尾覆盖旧指令；④预热缓存，在启动时先把共享指令、工具定义、参考资料处理好，把这部分处理时间移出用户等待。**可借鉴**：三条可以立刻照做——把缓存命中率当成和延迟、成本并列的常规监控指标；把「工具定义只追加不删改」写进自己 agent 的开发约定（这是长时 agent 缓存失效最常见的原因）；用预热把冷启动的首 token 延迟移到用户到达之前。
- 【必看】**[Enabling Private High-Performance Production AI Inference with NVIDIA Confidential Computing](https://developer.nvidia.com/blog/enabling-private-high-performance-production-ai-inference-with-nvidia-confidential-computing/)** · 出处：NVIDIA 开发者博客（Agentic AI / Trustworthy AI）· 09-22 —— 面向要在受监管环境里跑 LLM 推理的平台工程师，回答「开启机密计算要付多少性能代价」。**结论**：在 1 台 DGX B200（8×B200）、Intel TDX 平台、TensorRT LLM PyTorch 后端、DeepSeek-R1-0528-NVFP4 模型、32K 输入/1K 输出、TP=8、FP8 KV cache 的配置下，并发 1–16 时开启机密计算保留了 96.1%–98.2% 的输出吞吐，平均 TPOT 只比基线高 1.2%–4.3%。**方法学**（这才是可迁移的部分）：要暴露机密计算的开销，必须故意挑「长输入 + 长输出 + 低并发」的负载——长上下文压 prefill 阶段的数据搬运，长生成放大 decode 阶段每 token 的小开销，低并发让这些开销无法被并发请求掩盖；高并发会把固定加密成本摊薄，反而测不出来。对照实验只允许机密计算状态这一个变量变化，模型、硬件、框架版本、序列长度、并行度、并发全部固定，指标用「吞吐保留率」和「TPOT 开销百分比」两个比值。**框架侧适配**：机密执行改变了内存搬运、计时、调度、多 GPU 通信的假设，框架必须感知——例如自动调优时改用 GPU `%globaltimer` 做 tactic 测量、机密环境外仍用 CUDA events。**可借鉴**：这套「挑最坏负载 + 单变量对照 + 报比值不报绝对值」的做法可以直接搬去评估任何一项安全/合规开关（沙箱、审计日志、加密存储）对推理性能的影响；结论本身则说明「隐私合规」不再是性能上的硬约束，代价已经压到个位数百分比。
