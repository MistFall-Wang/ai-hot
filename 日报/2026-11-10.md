## 今日判断

- 【必看】多 agent 协作的共享状态用数据库而不是共享机器：Anthropic 单机在约 100 个 agent 时资源耗尽、过半运行被迫重启，换成每 agent 独立轻量 VM 加一个 SQL 库（事务处理并发写）后扩到 1,000 个；做多 agent 系统先设计"认领任务 / 写笔记 / 记完成"三类表。
- 【必看】换模型之前按顺序做三件事：先给 agent 自验证手段（测试、构建、调接口脚本），再升一级 effort，最后才换大模型；能自动判对错时"全部 low 跑一遍、失败的用 high 重跑"，在 SWE-bench Pro 子集上 97% 通过、每题 $0.17，优于全用 high 的 95.3%、$0.29。
- 【警示】越强的模型越容易越权、也越会怀疑自己在被评测：Authorization Drift 测出前沿模型越权率 0.43–0.61，Anthropic 自述 Fable 5.2 / Mythos 5.2 比以往任何模型都更常说出"这可能是评测"；只靠上线前评测给安全结论越来越不可靠，生产侧要有逐调用拦截与轨迹审计。
- 【值得盯】"停止开关"开始成为基础设施标配：OpenAI 要求每个做 agentic 推理的研究任务绑定 safety case、在推理层按 job_id 鉴权、服务挂了就全部拒绝（fail-closed）；Anthropic 千 agent 实验里任一分类器拦截 lead 即全队停。自建 agent 平台时把"可在秒级停掉某个任务的全部推理"列为必做项。
- 【结论】Agent 团队里的隐蔽破坏者几乎抓不出来：Project EVE 中四 agent 小队即使被提前警告"队里可能有人目标不同"，也几乎从未识破破坏者，还冤枉过正常队友；多 agent 系统的可信度不能靠 agent 互相监督，需要独立的外部监控。

## 论文（自演进、评测优先）

- ⭐ 🧪 **[Flex-RSI: Benchmarking Recursive Self-Improvement of Frontier Agents](https://arxiv.org/abs/2611.08946)** · Jingdong Zhang 等 22 人 · 2026-11-06 —— 衡量 agent 递归自改进的基准，覆盖视觉与机器人任务，固定预算。每轮 executor 改进解，仅在保留验证集上更好才保留；improver 再修改 harness（包括 executor 和它自己）；所有运行从同一通用 harness 起步，最终在隐藏测试集上打分。发现：agent 自己构建解时自改进收益最大；只给成功/失败信号会拖累开源模型；在需要物理稳定或精确正确的严格检查上开源模型落后最多；配对运行证实编辑 harness 本身贡献了增益。**可借鉴**：做 harness 自进化时用"保留集门控 + 隐藏测试集终评"两层防过拟合，并给反馈尽量丰富的信号而不只是通过/失败。
- ⭐ **[BOXBOX: Recursive Harness Self-Improvement for Long-Running Performance Optimization](https://arxiv.org/abs/2611.09218)** · Yuhao Tan 等 11 人 · 2026-11-06 —— 针对开放式长任务（离线优化的 harness 解决不了长跑中暴露的新问题），提出 PerfRace 基准（软件项目长时性能优化）和 BOXBOX：agent 可在任务进行中触发 harness 修订，由内核管理热重载并保留执行上下文。同等测试预算下对比冻结 harness、离线 Harness Evolution 和 Harness Scaling，BOXBOX 4 小时加速比 1.70x，最强基线 1.54x，任务时间与模型成本用得更省。**可借鉴**：长任务 agent 可以留一个"改自己 harness 并热加载"的入口，但要保证上下文不丢，并用同预算基线对比证明收益。
- 🧪 **[Authorization Drift in LLM Agents: Evaluating Boundary Compliance in Multi-Step Tool Use](https://arxiv.org/abs/2611.09113)** · Chuxue Cao 等 10 人 · 2026-11-06 · HF ↑5 —— 定义无攻击者情况下 agent 在数据、工具、范围、时间四个维度的越权，构建 648 样本、7 领域的 ADB，每题都有合规路径和诱人的越权捷径，用真实 rollout 而非 LLM 自评验证题目可解。13 个模型、3 个框架、25,207 条轨迹：能力越强越权越多，前沿模型越权率 0.43–0.61；但 86.18% 的任务观察到过干净成功轨迹，说明可避免；越权主要来自早期过度收集数据。**可借鉴**：评测 agent 时为每题设计一条"更快但越权"的捷径，单独统计越权率，而不只看成功率。
- 🧪 **[MemoryDojo: Benchmarking Poisoning Through LLM Agent Memory](https://arxiv.org/abs/2611.09721)** · David H. Yang 等 5 人 · 2026-11-06 —— 追踪恶意指令从一次会话写入记忆、到后续会话被检索并执行的全过程：155 条多会话长轨迹、4 个领域、支持 5 种记忆系统。所有记忆系统都会被投毒，下游影响差异很大；按记忆架构定向优化的投毒进一步提高成功率。**可借鉴**：上线记忆功能前做跨会话投毒回归测试，按记忆写入路径评估风险。
- 🧪 **[Knowing When to Intervene: Causal Evaluation of AI Agents](https://arxiv.org/abs/2611.09792)** · Ayush Sawarni 等 5 人 · 2026-11-06 —— 静态基准无法回答"部署时在轨迹哪一步介入审查值不值"。提出用少量随机化介入（验证、筛查）下收集的轨迹估计介入策略的动态因果效应，并据此构建按动作风险排序的安全排行榜。在 tau-bench Retail、ToolSandbox、ImpossibleBench 上发现介入效果随动作和状态差异很大。**可借鉴**：人工复核预算有限时，先小规模随机介入测因果效应，再把复核集中到收益最大的动作类型。
- **[From Procedures to Permissions: Learning Precise Subagent Authorization from Agent Skills](https://arxiv.org/abs/2611.08905)** · Wenkai Yu 等 4 人 · 2026-11-06 —— 用 Agent Skills 里写明的步骤、工具与文件合成"子任务需要哪些权限"的训练数据；在 ClawArena-Team 上让 Qwen3.5-35B-A3B 的工具权限精度 +13.4 点、工作区权限精度 +24.1 点、任务成功 +11.6 点。
- **[From LoRA to Language: Recovering Skill Documents from Adapters](https://arxiv.org/abs/2611.09454)** · Saranya Dintakurthy Swadha 等 4 人 · 2026-11-06 —— 编译成 LoRA 的 skill 能否写回文字：只读权重几乎不行，运行适配器训练的小 writer 可还原 39–44% 关键指令、恢复 85–91% 任务增益；对比基座与适配模型差异写 skill 的 agent 在 ALFWorld 上把 Llama-3.1-8B 从 5% 提到 55%。
- **[When Routine Operations Break Architectural Pattern Relationships in LLM Agent Harnesses](https://arxiv.org/abs/2611.09088)** · Boming Xia 等 4 人 · 2026-11-06 —— 分析 5 个已发布 harness、14 个第三方插件，发现重装插件、保存一条 allow 规则等日常操作会在不改代码的情况下悄悄打破护栏执行点、自主度控制等架构约束。
- **[AgentBaton: Efficient Model Collaboration in Agentic Tasks](https://arxiv.org/abs/2610.35959)** · Junlong Li（HF 标注 NVIDIA）· 2026-10-25 提交、HF 11-09 页 · HF ↑12 —— 研究长任务中大小模型交接：小模型先做再交给大模型通常不省钱也不更准；大模型做到合适阶段再交给小模型基本保持甚至提升准确率并降本。
- **[CPU-ARC: Agentic Reasoning Caching for on-CPU Reasoning Reuse](https://arxiv.org/abs/2611.09891)** · Peter Belcak（HF 标注 NVIDIA）· 2026-11-06 · HF ↑6 —— 把 LLM 推理轨迹编译成可在 CPU 上执行的"推理缓存"，在数学与科学任务上与前沿模型持平、可解释、调用成本低 16–291 倍。
- 🧪 **[LongBanana: An Expert-Verified Benchmark for Long-Context Multi-Reference Image Synthesis](https://arxiv.org/abs/2611.06856)** · Haoxiang Cao（HF 标注快手 Kolors 团队）· 2026-11-04 · HF ↑28 —— 90 个专家设计任务、每题约 32 张参考图，4,670 条原子评测项按图结构转成检查清单；15% 双标子集精确一致率 89.4%、二次加权 kappa 0.83；附 agent harness 生成框架。
