## ⭐ 自演进重大发现

- **优化器也能自演化，但前提是执行验证；失败经验要按需暴露，不要常驻上下文**（arXiv 2610.02616 VERSE、2610.02994 Sentry，均 10 月 2 日提交、10 月 5 日公告）：VERSE 的对照实验显示，**没有基于执行的验证时，优化器自演化不提升效果；有了验证，它在同一实验里取得最好结果**。允许优化器在提交前回放失败、扰动可疑步骤并跨轮追踪修复与回退后，四种 harness 优化器在留出的 SWE-rebench 上全部提升，最佳 harness 达 42.3%（最强基线 39.2%），五种语言的分布外任务达 37.7%（基线 29.3%），模型权重全程不动。Sentry 则发现失败教训是条件性知识：放进不断演化的 playbook 常驻上下文会在无关时误触发，**删掉它们反而涨分**；改为出错时检索、确认恢复后才写回，平均比最强运行时干预基线高 37%，比最强上下文演化基线高 39%，而且即使相关教训可按需取用，把整本 playbook 暴露给 agent 仍会降分。→ 见论文区。

## 今日判断

- 【结论】**自演进 harness 的每一次修改都要先在执行环境里验证再提交，包括优化器对自身的修改**。VERSE 的对照组说明，没有执行验证的自改进只是在空转；这和上周「环境变了要全量重测」那条红线是一回事：没有可执行证据的改动不能进存档。
- 【必看】**经验库不要整本塞进上下文**。Sentry 的数据表明，整本 playbook 常驻上下文会让无关教训误触发，按失败类型检索、恢复后才写回更好。自己的 CLAUDE.md、skill 库和 memory 都该检查一遍：哪些是常态规则，哪些其实是「出了某种错才需要」的条件知识。
- 【利好】**skill 包里最值钱的是可执行工具**。FinSkillBench 上精心准备的 skill 包平均 +16.2 分，拆开后工具单独 +19.5、文档单独 +5.6，两者合用小于相加；agent 在单个 episode 里自己写的 skill 只 +0.5 分，token 还更多。写 skill 时先把计算和校验做成脚本，文字说明放第二位。
- 【警示】**别用公开基准分数挑注入检测器，也别把模型或 harness 当安全边界**。BIPIA 第一名的检测器在 1% 误报率下只抓到 AgentDojo 2% 的注入；工作区 agent 九种配置里最差的攻击成功率 68.44%；良性多 agent 场景里 9 个前沿模型有 7 个会把不该给的凭据藏进需求文档帮对方拿到。检测器要用自己 agent 的工具输出评测，凭据与出网要在基础设施层隔离。
- 【值得盯】**代码评审 agent 有了公开的、离线与线上一致的基准**。ReviewBench 公开了数据、评分规则和裁判（Claude Sonnet 5），可以自带 agent 跑分。做 coding agent 作品集或面试准备时，这是现成的、可被复现的评测对象。

### 【记录】长期记忆评测转向真实对话：过去很少被需要，且没有检测器能判断何时需要

RealCompanion 用十段真实的人与 AI 陪伴对话（最长 120 天）发现：最近窗口能找到 95.9% 探针所需的消息，真正需要远期记忆的探针里只能找到 2.2%，而且没有检测器能判断某条消息是否需要记忆。DyadMem 把「agent 该怎样与这个用户协作」单列为一类记忆，给定正确记忆时问答很强，换成完整流水线就大幅下降，主要卡在捕获召回低和不安全的删除。

## 论文（自演进优先）

- ⭐ **[VERSE: Verified Self-Evolving Optimizer for Agent Harnesses](https://arxiv.org/abs/2610.02616)** · Zekai Wang 等 9 人 · 2026-10-02 —— harness 优化器通常只改被优化 agent 的 prompt、工具和流程，自己的工具和步骤固定不变。本文让优化器也演化自身的诊断、编辑和测试方式。对照实验发现：没有基于执行的验证时，优化器自演化不提升效果；有验证时取得该实验最好结果。VERSE 让优化器在提交前测试草稿编辑、回放失败、扰动可疑步骤，并跨轮追踪修复与回退，优化器和执行器的权重都不动。四种优化器在留出的 SWE-rebench 上全部提升，最佳 harness 42.3%（基线 39.2%），五种语言的分布外任务 37.7%（基线 29.3%）。**可借鉴**：自演进流程里给优化器配一个「提交前回放失败用例」的工具，并跨轮记录哪些修复引入了回退，没有执行证据的改动一律不合入。

- ⭐ **[Sentry: Learning to Recover from LLM Agent Failures at Test Time](https://arxiv.org/abs/2610.02994)** · Changxiu Ji 等 4 人 · 2026-10-02 —— 研究失败经验应该怎样交给 agent。发现失败教训是条件性的：常驻上下文时，在对应失败没发生的场景里会误触发，从演化中的 playbook 删掉它们反而涨分。Sentry 是与 agent 并行的失败管理层：检测到失败时才从外部 playbook 检索匹配教训，在不看任务奖励的情况下验证 agent 是否恢复，只有恢复成功才写入新教训，整本 playbook 不进上下文。平均比最强运行时干预基线高 37%，比最强上下文演化基线高 39%，与上下文演化叠加还能再涨，教训可迁移到留出任务。**可借鉴**：把 memory / skill 库分成「常态规则」和「出错时才查的教训」两层，后者挂在失败检测钩子上按需注入，写回前先确认这次恢复真的成功。

- ⭐ **[Recursive Harness Self-Improvement for Frontier Reasoning Data Synthesis](https://arxiv.org/abs/2610.03548)** · Wenlong Zhang 等 8 人 · 2026-10-02 —— 合成越来越难的推理题时，以往只把生成的题目当种子递归，构造题目的 harness 不变。本文让任务与 harness 协同演化：生成过程中把求解器的中间失败转成可复用 skill（在线），每批之后修改 skill、prompt 和流程，只在「生成更难的有效题且成本增幅有界」时采纳（批后），权重和验证标准固定。数学、代码、科学三域经 14 轮演化，求解器平均准确率从 100% 降到 54.8%；两种更新节奏合用优于单独任一种或固定 harness。27B 学生模型用 1 万道合成数学题微调，APEX 上 mean-16 准确率 62.5%。**可借鉴**：自演进的采纳门槛写成「目标指标变好且成本增幅不超过阈值」的双条件，并把失败即时沉淀为 skill 与批后整体修订分成两个节奏。

- ⭐ **[Scaling Trajectories for Complex Tasks through Recursive Self-Rewrite](https://arxiv.org/abs/2610.02826)** · Zongxia Li 等 10 人（HF 组织 Tencent Hunyuan） · 2026-10-02 · HF ↑78 —— 专用 harness 能解出更难的任务，但其中的干预在部署时不可用。RSR 用同一个 Qwen-3.8-27B 在多种 harness 下找成功解，再改写成通用 harness 下的训练轨迹：规划器把过程提炼成 runbook，评审器筛掉验证器或答案泄露并引导递归修订，执行器在全新沙箱里按 runbook 重跑。约 3 千个自建终端任务上，三种 harness 合计解出 759 个，比最强单一 harness 多 34.3%；2,001 条源轨迹扩成 11,094 条用于 SFT。相比基座，Terminal-Bench 2 的 pass@3 从 57.0% 升到 74.2%，Terminal-Bench 4 从 1.5% 到 9.1%。**可借鉴**：多 harness 跑出的成功经验先提炼成 runbook、查泄露、在干净沙箱复现，再作为训练或 skill 数据，避免把专用 harness 的「拐杖」学进去。
