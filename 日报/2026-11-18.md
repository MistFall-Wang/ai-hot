## 今日判断

- 【必看】验证闸门要和被验证的改动隔离：Claude Code 团队的 Code Review 只从基础分支读 REVIEW.md，改动无法修改评判它的规则；自己的 agent 流水线里，测试、rubric、评审提示词都应放在 agent 写不到的位置。
- 【必看】评测器先过校准再用来判 agent：美团把校准集分成 Good、Bad、边界三类，确定性 Grader 发现线性顺序会误判合理的并行路径后改成 DAG，LLM Grader 用人机一致率抽检；并且明确"误判减少不等于 agent 变强"，改了尺子要用新尺子重跑基线。
- 【警示】Pass@k 和 Pass^k 要分开报：美团优化后 Pass^k 仍明显低于 Pass@k，瓶颈从"不会做"变成"不能稳定做对"；SWE-CoWork 里领先模型通过约 63% 的 F2P 测试但完整交付不到 8%。只报单次成功率会高估上线可用性。
- 【值得盯】RSI 相关能力已经进入正式发布流程：OpenAI 在发布文里确认 GPT-6.2 Astra 过了"AI 自我改进"High 阈值，同周宣布外部评估方进驻看训练过程；做 agent 的人短期内会看到更强的研究型模型，同时也会遇到更严的网络安全拒答（Astra 和 Sol 都达到网络安全 Critical 阈值，上线即收紧）。
- 【利好】长会话 agent 的算力成本有了可算的模型：Google 的数据是编码 agent 约 78% 时间在等用户，每小时 2 次提示时空闲挂起能省近 40% 节点费，超过约 4 次就不划算；先从网关日志统计每小时提示数再决定部署方式。

## 论文（自演进、评测优先）

- 🧪 **[Accelerate Bench: Evaluating Agents for Application-Level Program Optimization](https://arxiv.org/abs/2611.20882)** · Bowen Liu 等（HF 组织页：Tencent Hunyuan）· 2026-11-16 · HF ↑16 —— 32 个来自科学计算和超算竞赛的 CPU 优化任务，每题给可运行程序、负载、正确性要求和允许修改的范围，由 agent 自己决定改哪里，最终提交由独立验证器评分。16 个"模型 + harness"组合的 Score@1 在 25.5% 到 67.4% 之间，大多数程序是正确的，差距在加速幅度：前两名在 22 题以上达到 2 倍加速。对照重放显示同一份代码只改构建和运行设置就在 0.29 倍到 2.12 倍之间变化。**可借鉴**：评测优化类 agent 时，正确性和加速幅度分开计分，并固定构建和运行环境，否则分数差异可能来自配置而不是代码。
- ⭐ **[G-CAST: Governed Continual Self-Training for E-Commerce Agents under Evolving Demands](https://arxiv.org/abs/2611.17814)** · Yuechun Yu 等 · 2026-11-13 · HF ↑20 —— 针对电商导购 agent 面临的两种变化：用户需求分布漂移，以及 harness（工具、skill、操作流程）不断新增能力。G-CAST 把每天的生产数据按奖励路由、按熵排序转成训练数据，奖励函数本身也在受控流程下演进；每次模型更新都要通过累积评测才能切换检查点，目标是学会新行为的同时不丢已有行为。**可借鉴**：做持续自训练时把"新检查点能否上线"设为独立闸门，用累积的回归评测集判定，不能只看新任务上的提升。
- 🧪 **[SWE-CoWork: Benchmarking Coding Agents as Digital Employees in Organizations](https://arxiv.org/abs/2611.20218)** · Xinping Lei 等（HF 组织页：Tokenwave.AI）· 2026-11-15 · HF ↑44 —— 101 个真实仓库的开发任务，agent 置身于有 26 名同事的模拟工程组织，需要从同事和工作记录里拼出需求、处理相互矛盾的信息。11 个模型中领先的两个能通过约 63% 的 F2P 测试，但完整交付不到 8%；直接给全需求能把 F2P 提高约 16 个百分点，完整交付率却不变。**可借鉴**：评测编码 agent 时同时报"测试通过比例"和"整单交付率"，两者差距很大时问题在交付流程而不在需求获取。
- 🧪 **[VibePrevisBench: Evaluating Agentic Coding for 4D Scene Generation in Blender](https://arxiv.org/abs/2611.15789)** · Yuzhe Chen 等（HF 组织页：Kling-Keye）· 2026-11-11 · HF ↑88 —— 242 个任务，agent 根据剧本、照片或参考视频在 Blender 里搭 4D 场景并渲染预览视频。评分两层：规则检查重跑代码、按九个维度对比隐藏的标准答案；再由 VLM 评审判断通过的事实能否在视频里看出来。11 个前沿编码 agent 中，空间与镜头理解是主要差距，agent 会看自己的渲染结果但改不对。
- 🧪 **[JFinBench: A Continuously Refreshable Japanese Financial Benchmark from the Latest Certification Exams](https://arxiv.org/abs/2611.18130)** · Issa Sugiura 等（HF 组织页：Sakana AI）· 2026-11-13 · HF ↑7 —— 用 2026 年六种日本金融资格考试做的 321 题评测集，用"编码 agent 写转换代码 + 人工逐题核对并把修正反馈给 agent"的流程构建，便于每年刷新以避免数据污染。Claude Fable 5 和 GPT-6 Astra 总分超过 93%，最好的开源模型落后 12 个百分点。
- 🧪 **[Interpreting Coding Agents Through Their Behavioral Trajectories](https://arxiv.org/abs/2611.17440)** · Ibragim Badertdinov 等（HF 组织页：Nebius）· 2026-11-12 · HF ↑11 —— 分析 125 种 agent 配置、117 个模型的 143,209 条执行轨迹，用规则解析器把原始 trace 映射成搜索、编辑、测试等高层动作。解题率相近的 agent 在探索、修改、验证上的行为差别很大，仅凭行为画像就能识别出是哪种 agent 栈；scaffold 和推理强度会系统性地改变行为。解析器和标注数据已开源。

- 🧪 **[Invariant-Aware Harness Enforcement to Protect LLM Agents from Silent API Failures](https://arxiv.org/abs/2611.20595)** · Sajib Acharjee Dip 等（HF 组织页：Genentech）· 2026-11-16 · HF ↑2 —— API 有时会忽略部分请求（如拼错的过滤条件）仍返回 HTTP 200 和看似合理的错误结果。SilentGuard 在 harness 层用"正确 API 必须满足的不变量"检查每个返回，不满足就扣下不给模型。15 个公开研究 API 中 11 个存在这类静默失败；三个前沿模型的错误答案从 70.2% 降到 0.5%，而只给警告时仍有 70.1% 答错。**可借鉴**：工具结果校验要在 harness 里强制拦截，不能只提示模型"结果可能有问题"。
- **[Reducing Batch Makespan for LLM Agent Workloads through Inference-Environment Coordination](https://arxiv.org/abs/2611.16661)** · Wei Feng 等（HF 组织页：inclusionAI）· 2026-11-12 · HF ↑3 —— 针对评测、合成数据、RL rollout 中批量跑 agent 任务的场景，协调推理与环境执行：按负载分配 KV 缓存与循环状态显存、按轨迹路由提高缓存复用、环境容量受限时优先推进长链任务。在 BFCL、SWE-bench Multilingual 等基准上总耗时降低 10.4%–65.0%，评测分数不变。
