## 今日判断

- 【结论】计算机使用 agent 的成绩要分平台看：OS-Omni 上同一个模型在 Linux 超过人类、在 iOS 和 macOS 落后 25 个百分点以上。给产品选型或报成绩时，按目标平台单独测，不要用一个平均分代表全部。
- 【警示】让模型自己从失败经验里总结规则，收益没有想象的稳：NUS 的对照里没有任何一种自动上下文工程方法在所有任务上胜出，有时连思维链基线都比不过，而且失败模式越分散收益越小（相关系数 -0.5）。上线"经验记忆 / 自动写规则"前，先看失败是不是集中在少数几类。
- 【值得盯】只看"最终对不对"分不出两种 agent：DetourBench 里五个模型成功率从 58.7% 到 96.0%，按"走了多少冤枉路"排名却是另一个顺序。自己的评测里把成功、离完成还差几步、多走了多少步分开报。
- 【警示】只在一个数据库上比对结果的奖励会被钻空子：Text-to-SQL 的对照里 29.5% 的错误查询拿到满分，加几份隐藏的数据库副本后降到 16.8%，没有误伤任何正确查询。用执行结果当奖励或当评测答案时，至少多准备几份数据不同的环境。
- 【利好】答案能算出来的视觉题，让编码 agent 写程序比让视频模型直接生成可靠得多：三个闭源编码 agent 得分 0.89 到 0.92，各比最强视频模型高出 0.22 以上。遇到这类任务优先走"写代码渲染"的路线。

## 今日话题

### 【值得盯】agent 评测在补"过程"和"覆盖面"：跨平台长流程、最少动作数、知识覆盖
三个新基准都在回答"终态对了"之外的问题。OS-Omni 把任务拉长到平均 67.54 步并跨六个平台，暴露出同一个模型在不同平台上差距很大；DetourBench 把环境限制到可以穷举，算出每个任务的最少动作数，再把成功、差几步完成、绕了多少路分开报；DRBench Pro 用维基百科知识树生成 44,102 条评分细则，分别量报告覆盖了多少方向、每个方向挖了多深。CMU 的同题对比则说明评测对象本身也可以换：同一套题和同一个评分器下，写程序的编码 agent 明显强于视频模型。

### 【警示】自改进靠什么信号：验证过的轨迹有效，模型自己总结的经验不一定
RoboEvo² 的闭环里，写进技能库和训练集的只有验证通过的解法，并且让策略对比"同一起点下成功的纠正和失败的尝试"，不加人工示范就把独立成功率从 11.0% 提到 84.1%。NUS 的研究给出反面：让模型从离线试验里自己提炼指令或经验，没有稳定赢家，失败越多样越提炼不出有用的规则。另外两篇讲信号本身不可靠时怎么办：SQL 奖励用隐藏数据库副本防止"碰巧答对"，NOPO 在只能证伪、不能证实的场景里只惩罚确定错的样本。

- ⭐ **[RoboEvo^2: Recursive Robot Self-Improvement via Harness-Policy Co-Evolution](https://arxiv.org/abs/2611.34675)** · Chenzhi Liu 等 12 人 · 2026-11-25 · HF ↑10 —— 机器人的视觉语言动作策略执行快但换环境要补示范，会推理的 agent 能找到解法但每次都要重新思考和修补，成本高。RoboEvo² 让两者互相改进：策略失败时，编码 agent 在纯代码、代码加上下文示例、代码加策略三条路线里搜索，把验证通过的解法沉淀成可复用的技能、路由策略和经验记忆；反过来，验证过的轨迹用来训练策略，并让策略学会在同一起点下偏向成功的纠正而不是失败的尝试。不加人工示范，LIBERO-PRO 上独立成功率从 11.0% 到 84.1%，混合成功率从 30.4% 到 90.5%，Unitree G1-D 上混合成功率 95.0%。**可借鉴**：把"慢但能解题的 agent"当成数据来源，只把验证通过的轨迹蒸馏进"快的策略"，剩下的失败再交回 agent 处理，推理成本随迭代下降。
- ⭐ **[Revisiting LLMs as Context Engineers](https://arxiv.org/abs/2611.30494)** · Junrui Zhang 等 10 人（HF 页面标注机构：National University of Singapore）· 2026-11-23 · HF ↑4 —— 很多方法让模型自己当"上下文工程师"：从离线试验里提炼通用指令或经验，再放进提示里。作者先建了一个覆盖不同推理模式的基准，用 8B 规模的几类模型比较这些方法：没有哪一种在所有任务上胜出，有时不如简单的思维链基线；加大模型参数或增加迭代轮数也不能稳定提升。跨所有数据集和模型，收益与推理失败模式的多样性负相关（r = -0.5）。能解释部分收益的是指令遵循变好，主要瓶颈是模型能否从多样的失败里提炼出有效经验。**可借鉴**：做自动写规则或经验记忆前，先统计失败类型的分布；失败集中时才值得自动提炼，分散时收益有限，并且一定要和思维链基线对比。
